# 启动配置与持久化

## 模块定位

`stock-starter` 是唯一 Spring Boot 启动模块，负责聚合业务模块、前端静态资源、MongoDB 运行配置、日志配置和启动期预热。

## 启动入口

`com.stock.starter.StockStarterApplication` 是唯一 `@SpringBootApplication`。其他 Maven 模块只提供业务 Bean，不创建独立启动类。

## 聚合关系

`stock-starter` 直接依赖 `stock-model`、`stock-agent`、`stock-job` 和 `stock-web`，其余业务模块通过依赖链传递进入最终应用。

Spring Boot 插件只在本模块生成可执行 JAR，主类明确指向 `StockStarterApplication`。

## 运行配置

`application.yml` 集中配置：

- HTTP、压缩和时区。
- MongoDB 和 Jackson。
- Quartz RAMJobStore 和线程池。
- 券商、真实交易和费用参数。
- Agent Provider、预算、熔断、RAG 和 Memory。
- LSTM、Sentiment、回测和策略参数。
- 日志级别和运行节点标识。

密码、Token 和密钥使用环境变量占位，不在配置文件中保存真实值。

## MongoDB 结构

MongoDB 通过文档映射和索引声明维护集合结构，不加载 SQL 迁移组件。新增唯一约束和查询索引时，应在对应文档类中声明并在部署前核对已有数据冲突。

## 启动期动作

- Quartz 根据配置决定是否启动。
- `JobBootstrap` 幂等补齐 MongoDB 固定任务默认配置、重建内存调度任务，并按运行开关检查是否需要补齐股票基础数据。
- 模型预热服务检查并加载必要的固定模型制品。
- 启动耗时记录用于发现模型或基础设施初始化瓶颈。

启动期动作失败需要明确区分：核心数据库不可用应阻止应用正常提供服务；Agent 或可选模型不可用可以进入受控降级，但必须暴露健康状态。

## 边界

- 不在本模块新增普通业务 Controller、Service、Entity 或 Repository。
- MongoDB 文档和索引变更不承载运行时业务计算。
- 启动预热不得隐式训练模型或触发真实交易。
- 端口健康不代表所有业务能力都健康。
