# stock-strategy 模块说明

## 模块定位

`stock-strategy` 负责确定性策略计算，将市场数据、模型预测、情感结果和配置规则转换为排名、信号、卖出判断和回测结果。

## 业务用途

- 生成可解释的股票候选排名。
- 根据策略模式和技术指标生成买卖信号。
- 管理策略配置、运行状态和切换记录。
- 对历史数据执行日线基准回测和数据审计。
- 为真实交易和 Agent 提供稳定的 Java 基线结果。

## 核心能力

| 能力 | 说明 |
|---|---|
| 候选筛选 | 按价格、成交量、预测、情感和业务门槛过滤股票 |
| 综合评分 | 聚合模型、趋势、技术指标和风险因素 |
| 信号生成 | 生成结构化买入、持有、卖出或跳过信号 |
| 策略模式 | 支持不同风险偏好的配置和运行状态 |
| 卖出判断 | 处理止盈、止损、移动止损和盘中退出条件 |
| 回测 | 使用历史股票池和行情复现策略表现 |

## 实现方式

策略引擎由计算器、选择器、决策聚合器和状态管理器组成。策略配置持久化后由运行状态记录当前生效版本，切换操作保留审计记录。

回测按数据、资金和成交职责拆分：`BacktestMarketDataLoader` 统一装载并校验历史行情，`BacktestCapitalScenario` 管理初始资金、费用和持仓变化，`DailyBaselineBacktestService` 聚焦策略信号与成交计算，执行编排、数据审计和结果保存分别由对应服务负责。排名、信号、配置和回测运行信息统一存入 MongoDB。Controller 提供策略配置、状态、排名和回测相关接口。

## 依赖关系

- 依赖 `stock-base`、`stock-data` 和 `stock-model`。
- 被 `stock-trading`、`stock-agent` 和 `stock-job` 使用。
- 不直接提交券商委托。

## 决策边界

- 策略结果是 Java 基线决策，不等同于最终订单。
- 候选必须携带来源批次、策略版本和有效期。
- 数据不完整、候选过期或交易事实不确定时应跳过。
- Agent 只能在受控模式下收缩基线允许项，不能提升基线拒绝项。
