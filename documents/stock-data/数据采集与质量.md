# 数据采集与质量

## 股票资料同步

股票资料同步先获取证券接口的全量结果，再一次性读取数据库已有股票，以股票代码划分为更新、新增和数据库独有三类。

- 交集记录批量更新，不逐条写库。
- 接口新增记录补充上市日期后批量插入。
- 数据库独有记录只有在已有资料明确表明退市时才进入关联数据清理。
- 接口空响应或解析失败必须阻止本轮同步被标记为成功。

## 行情同步

日线同步分为两个用途：

| 类型 | 业务用途 | 处理原则 |
|---|---|---|
| 日常增量 | 保证最近交易日数据及时可用 | 只处理当前应同步窗口，不被历史缺口阻断 |
| 历史回补 | 修复长期缺口和新增股票历史数据 | 独立低频运行，按时间窗口递进并记录状态 |

分钟行情、复权因子、参考指数和股票池数据按各自时间粒度写入。相同股票、时间和数据类型应保持幂等。

## 交易日历

交易日历由受控数据源维护，并记录覆盖年份和验证状态。模型预测、回测和真实交易使用同一日历语义。

日历判断顺序：

1. 优先使用已确认的本地日历记录。
2. 缺失时触发维护或返回未确认状态。
3. 自动交易不得仅根据工作日或周末进行猜测。

## 新闻与情感输入

新闻采集按股票和来源读取标题、正文摘要、发布时间和来源标识，通过来源键和内容特征去重。事件分类器提取公司公告、经营变化、风险事件等业务标签，为情感模型和策略提供结构化上下文。

新闻情感值是推断输入，不替代原始新闻。原文、来源、时间和处理状态应保留，便于追踪误判。

## 数据质量规则

- 训练和回测数据必须按时间截断，防止使用未来数据。
- 数据记录需要携带业务日期和来源时间，不能只依赖写入时间。
- 批量任务记录处理数、成功数、跳过数和失败原因。
- 缺失、过期、来源不可用和解析失败应使用不同状态表达。
- 对下游提供的数据应注明覆盖范围，不能把局部数据表述为全量数据。

## 持久化分工

| 数据 | 存储 |
|---|---|
| 股票资料、交易日历 | MongoDB |
| 日线、分钟线、复权、可交易事实 | MongoDB |
| 新闻及事件元数据 | MongoDB |
| 同步窗口和运行状态 | 由相关业务模块的状态表维护 |

## 与下游协作

`stock-model` 消费行情、新闻和参考序列；`stock-strategy` 消费价格、可交易事实和历史股票池；`stock-trading` 使用最新事实执行风控；`stock-agent` 通过只读工具获取受控摘要。
