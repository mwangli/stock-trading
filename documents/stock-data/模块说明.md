# stock-data 模块说明

## 模块定位

`stock-data` 是系统事实数据入口，负责股票资料、行情、新闻、交易日历、复权和可交易状态的采集、标准化、持久化与查询。

## 业务用途

- 为模型训练和推理提供时间一致的市场数据。
- 为策略和风控提供最新价格、交易日及可交易事实。
- 为 Agent 提供可审计、可脱敏的数据来源。
- 维护新上市、退市、停牌和历史股票池等生命周期信息。

## 核心能力

| 能力 | 说明 |
|---|---|
| 股票资料 | 全量同步股票代码、名称、市场和上市信息 |
| 日线与分钟线 | 支持日常增量、按时间窗口回补和查询 |
| 交易日历 | 维护开闭市状态、节假日和覆盖范围 |
| 可交易事实 | 保存停牌、涨跌停和开放交易状态 |
| 复权与参考序列 | 为模型和回测提供一致价格基础 |
| 新闻 | 按股票采集、去重、分类并补充事件元数据 |
| 数据质量 | 校验数据范围、完整性、来源状态和异常原因 |

## 实现方式

Controller 只负责参数接收、入口日志和 `ResponseDTO` 响应封装。股票数据核心能力按职责拆分：`StockListSyncService` 负责股票列表全量同步，`StockPriceService` 负责日线查询、增量同步和历史回补，`StockQueryService` 负责分页、统计、校验和市场概览。新闻同步由 `StockNewsService` 编排，`StockNewsDocumentFactory` 负责把外部新闻转换为领域文档，`StockNewsSyncStateService` 负责同步游标和运行状态，避免内容构造、持久化进度和采集流程混在同一个服务中。股票资料、交易日历、行情、新闻和高频事实统一保存到 MongoDB。

外部接口结果先转换为明确领域对象，再批量写入。同步主流程一次性加载数据库现状后完成新增、更新和缺失分类，不在股票循环中反复查询数据库，也不使用空响应伪装成功。

## 输入与输出

输入主要来自证券接口和人工触发的导入请求；输出是股票资料、价格序列、新闻、交易日历和可交易事实。下游通过 Service 和明确 DTO 使用数据，不直接耦合外部接口格式。

## 依赖关系

- 依赖 `stock-base` 的公共响应和稳定契约。
- 被 `stock-model`、`stock-strategy`、`stock-trading`、`stock-agent` 和 `stock-job` 使用。
- 不依赖模型、策略、Agent 或交易执行模块。

## 失败边界

- 数据源整体为空、解析失败或关键数据缺失时明确失败。
- 单个股票暂时无数据时记录股票级结果，不扩大为全局故障。
- 未确认退市的股票不能因为本次接口未返回就被删除。
- 未确认的交易日历不能被自动交易链路当作正常交易日。
