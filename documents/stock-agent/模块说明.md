# stock-agent 模块说明

## 模块定位

`stock-agent` 是独立 Spring Boot 服务，默认端口 8081，负责自然语言交互、研究诊断、RAG、Memory、交易计划草案和受控交易判断。它可以独立构建、发布和扩缩容，不参与 Backend 的 Java 编译依赖。

Backend 的核心数据、确定性策略、风险控制和券商执行不依赖 Agent 才能成立。Agent 不可用时，Backend 回退 Java 基线或人工操作，不得扩大交易权限。

## 核心能力

| 能力 | 说明 |
|---|---|
| 会话与任务 | 管理 Agent 会话、任务状态、并发和用户范围 |
| Provider | 在 DeepSeek 与本地 Ollama 等模型之间受控路由 |
| 结构化输出 | 将研究、诊断、报告和交易计划解析为明确类型 |
| 工具调用 | 使用 `AiServices + @Tool` 调用受控事实工具 |
| RAG 与 Memory | 加载 Embedding 制品，检索项目知识和用户确认记忆 |
| 交易判断 | 对 Backend 提供的 Java 基线候选执行单向风险收缩 |
| 审计与预算 | 记录工具调用、Provider 状态和 API 成本预算 |

## 服务协作

Agent 不直接依赖 Backend 的 Java 类、Repository 或数据库实体：

- 通过 `BackendFactsClient` 调用 `/api/internal/agentFacts/**` 获取价格、交易日历、策略状态、预测候选、券商、模型和任务摘要。
- 内部请求统一携带 `X-Internal-Token`。
- 对 Backend 暴露 `/api/internal/tradeDecisionGate`，只返回结构化门禁结果。
- 对 Frontend 暴露 `/api/agent/**`，由 Nginx 反向代理。
- 与 Backend 共享 Redis Session，用户身份仍由服务端 Session 解析，不采信请求体中的用户范围。

## 数据存储

| 存储 | 用途 |
|---|---|
| MongoDB | 会话、任务、Memory、交易计划、RAG 文档块、工具审计和决策评估 |
| Redis | 与 Backend 共享登录 Session，不作为 Agent 业务事实源 |
| `model-artifacts/embedding` | 固定 Embedding 制品，只读加载 |

Agent 不连接 MySQL，不直接读取 Backend 的 MongoDB 业务集合。需要核心事实时必须走内部 API。

## 交易安全边界

- 工具默认只读、最小数据集并限制用户范围。
- Provider 不接触券商凭据。
- 模型文本不能直接转换为订单。
- Agent 只能减少、拒绝或延迟 Java 基线允许的候选，不能放行基线拒绝项。
- 超时、熔断、预算耗尽、解析失败或服务不可用时，Backend 按 Java 基线继续判断。
- 真实交易仍由 Backend 重新读取当前账户、持仓、价格和交易日历后决定。
