# stock-agent 模块说明

## 模块定位

`stock-agent` 是可降级的智能增强模块，负责自然语言交互、研究、诊断、报告、RAG、Memory、交易计划草案和受控交易判断。

核心数据、确定性策略、风险控制和券商执行不依赖 Agent 才能成立。Agent 不可用时，系统应回退到 Java 基线或人工操作。

## 业务用途

- 回答关于行情、模型、策略、任务和交易状态的问题。
- 聚合多个只读事实工具，生成带证据的研究和诊断结果。
- 保存用户确认的偏好、事实和纠正信息。
- 根据候选批次生成结构化交易计划草案。
- 在受控模式下评估 Java 基线候选，并提供单向风险收缩。
- 评估 Agent 历史判断与后续市场结果。

## 核心能力

| 能力 | 说明 |
|---|---|
| 会话与任务 | 管理会话、任务状态、并发和用户范围 |
| Provider | 在 DeepSeek 与本地 Ollama 等模型之间受控路由 |
| 结构化输出 | 将研究、诊断、报告和交易计划解析为明确类型 |
| 工具调用 | 通过 `@Tool` 获取受控、脱敏、最小范围事实 |
| 证据聚合 | 将工具结果组织为可追踪证据集合 |
| RAG 与 Memory | 检索项目知识和用户确认记忆 |
| 交易判断 | 对候选生成结构化建议并执行模式治理 |
| 审计与预算 | 记录工具调用、Provider 状态和 API 成本预算 |

## 实现方式

`LangChain4jAgentModelProvider` 使用 `AiServices` 绑定类型化 Agent 接口和允许的工具集合。`AgentProviderClientRegistry` 负责按配置创建和复用 Provider 客户端，`AgentProviderHealthChecker` 负责独立健康检查，主 Provider 聚焦模型调用和结构化输出。`AgentApplicationService` 只编排研究、诊断和报告，`AgentSessionService` 管理会话，`AgentTaskService` 管理任务生命周期与用户范围，避免单个应用服务同时承担所有运行状态。

MongoDB 统一保存会话、任务、Memory、交易计划、工具审计、决策治理、RAG 文档块和向量文档。接口按会话任务、运行时、知识、交易计划和交易决策五个 Controller 分离，避免单个入口同时依赖全部 Agent 能力。

## 依赖关系

- 依赖 `stock-base`、`stock-data`、`stock-model`、`stock-strategy` 和 `stock-trading`。
- 被 `stock-job` 和 `stock-starter` 使用。
- 通过 `stock-base` 的 Port 查询任务状态，不反向依赖 `stock-job`。

交易计划只生成、保存和审批结构化草案，当前不提供自动执行入口；任何真实交易仍必须由 `stock-trading` 的账户、风控、订单和券商执行链路显式发起。新增券商或基础交易能力不得放入本模块。

## 安全边界

- 工具默认只读并限制用户范围。
- Provider 不接触券商凭据。
- 模型文本不能直接转换为订单。
- 结构化输出仍需 Java 校验。
- 超时、熔断、预算耗尽或解析失败时不得扩大权限。
