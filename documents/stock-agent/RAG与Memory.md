# RAG 与 Memory

## 职责区别

| 能力 | 保存内容 | 主要用途 |
|---|---|---|
| RAG | 项目知识、业务规则和可检索文档片段 | 为当前问题补充外部知识证据 |
| Memory | 用户确认偏好、纠正、系统事实和历史经验 | 在后续会话中保持受控连续性 |
| Chat Memory | 当前会话最近消息 | 维持短期对话上下文 |

三者不能混用。RAG 文档不自动成为用户偏好，模型推断也不能未经确认写成长期事实。

## Embedding

Embedding 使用 `model-artifacts/embedding/bge-base-zh-v1.5` 中的本地 DJL 模型生成固定维度向量。向量归一化、Pooling 方式、最大序列长度和模型版本属于向量契约。

模型版本或向量维度变化后，旧向量不能与新向量直接比较，需要使用对应版本重新构建索引。

## RAG 流程

```text
文档导入
  → 文本分块
  → 元数据和来源标识
  → Embedding
  → MongoDB 向量文档
  → 查询向量
  → 相似片段检索
  → 受控上下文组装
```

检索结果携带来源、片段标识和相关度，回答应能够区分检索证据与模型推断。

## Memory 生命周期

Memory 类型包括会话、偏好、语义、经验和交易相关记忆，来源区分用户确认、系统事实、模型推断和交易结果。

长期 Memory 需要：

- 绑定用户范围。
- 记录来源和创建时间。
- 设置有效期或保留策略。
- 支持纠正、遗忘和过期状态。
- 避免存储密码、Token、Cookie 和完整账户信息。

用户纠正不直接覆盖历史记录，而是将旧记录标记为已纠正并建立新事实，保留审计关系。

## 降级行为

Embedding 未就绪时，RAG 和向量 Memory 返回不可用状态。系统默认不启用低质量哈希向量替代真实 Embedding。Agent 可在不依赖检索的任务中继续运行，核心数据、策略和交易链路不受影响。

## 数据边界

RAG 和 Memory 只为 Agent 提供上下文，不成为行情、持仓、任务或交易状态的权威来源。涉及当前事实时必须调用对应只读工具重新查询。
