# Agent 交易建议边界

## 设计目标

Agent 基于冻结事实生成可审计的交易建议和反事实评估，但不参与 Backend 的自动交易执行。Java 始终掌握当前事实、交易资格、硬风险、幂等和券商执行权。

## 建议上下文

Agent 建议基于冻结的 `TradeDecisionContext`，包含候选批次、策略版本、价格截止时间、预测、情感、新闻摘要、交易日和必要质量标记。

上下文保存用于复盘，不能在事后使用新数据改写原建议输入。

## 单一运行方式

系统只保留一种交易建议生成方式：为指定候选批次生成结构化建议并持久化。不存在参与模式、生产影响开关、灰度范围、紧急回退或融合结果。

## 执行隔离

Agent 可以：

- 对候选给出买入、持有、跳过或弃权建议。
- 在证据不足、Provider 失败或输出无效时明确弃权。
- 在后续行情到达后进行反事实评估和 Provider 稳定性统计。

Agent 不能：

- 控制、暂停或放行真实订单。
- 修改 Backend 候选集合、委托数量或风险参数。
- 绕过交易日、资金、仓位、T+1、停牌或涨跌停校验。
- 直接调用券商适配器或持有券商凭据。

## 评估与审计

每次建议记录上下文版本、Provider、模型、建议、置信度、理由、状态和有效期。反事实评估只用于衡量建议质量，不自动调整策略、风控或交易权限。

建议写入 MongoDB 的 `agent_trade_suggestion` 集合，不读取旧的门禁模式决策集合。

最终交易记录只以 Backend Java 风控、执行批次和券商事实为准。
