# Agent 运行机制与工具

## 运行流程

```text
用户请求或后台任务
  → 身份与任务类型解析
  → 能力路由
  → 工具白名单选择
  → 上下文、RAG 和 Memory 组装
  → AiServices 调用 Provider
  → 结构化输出解析与校验
  → 结果、证据和审计持久化
```

## 任务类型

| 类型 | 用途 |
|---|---|
| `RESEARCH` | 对股票、模型或策略进行事实驱动分析 |
| `DIAGNOSTIC` | 排查任务、Provider、模型或交易状态问题 |
| `REPORT` | 汇总受控范围内的业务状态 |
| `TRADE_PLAN` | 生成结构化交易计划草案 |

任务状态区分创建、运行、等待模型、等待工具、完成、降级、失败、需复核、取消和过期，便于判断是业务等待还是技术故障。

## Provider 路由

系统支持云端 Provider 和本地 Ollama。Provider 配置包含启用状态、模型、超时、最大输出、并发、预算和熔断参数。

Provider 失败达到阈值后打开熔断器，在冷却期间不持续重复调用。降级时返回明确状态，不将空文本或默认回答伪装为成功。

## 工具体系

工具使用 LangChain4j `@Tool` 声明，由 `AiServices` 按任务绑定。当前工具覆盖：

- 最新行情与交易日历。
- 模型概览和预测候选。
- 策略状态。
- 任务运行诊断。
- 券商认证、账户和持仓脱敏摘要。
- 交易绩效摘要。
- Provider 与熔断状态。

工具实现调用已有领域 Service，不直接访问 Controller、SQL、Repository 或券商底层协议。

## 上下文控制

- 每类任务只绑定必要工具，避免模型获得无关能力。
- 工具参数和结果使用明确类型。
- 查询结果限制数量、时间范围和敏感字段。
- 完整提示词、券商凭据和数据库对象不得写入日志。
- 工具调用记录任务、工具名、输入摘要、结果状态、耗时和错误码。

## 结构化输出

研究、诊断、报告和交易计划分别使用明确结果类型。解析失败时保留原始调用状态和错误原因，但不把自由文本强制转换为业务成功。

## 预算与并发

云端调用通过每日预算限制成本，调用前预留估算额度，完成后记录实际使用。Agent 并发默认保持较低，防止在 2C4G 环境中与模型训练、Quartz 和交易任务争抢资源。
