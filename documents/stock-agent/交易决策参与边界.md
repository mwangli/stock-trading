# Agent 交易决策参与边界

## 设计目标

Agent 可以参与交易判断，但 Java 仍然掌握当前事实、硬风险、幂等和券商执行权。Agent 的影响必须可关闭、可审计、可评估和可立即回退。

## 决策上下文

Agent 判断基于冻结的 `TradeDecisionContext`，包含候选批次、策略版本、价格截止时间、预测、情感、新闻摘要、交易日和必要质量标记。

上下文保存用于复盘，不能在事后使用新数据改写原判断输入。

## 运行模式

| 模式 | 行为 |
|---|---|
| `OFF` | 不生成 Agent 交易判断 |
| `SHADOW` | 生成并保存判断，但不影响交易结果 |
| `ADVISORY` | 向用户展示建议，不改变自动交易结果 |
| `GATED` | 仅允许对 Java 已允许候选执行跳过或延迟 |

`GATED` 必须同时开启生产影响开关并满足配置范围，否则自动降级为 `ADVISORY` 或 `SHADOW`。

## 单向约束

Agent 不能：

- 将 Java 基线拒绝的股票改为买入。
- 绕过交易日、资金、仓位、T+1、停牌或涨跌停门禁。
- 修改委托数量以突破风险上限。
- 直接调用券商适配器。

Agent 可以：

- 对基线候选给出买入、持有、跳过或弃权建议。
- 在 `GATED` 模式下根据有效的 `HOLD` 或 `SKIP` 收缩自动买入集合。
- 在证据不足、Provider 失败或输出无效时弃权。

## 降级策略

Agent 无结果时根据配置选择回到 Java 基线或进入人工复核。任何降级都不得将原本不可交易的候选变为可交易。

管理员可以随时将模式紧急回退到 `SHADOW`，同时关闭生产影响。

## 评估与审计

SHADOW 判断在后续行情到达后进行反事实评估，统计建议方向、弃权、基线回退和不同 Provider 的表现。评估用于决定是否扩大使用范围，不直接自动调整生产权限。

每次判断记录上下文版本、Provider、模式、建议、置信度、理由、状态和融合结果。最终交易记录仍以 Java 风控和券商事实为准。
