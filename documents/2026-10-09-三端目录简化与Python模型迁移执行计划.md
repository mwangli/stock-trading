## 4. Python 模型端职责

### 4.1 必须负责

#### 数据快照校验

- 校验 Java 导出的 LSTM 面板数据和情感训练数据。
- 校验 Schema、字段顺序、数据类型、时间范围和摘要。
- 校验训练集、验证集、测试集及 purge gap。
- 拒绝特征版本不兼容或摘要不匹配的数据。

#### LSTM 训练

- 实现与当前共享多任务 LSTM 等价的 PyTorch 模型。
- 支持股票和行业 Embedding。
- 支持 Group Head 和 Residual Head。
- 输出收益率、上涨概率和下行风险。
- 支持 Early Stopping、固定随机种子和断点恢复。

#### LSTM 评估

- Walk-forward。
- Rank IC、ICIR。
- Top-K 扣费收益。
- 最大回撤和换手率。
- 行业、市值和市场阶段分层。
- 与 Java/DJL Golden Output 对比。

#### 情感模型训练

- 文本清洗和事件去重。
- 按时间切分数据。
- 教师模型软标签生成。
- 轻量模型微调或蒸馏。
- 强负面事件专项评估。

#### ONNX 制品

- 默认导出 FP32 ONNX。
- 校验训练框架与 ONNX 输出。
- 仅当 FP32 在 2C4G 实测资源不足时，生成 INT8 降级候选。
- 构建 `metadata.json`、`metrics.json`、`manifest.json` 和 SHA-256。
- 生成 Golden Input/Output。

## 5. 本地 32GB 电脑运行方式

### 5.1 推荐方式

优先提供两种等价入口：

```text
原生 Python 虚拟环境
Docker 训练容器
```

日常开发使用虚拟环境，正式可复现训练使用 Docker 镜像。

### 5.2 本地目录

```text
python/runtime/
├─ datasets/              # Java 导出的只读数据快照
├─ runs/                  # 每次训练运行目录
├─ cache/                 # Hugging Face 和模型缓存
└─ artifacts/             # 待发布 ONNX 制品
```

这些运行目录加入 `.gitignore`，不提交模型、大数据集或缓存。

### 5.3 32GB 资源建议

| 任务 | 建议方式 |
|---|---|
| LSTM 训练 | CPU 可运行，建议单任务、4-8 个 DataLoader Worker 上限按实测调整 |
| LSTM Walk-forward | 串行或限制为 2 个并发窗口 |
| 情感教师推理 | CPU 可运行但耗时较长，有 NVIDIA GPU 时优先 GPU |
| 情感微调/蒸馏 | 主要取决于 GPU 显存；无 GPU 时降低 Batch 并使用梯度累积 |
| ONNX 导出 | CPU 即可 |
| FP32/INT8 对比 | CPU 执行，固定评估集 |

本地运行约束：

- 同一时间只运行一个正式训练任务。
- 数据库、Java 服务和训练并发时保留至少 6-8GB 系统余量。
- 不把完整训练数据加载为多个重复 DataFrame。
- 使用内存映射或分批读取较大快照。
- 每次训练输出独立 Run ID。

### 5.4 本地执行流程

```text
Java 导出数据快照
  -> Python validate-data
  -> Python train-lstm 或 train-sentiment
  -> Python evaluate
  -> Python export-onnx
  -> Python verify-onnx
  -> Python build-artifact
  -> 上传 staging
```
