## 1. 模块目标

模型服务采用 Python 离线训练、ONNX 标准制品、Java 在线推理。模型不得直接调用券商，所有真实交易必须经过 Java 策略、风控、幂等和执行链。

## 4. 数据和特征要求

- 第一阶段由 Java 导出训练快照，保持训练与在线特征同源。
- LSTM 至少使用 60 个交易日窗口，禁止使用未来数据。
- Manifest 必须记录特征版本、标签版本、数据截止时间、字段顺序和切分范围。
- Python 直接读取生产数据库不是第一阶段默认方案。
- Java/Python Golden Case 未逐字段一致前，不允许各自维护无校验的特征实现。

## 5. 模型验收

- LSTM：Walk-forward、Rank IC、ICIR、Top-K 扣费收益、最大回撤和换手率。
- 情感：Macro-F1、Negative Recall、强负面一致率、置信度和候选排序回放。
- ONNX：无 NaN/Infinity，输出误差、排序、阈值和风控结论达到门槛。
- 资源：2C4G 常驻、峰值、模型切换和连续运行达到设计指标。
- 静态检查、训练损失下降或单次加载成功不能证明可上线。

## 6. 运行约束

- Java 不提供模型训练入口，也不包含生产 PyTorch 依赖。
- LSTM 和情感模型都必须由 Python 训练并以 ONNX 制品交付。
- 生产交易期间禁止训练、下载或切换未经验证的模型。
- ONNX 制品缺失、指标未通过或摘要不匹配时，真实候选生成必须失败关闭。
