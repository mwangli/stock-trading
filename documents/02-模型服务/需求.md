## 1. 模块目标

模型服务统一运行在 Java 17 中，DJL 提供模型 API，PyTorch Engine 提供训练和推理执行。Python 与 ONNX 不再属于生产或训练链路。模型不得直接调用券商，真实交易仍必须经过策略、风控、幂等和交易执行模块。

| 需求 ID | 需求描述 | 优先级 | 验收标准 |

## 4. 情感模型需求

- Java 使用 DJL Hugging Face Tokenizer 和 PyTorch Engine 加载文本分类模型。
- 生产默认从版本化本地目录加载，禁止运行时调用 Python 生成 Tokenizer 或转换权重。
- 大体积 Transformer 权重不写入 MongoDB；MongoDB只保存模型配置、状态、摘要、指标和制品路径。
- 交易候选使用严格推理，模型不可用时必须停止候选生成；非交易查询允许明确标识的规则降级。

## 5. 配置与运行约束

- 正式训练默认关闭，只有 `LSTM_TRAINING_ENABLED=true` 的指定节点可以执行训练。
- 训练期间不得修改订单、持仓、风控或券商数据。
- 生产容器必须包含与 DJL 版本匹配的 `pytorch-engine`、`pytorch-jni` 和 PyTorch Native CPU 运行库。
- 配置变化只影响新训练版本；历史版本的训练配置必须保存在 MongoDB 中以便审计。
- 当前实现继续直接构造 `StockLSTMModel`，不引入额外 Factory 或 `modelStructureVersion` 机制。

## 6. 验收边界

- LSTM：Walk-forward、Rank IC、ICIR、Top-K 扣费收益、最大回撤和换手率。
- 情感：Macro-F1、Negative Recall、强负面一致率、置信度和候选排序回放。
- 资源：2C4G 常驻内存、训练峰值、连续推理和模型切换达到部署门槛。
- `mvn compile`、训练损失下降或单次模型加载成功均不能单独证明可上线。
