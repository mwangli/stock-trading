## 1. 业务背景

股票价格受市场走势、行业特征、个股历史表现和短期交易行为共同影响，单一规则难以持续刻画不同股票在不同市场环境下的变化。系统需要通过 LSTM 模型学习历史时序数据中的共性与差异，为次一交易日的候选股票筛选提供收益方向、上涨可能性和下行风险参考。

模型输出只作为策略分析的输入，不直接形成交易指令。任何真实交易仍须经过候选筛选、风险控制、资金检查、人工或自动交易门禁，避免模型结果绕过既有交易安全链路。

## 2. 业务目标

1. 建立覆盖全市场股票的共享 LSTM 模型，减少逐只股票维护模型带来的资源消耗和版本失控。
2. 定期使用最新历史数据更新模型，使预测能力能够跟随市场结构和交易行为变化。
3. 将模型训练、候选评估和生产启用分离，保证训练成功不等于立即影响交易。
4. 保留每次训练的参数、数据规模、结果和失败原因，支持问题追踪、版本比较和回滚。
5. 当数据、资源或运行时机不满足要求时主动拒绝训练，优先保障交易业务稳定。
6. 在长时间训练过程中持续展示当前阶段、训练轮次、完成比例、损失变化和预计剩余时间，便于运维人员判断任务是否正常推进。

## 3. 使用角色

| 角色 | 业务职责 |
|---|---|
| 模型运维人员 | 查看模型状态、发起受控训练、评估候选版本、执行激活或回滚 |
| 交易策略人员 | 使用已激活模型的预测结果生成候选股票，不参与模型训练过程 |
| 系统调度任务 | 在约定时间检查模型是否需要更新，并提交训练任务 |
| 审计人员 | 查询训练过程、版本变化、操作人和失败原因 |

## 4. 功能范围

### 4.1 本期范围

- 基于多只股票历史行情构建共享训练样本。
- 同时学习次一交易日收益、上涨方向和下行风险。
- 支持定时训练和运维人员手工发起训练。
- 支持训练开关、交易时段、并发任务、数据完整性、资源余量和参数范围门禁。
- 支持训练过程记录、候选版本保存、候选质量判断、人工激活和上一版本回滚。
- 支持训练状态、阶段、进度、耗时、预计剩余时间和损失收敛情况的持续查看。
- 支持已激活版本的单只股票与批量股票预测。

### 4.2 非本期范围

- 不由模型直接下单或修改持仓。
- 不在交易时段执行训练或切换生产版本。
- 不建设自动超参数搜索、通用实验平台或多级审批平台。
- 不以一次训练损失下降作为生产可用的唯一依据。
- 不允许训练完成后自动替换当前生产模型。

## 6. 训练业务流程

1. 系统调度任务或模型运维人员提出训练请求。
2. 系统检查训练能力、运行时段、并发任务、基础数据、资源余量和参数范围。
3. 门禁不通过时记录拒绝原因，不启动训练。
4. 门禁通过后建立训练运行记录，并加载符合条件的股票历史数据。
5. 系统构建训练集和验证集，检查有效股票和样本规模。
6. 系统执行多目标训练，保留验证效果最好的轮次。
7. 训练结果通过完整性、兼容性和质量阈值检查后形成待激活候选版本。
8. 模型运维人员评估候选版本并决定激活、保留或拒绝。
9. 新版本激活后成为预测使用版本，上一版本保留为回滚目标。

## 7. 状态与审计

### 7.1 训练运行状态

| 状态 | 业务含义 |
|---|---|
| 排队中 | 已通过提交门禁，等待执行 |
| 运行中 | 正在构建数据或训练模型 |
| 成功 | 已生成并通过基础质量检查的候选版本 |
| 失败 | 训练、数据检查、完整性检查或质量检查未通过 |

### 7.2 模型版本状态

| 状态 | 业务含义 |
|---|---|
| 候选 | 已保存训练结果，尚未完成候选质量确认 |
| 待激活 | 已通过基础质量和兼容性检查，可由运维人员激活 |
| 已激活 | 当前生产预测使用的版本 |
| 已归档 | 曾被激活或保留，但当前不用于生产预测 |
| 已拒绝 | 未通过候选质量检查，不允许激活 |

### 7.3 审计要求

- 记录训练来源、触发人、提交时间、开始时间、结束时间和最终状态。
- 记录请求参数、实际生效参数、有效股票数、训练样本数、验证样本数和关键结果。
- 记录训练拒绝、训练失败、候选通过、候选拒绝、激活和回滚原因。
- 训练运行期间记录最近进度更新时间、当前阶段、轮次、完成比例、耗时、预计剩余时间及最近损失。
- 历史训练记录和模型版本不得因新版本生成而自动删除。

## 9. 验收边界

- 编译成功只能证明代码可构建，不能证明训练业务有效。
- 单次训练完成或损失下降不能单独证明模型可用于生产。
- 生产启用前仍需结合滚动验证、候选股票回放、扣除交易成本后的收益、最大回撤、换手率和资源占用进行评估。
 - 快照复用只能证明输入数据一致，不能单独证明模型效果或生产可用性。

## 10. 训练数据快照与中断恢复

### 10.1 数据快照

- 将历史行情读取、特征计算和训练样本构建形成独立的数据快照，避免每次训练重复准备相同数据。
- 快照保存数据截止日期、股票范围、特征版本、标签版本、样本数量和数据质量结果，支持历史复现和多版本备用。
- 训练任务优先使用状态正常且契约兼容的最新快照；没有可用快照时才构建新快照。
- 快照构建和模型训练的状态分开记录，运维人员可以区分数据准备和模型训练阶段。
- 快照被历史训练、回测或审计记录引用时不得自动删除。

### 10.2 中断与恢复

- 训练过程中按已完成轮次保存模型参数检查点，停止请求或应用重启不得破坏最近一次完整检查点。
- 已中断或失败且存在有效检查点的任务允许创建新的恢复任务，恢复任务必须复用原训练配置和数据快照。
- 恢复任务记录来源任务、恢复轮次和检查点校验结果，不能伪装成全新训练。
- 检查点与模型结构、特征版本或训练参数不兼容时必须拒绝恢复并说明原因。
- 恢复成功后仍只能生成新的候选模型版本，不得自动激活生产模型。

### 10.3 业务状态

| 状态 | 业务含义 |
|---|---|
| 快照构建中 | 正在读取行情、计算特征或写入快照工件 |
| 快照可用 | 工件完整、摘要一致并允许训练复用 |
| 快照失败 | 快照构建或数据质量检查失败 |
| 训练中断 | 训练被停止、应用重启或异常终止，但可能存在可恢复检查点 |

### 10.4 验收标准

- 首次构建训练数据快照后，契约一致的后续训练能够复用快照并记录快照 ID。
- 快照工件损坏、摘要不一致或特征契约变化时，训练拒绝复用并给出明确原因。
- 训练停止或应用重启后，存在完整检查点时可以创建恢复任务，并从已完成轮次之后继续训练。
- 恢复任务保留原任务 ID、快照 ID、检查点轮次和恢复后的新候选模型版本。
