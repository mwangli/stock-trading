# 模型格式与 ONNX 制品指南

## 1. 当前结论

项目目标模型格式统一为 ONNX：

- LSTM 默认使用 FP32 ONNX。
- 情感模型默认使用 FP32 ONNX。
- 情感 INT8 仅在 FP32 不能满足 2C4G 实测资源门槛时作为降级候选。
- Java 在线端使用 ONNX Runtime。
- Python 3.14 模型端负责训练、评估、导出和候选制品构建。

旧的 TorchScript、`djl-convert` 和 DJL PyTorch 路径已从当前 Java 代码移除，只能通过 Git 历史查看。

## 2. Python 导出流程

```text
训练框架最佳模型
  -> FP32 ONNX 导出
  -> ONNX 模型检查
  -> PyTorch/ONNX 输出比较
  -> 业务指标评估
  -> 构建版本化候选制品
  -> Java staging 校验
  -> 部署到 Java ONNX 制品目录
  -> Java 在线推理
```

Python 工程路径：

Java 加载前必须校验：

- 模型名称、版本和 SHA-256。
- ONNX Opset。
- 输入输出名称、顺序、Shape 和数据类型。
- 特征版本和标签版本。
- Tokenizer 与 `id2label`。
- LSTM 序列长度、特征数、哈希算法和输出语义。
- Python Golden Output 与 Java 实际输出。

## 4. 精度策略

### LSTM

LSTM 参数规模较小，固定使用 FP32。INT8 的内存收益有限，不能抵消 LSTM、Embedding 和多任务输出漂移风险。

### 情感模型

先验收 FP32：

- Macro-F1。
- Negative Recall。
- 强负面事件一致率。
- 置信度分布。
- Top-N 候选和风控结论。
- 2C4G 常驻内存、推理峰值和模型切换峰值。

只有 FP32 资源验收失败时才生成 INT8，并重新执行全部业务指标。INT8 指标不通过时继续使用 FP32，并优先扩容。

## 5. 发布边界

- Python 只能写入候选制品目录。
- Python 不修改生产 `current` 指针。
- Java 负责摘要和兼容性校验以及在线推理。
- 新模型加载失败时继续使用旧 Session。
- 当前版本和上一版本同时保留。
