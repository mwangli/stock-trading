# DJL 原始模型制品指南

## 当前决策

项目不再执行 ONNX 导出或格式转换。LSTM 训练和推理都使用 DJL + PyTorch Engine，参数通过 DJL `Block.saveParameters` 和 `Block.loadParameters` 序列化与加载。

## LSTM 制品

LSTM 是小型自定义模型，制品直接保存到 MongoDB：

- `params`：DJL 参数二进制。
- `trainingConfigJson`：本次训练使用的结构和超参数快照。
- `inputContractJson`：输入 Shape、特征版本和标签版本。
- `metricsJson`：训练损失、验证损失、最佳轮次和样本量。
- `parameterSha256`、`parameterSize`：参数完整性校验。
- `status`：版本状态。

加载时继续使用原有 `StockLSTMModel` 构造结构，再加载参数。当前方案不引入 Factory 或 `modelStructureVersion`；因此修改 `StockLSTMModel` 的参数布局时必须同时升级 `MODEL_VERSION`，并通过新训练生成新参数，禁止用新代码加载不兼容旧参数。

## 情感模型制品

情感 Transformer 权重不保存到 MongoDB、Git 或应用镜像，使用版本化目录：

```text
/models/sentiment/<version>/
├─ config.json
├─ tokenizer.json
├─ serving.properties
└─ pytorch_model.bin | model.safetensors | *.pt
```

`manifest.json` 使用 `sentiment-artifact-v1` 契约，至少记录模型名称、不可变版本、基础模型、PyTorch 引擎、最大序列长度、标签顺序、文件相对路径、字节数、SHA-256 和离线评估摘要。manifest 不把自身列入文件清单。

部署前必须验证目录完整性、文件大小、文件摘要、标签顺序、输入契约和 PyTorch Engine 可加载性。生产默认禁止在线下载，避免启动时依赖外网和不可审计变更。模型目录以只读方式挂载，应用只读取指定版本，不通过 `current` 软链接或覆盖目录隐式切换。

推荐发布流程：

1. 制品库下载到同一磁盘的临时目录，逐文件核对摘要。
2. 校验成功后原子重命名为版本目录，已存在版本不得覆盖。
3. 通过 `SENTIMENT_MODEL_VERSION` 指定新版本并滚动重启。
4. 核对健康接口中的版本、总大小、manifest 摘要、完整校验状态和基准样例。
5. 回滚时恢复旧版本配置并重启，不改写任一版本目录。

当前中文金融情感基线为 `yiyanghkust/finbert-tone-chinese`，固定源版本 `e91b1a3af10e1e8c9c03429d3cd7d5e9a1c8000d`，部署版本为 `finbert-tone-chinese-e91b1a3a`。Hugging Face 原始 `model.safetensors` 不能直接交给 DJL PyTorch Engine 加载，发布前必须通过 DJL Converter 生成 TorchScript `.pt` 和 `tokenizer.json`。转换完成后不保留原始 `model.safetensors` 到运行目录，避免双份权重占用。

该 BERT 模型的 TorchScript 输入签名包含 `input_ids`、`attention_mask` 和 `token_type_ids`。Java Translator 必须启用 Token Type 输入，并按照 manifest 的 `maxSequenceLength=128` 开启截断。`config.json` 中的 `id2label` 固化为小写 `neutral / positive / negative`，避免不同运行库返回标签大小写不一致。

## 版本升级规则

1. 只调整学习率、Epoch、Batch Size 等训练超参数：生成新模型版本，`StockLSTMModel` 可不变。
2. 调整输入特征、序列长度或标签：升级特征/标签版本并重新训练。
3. 调整层数、隐藏维度、Embedding 或 Head 参数布局：升级 `MODEL_VERSION` 并重新训练，旧版本仅允许由兼容代码回滚。
4. 升级 DJL 或 PyTorch Engine：重新执行参数加载、批量推理、资源和业务回放验证。
