# 模型服务设计

## 目标架构

```text
Java 数据和特征快照
  -> Python 训练与评估
  -> FP32 ONNX 候选制品
  -> Java 制品校验
  -> Java ONNX 在线推理
  -> 策略、风控和交易
```

Python 是训练权威端，Java 是在线推理和业务控制端。两端通过数据快照契约和 ONNX 制品契约协作，不通过内部实现细节耦合。

## Python 模型端

目录为 `python/src/stock_models`，负责：

- 数据快照和摘要校验。
- 多任务共享 LSTM 训练与评估。
- 情感模型微调、蒸馏与评估。
- FP32 ONNX 导出和输出一致性检查。
- 资源不足时的受控 INT8 情感候选。
- Metadata、Metrics、Manifest 和 Golden Case 构建。

Python 不激活生产模型，不调用券商，不写订单和持仓。

## Java 在线端

`com.stock.modelService` 已收敛为：

- 在线特征构建。
- 模型制品校验。
- ONNX Session 生命周期管理。
- LSTM 批量推理。
- 情感严格推理与事件聚合。
- 模型健康状态和严格失败控制。

Java 不再包含模型训练入口、训练任务、DJL/PyTorch 模型实现或旧模型仓储。LSTM 和情感推理分别由 `LstmInferenceService`、`SentimentInferenceService` 加载 Python 产出的 ONNX 制品。

## 数据快照

第一阶段由 Java 生成不可变快照：

```text
dataset.parquet 或 dataset.npz
dataset-manifest.json
feature-schema.json
split-manifest.json
golden-samples.json
```

Manifest 至少包含数据截止时间、特征版本、标签版本、字段顺序、缺失值规则、归一化参数、哈希算法、切分范围和 SHA-256。

## ONNX 制品

```text
model.onnx
metadata.json
metrics.json
manifest.json
sha256.txt
preprocessor.json
tokenizer/
golden-inputs/
golden-outputs/
```

FP32 是 LSTM 和情感模型的默认生产精度。情感 INT8 只有在 FP32 不能满足 2C4G 资源门槛时才进入候选，并必须重新通过强负面召回、置信度、Top-N 候选和风控一致性验收。

## 发布与回滚

1. Python 构建候选制品并上传 staging。
2. Java 校验元数据、摘要和 Golden Case。
3. 运维将通过验收的完整制品部署到配置目录。
4. Java 在创建 Session 前校验元数据、离线指标和 SHA-256。
5. 加载失败时停止模型候选生成，不使用规则或随机结果冒充模型输出。
6. 制品目录切换和回滚仍需在部署流程中完成验证。

## 运行环境

- 本地 32GB：Python 3.14，执行正式训练、评估和导出。
- 云端 2C4G：Java ONNX 在线推理，不执行正式训练。
- 扩容后：运行同一个 Python 镜像，仅改变资源限制和数据挂载。

## 失败原则

- 数据契约不兼容：拒绝训练或推理。
- 模型摘要不匹配：拒绝加载。
- LSTM 模型失败：停止 LSTM 候选生成。
- 情感模型失败：停止整次真实候选生成。
- Python 训练失败：继续使用最近一个已发布模型。
- 不允许随机值、固定分数或规则结果冒充真实交易模型输出。
