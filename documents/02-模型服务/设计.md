# 模型服务设计

## 目标架构

```text
MySQL stock_info + MongoDB stock_prices
  -> Java LstmDataPreprocessor 构造面板样本
  -> DJL Trainer + PyTorch Engine 训练 StockLSTMModel
  -> MongoDB 保存版本、参数、配置、指标、状态和 SHA-256
  -> model_activations 激活当前版本并保留上一版本
  -> DJL + PyTorch Engine 批量在线推理
  -> 策略、风控和交易
```

Python 和 ONNX 已移除。训练与推理共享同一 Java 特征实现、同一 `StockLSTMModel` 和同一 PyTorch Engine，不再维护模型转换、算子兼容和跨引擎误差校验。

## LSTM 结构

`StockLSTMModel` 保留以下结构：

- 连续量价特征进入多层 LSTM 和 LayerNorm。
- 股票代码与行业代码使用哈希桶 Embedding。
- 共享 Head 输出基础结果，Group Head 和个股 Residual Head 做小幅校正。
- 单次输出缩放收益率、上涨概率和下行风险三个任务。

训练使用 Adam、多任务 `Huber + BCE + Huber` Loss、验证集 Early Stopping，并只保存最佳轮次参数。

## MongoDB 文档

### `lstm_models`

每次训练生成新文档，关键字段包括：

```text
modelName / modelVersion / parentModelVersionId
trainingConfigJson / inputContractJson / metricsJson
featureVersion / labelVersion
engineName / engineVersion / djlVersion
parameterSha256 / parameterSize / status
params / createdAt / epoch / trainLoss / valLoss
```

版本文档不得因新模型发布而删除。`params` 只用于当前小型 LSTM；大模型权重不进入该集合。

### `model_activations`

```text
modelName
activeModelVersionId
previousModelVersionId
activatedAt
```

训练成功后先保存完整版本，再更新激活指针。推理始终通过激活指针读取版本，并在参数加载前校验 SHA-256。回滚只修改激活指针。

## 调度与故障边界

- `OfflineLstmTrainingJob.trainStaleModels()` 由统一调度中心在收盘后触发。
- `LSTM_TRAINING_ENABLED=false` 时任务直接跳过，在线节点默认不训练。
- 训练失败时不更新激活指针，当前版本继续服务。
- 激活版本不存在、参数为空、摘要不匹配或元数据不兼容时，推理失败关闭。

## 情感模型

情感模型通过 DJL `Criteria`、Hugging Face Tokenizer 和 PyTorch Engine 加载。默认读取 `/models/sentiment` 版本化目录；目录必须由部署流程提供完整 `config.json`、`tokenizer.json`、`serving.properties` 和权重文件。Java 不再调用 Python 补全 Tokenizer。

由于 Transformer 权重通常较大，权重保留在模型卷；MongoDB仅保存版本元数据、摘要、指标、状态和路径。后续如增加情感微调，应继续使用 DJL/PyTorch Engine 或独立受控训练平台，但不得重新引入 ONNX 作为并行生产路径。

## 部署要求

- Maven 编译依赖：`ai.djl:api`、`pytorch-engine`、`pytorch-model-zoo`、`model-zoo`、`tokenizers`。
- Linux x86_64 生产包显式包含 PyTorch Native CPU 和 JNI 运行库。
- Docker Compose 不再包含 `stock-python` 或 `ONNX_*` 环境变量。
- 模型卷只保留情感大模型等文件制品；LSTM 参数由 MongoDB 管理。
