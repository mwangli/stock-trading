## 1. 设计目标

在现有单体后端内补全 LSTM 离线训练闭环，保持训练、推理、策略、风控和交易执行的模块边界。实现重点是统一训练入口、真实数据门禁、候选质量判断和版本隔离，不新增 Python、ONNX 或独立模型服务。

## 2. 技术选型

| 领域 | 选型 | 设计意图 |
|---|---|---|
| 模型 API | DJL | 在 Java 内统一模型结构、训练和参数序列化接口 |
| 训练与推理引擎 | PyTorch Engine | 训练和线上推理使用同一执行引擎，减少转换误差 |
| 训练数据 | MySQL 股票主数据 + MongoDB 日线行情 | 复用现有数据采集结果，不建设重复数据链路 |
| 任务调度 | `JobConfig + JobSchedulerService` | 所有后台任务统一注册和执行，不使用 `@Scheduled` |
| 模型版本 | MongoDB 文档 | 保存不可变参数、配置、输入契约、指标和摘要 |
| 运行与审计 | MongoDB 文档 | 记录训练状态、门禁结果、候选版本和操作历史 |
| 训练可观测性 | 进度回调 + MongoDB 运行记录 + 前端轮询 | 在不引入独立消息中间件的前提下持续展示训练进度和损失收敛情况 |

## 4. 训练执行流程

1. `OfflineLstmTrainingJob` 或模型运维接口调用 `ModelOperationsService`。
2. 运维服务校验训练开关、交易时段、维护窗口、并发运行、股票基础数据、JVM 可用内存和参数范围。
3. 门禁通过后保存 `QUEUED` 运行记录，再提交到应用线程池。
4. 实际执行前再次检查时段、训练能力和资源，避免排队期间环境变化。
5. `LstmTrainerService` 加载历史日线，`LstmDataPreprocessor` 按股票生成面板样本。
6. 有效股票数、训练样本数或验证样本数低于阈值时直接失败，不创建模型版本。
7. DJL Trainer 使用 Adam 和多任务 Loss 训练，按验证损失执行 Early Stopping，只序列化最佳轮次参数。
8. 参数、输入契约、训练配置、样本规模、损失和 SHA-256 保存为 `CANDIDATE` 版本。
9. 运维服务校验参数完整性、版本兼容性、损失有限性和验证损失阈值；通过后标记 `READY`，否则标记 `REJECTED`。
10. 只有受控激活操作可以更新生产激活指针。

训练执行期间，`LstmTrainerService` 通过轻量回调上报阶段与轮次进度，`ModelOperationsService` 将进度写入当前 `model_training_runs` 文档。每个 Epoch 完成后更新当前损失、验证损失、完成比例、耗时和预计剩余时间；异常时最终状态覆盖运行中进度。

## 5. 数据与特征设计

- 每只股票独立按日期升序构造窗口，禁止跨股票拼接。
- 训练集位于时间前段，验证集位于时间后段，中间保留隔离窗口，降低相邻样本泄漏。
- 连续特征包含量价变化、成交量与成交额、RSI、MACD、均线、布林带和 OBV。
- 股票、行业和分组使用稳定哈希索引，模型版本中固化桶数量与哈希约定。
- 标签包含缩放后的次日收益、上涨方向和下行风险，训练与推理共用同一特征版本。

## 6. 模型结构

- 连续时序特征进入多层 LSTM 和 LayerNorm，取最后时间步表示。
- 股票与行业类别特征通过 Embedding 融入共享表示。
- Shared Head 输出基础结果，Group Head 提供行业或风格修正，Residual Head 提供受限的个股修正。
- 输出固定为收益率、上涨概率和下行风险三个值。
- 收益与下行风险使用 Huber Loss，方向使用 Binary Cross Entropy，各任务按配置权重合并。

## 7. 门禁与配置

`models.lstm` 保存模型结构和训练参数，`app.lstm.data-quality` 保存数据与候选质量阈值。新增或补齐的关键配置如下：

| 配置 | 默认值 | 用途 |
|---|---:|---|
| 最小有效股票数 | 100 | 防止少量股票形成偏置模型 |
| 最小训练样本数 | 1000 | 保证训练数据规模 |
| 最小验证样本数 | 200 | 保证候选质量判断有基本样本量 |
| 最大验证损失 | 1.0 | 超过阈值的候选版本标记为拒绝 |
| 最小 JVM 可用内存 | 256 MB | 资源不足时拒绝启动训练 |

手工覆盖参数仅允许训练天数、轮次、批次大小和学习率，并继续使用既有白名单范围。模型结构、特征版本、标签版本和引擎版本不能通过运行接口修改。

`models.lstm.training-time-guard-enabled` 默认值为 `true`，控制交易时段与工作日 18:30 至 23:30 的时间门禁。只有与生产交易隔离的本地节点允许通过 `LSTM_TRAINING_TIME_GUARD_ENABLED=false` 关闭该门禁；训练能力开关、并发任务、数据规模、JVM 内存和参数范围仍继续校验。

## 8. 版本与状态

- `model_training_runs` 保存触发来源、操作人、请求参数、实际参数、门禁结果、样本规模、损失、候选版本和错误原因。
- `lstm_models` 保存不可变模型参数和版本元数据，状态流转为 `CANDIDATE -> READY -> ACTIVE -> ARCHIVED`，质量失败时为 `REJECTED`。
- `model_activations` 只保存当前版本、上一版本和激活时间。
- `model_operation_audits` 记录提交、拒绝、完成、失败、激活和回滚操作。

## 9. 训练进度与日志

- 训练阶段统一为排队、数据准备、样本处理、模型训练、模型保存、候选校验和完成，页面展示中文阶段名称。
- 总进度按阶段分配权重，模型训练阶段依据当前轮次与总轮次计算，避免数据准备期间长期显示 0%。
- 预计剩余时间在完成首个 Epoch 后，基于已完成轮次平均耗时估算；尚无可靠样本时页面显示“计算中”。
- 训练页面在存在排队或运行任务时每 3 秒刷新概览和训练记录，任务结束后停止高频轮询。
- 后端每轮日志输出当前/总轮次、进度、训练损失、验证损失、最佳验证损失、是否改善、连续未改善轮次、已耗时和预计剩余时间。
- 进度持久化失败只记录告警，不中断模型训练；最终训练状态仍由主执行链路写回。
- 前端不承担最终业务门禁，不使用 `disabled` 阻断训练、激活或回滚操作；按钮点击后统一调用后端，由后端返回交易时段、并发任务、版本状态等错误。

## 10. 故障边界

- 训练失败不修改当前激活指针，线上预测继续使用原版本。
- 候选版本质量失败时保留版本和原因，但禁止激活。
- 参数为空、SHA-256 不一致、特征契约不兼容或激活版本不存在时，推理失败关闭。
- 定时训练发生门禁拒绝时仅记录并退出，不影响调度线程后续任务。
- 编译验证只覆盖代码结构；真实训练、指标有效性和生产资源占用需单独执行运行验证。
## 11. 全量训练数据快照设计

### 11.1 构建入口与兼容契约

- `TrainingDatasetSnapshotService.buildSnapshot` 负责独立构建快照，快照构建不受训练开关和训练时间窗口限制。
- `ModelOperationsService.prepareTrainingSnapshot` 从 `StockInfoRepository.findAllCodes` 获取全量股票范围，并应用训练排除代码配置。
- 兼容摘要由模型名称、历史天数、排序后的股票代码、`panel-embedding-v3` 特征版本、序列长度和输入维度组成。`LstmTrainerService` 只复用摘要一致且状态为 `READY` 的最新快照。
- MongoDB 集合 `training_dataset_snapshots` 保存状态、样本数量、截止日期、GridFS 清单文件 ID、工件摘要、格式和分片数；MongoDB GridFS 保存 manifest 与压缩分片正文。
- `models.lstm.artifact-directory` 只作为快照构建和训练检查点的本地临时目录，不作为正式快照持久化位置。

### 11.2 流式构建与分片

| 参数 | 当前值 | 实现意图 |
|---|---:|---|
| 股票批次 | 100 | 控制单批行情和样本对象数量 |
| 行情查询线程 | 6 | 提高 MongoDB 读取吞吐，同时避免连接数无上限增长 |
| 查询重试 | 最多 3 次 | 处理临时断流，重试间隔逐次增加 |
| 分片格式 | `CHUNKED_JSON_GZIP_V1` | 支持逐批压缩、校验和历史格式区分 |
| 进度间隔 | 100 支股票 | 与分片边界一致，输出耗时和预计剩余时间 |

每批股票通过 `CompletionService` 并发查询最近 N 个交易日。单股票查询结束后立即按日期升序调用 `LstmDataPreprocessor.processStockData`，生成该股票训练集和验证集；批次完成后按原股票顺序汇总为本地临时 `chunk-xxxxx.json.gz`。写盘完成即释放该批行情及样本引用，内存中只保留分片描述和全局计数。

manifest 保存格式版本、特征数量、序列长度、标签缩放值、特征版本、单股样本上限、有效股票数、训练/验证样本数、数据截止日期以及每个分片的文件名、大小和 SHA-256。全部文件生成后逐个上传 MongoDB GridFS，MongoDB 元数据进入 `READY` 后立即删除本地快照目录。读取时先校验 GridFS manifest 摘要，再逐分片校验大小、SHA-256、GZIP 和汇总数量。

GridFS 文件统一保存 `snapshotId`、`artifactType=LSTM_TRAINING_SNAPSHOT` 和 `fileName` 元数据。上传或 MongoDB 元数据保存失败时，按 `snapshotId` 删除已上传文件并递归清理本地目录，避免产生半完成快照。

### 11.3 当前快照实例

2026-10-12 构建的快照 `6acc490f643b6156a8d17834` 使用 90 个交易日、4,619 支股票和每股 21 个样本上限。最终 4,614 支股票有行情，4,596 支形成有效样本，产生 73,516 条训练样本、13,786 条验证样本和 47 个分片，数据截止日期为 2026-10-09。该实例用于本轮训练复用和运行风险评估，不代表生产模型已经通过回测或激活。

## 12. 特征归一化与样本实现

### 12.1 样本选取和时间切分

`resolveSampleLimit` 使用 `max(4, min(maxSamplesPerStock, maxPanelSamples / stockCount))` 计算单股额度。`createSeriesSamples` 对全部可能窗口做确定性等距抽样，输入窗口长度为 60，标签位于窗口后的下一交易日。`processStockData` 按时间顺序取前 80% 为训练样本，跳过 2 个隔离样本后将剩余样本作为验证集。

### 12.2 16 维输入定义

| 索引 | 特征 | 归一化方式 | 模型用途 |
|---:|---|---|---|
| 0 | 开盘相对前收 | `open / previousClose - 1`，截断到 `[-1, 1]` | 时序主干 |
| 1 | 最高相对前收 | `high / previousClose - 1`，截断到 `[-1, 1]` | 时序主干 |
| 2 | 最低相对前收 | `low / previousClose - 1`，截断到 `[-1, 1]` | 时序主干 |
| 3 | 收盘收益 | `close / previousClose - 1`，截断到 `[-1, 1]` | 时序主干 |
| 4 | 相对成交量 | 当前量与 20 日均量比值取对数、除以 5，再截断到 `[-1, 1]` | 时序主干 |
| 5 | RSI | 除以 100，截断到 `[0, 1]` | 时序主干 |
| 6 | MACD 相对价格 | `MACD / close`，非法值回退为 0 | 时序主干 |
| 7 | 均线偏离 | `SMA / close - 1`，截断到 `[-1, 1]` | 时序主干 |
| 8 | 布林上轨偏离 | `upperBoll / close - 1`，截断到 `[-1, 1]` | 时序主干 |
| 9 | 布林下轨偏离 | `lowerBoll / close - 1`，截断到 `[-1, 1]` | 时序主干 |
| 10 | 相对 OBV | `OBV / 20 日成交量总和`，截断到 `[-1, 1]` | 时序主干 |
| 11 | 股票类别索引 | 股票代码映射到 8,192 个稳定哈希桶，0 为未知 | Stock Embedding |
| 12 | 行业类别索引 | 行业代码映射到 512 个稳定哈希桶，0 为未知 | Industry Embedding |
| 13 | 分组索引 | 行业桶映射到 8 个 Group Head；0 为未知，1 至 7 为有效组 | Group Head 路由 |
| 14 | 市场身份 | 市场文本稳定映射到 `[0, 1]` | 时序主干 |
| 15 | 相对成交额 | 当前成交额与 20 日均值比值取对数、除以 5，再截断到 `[-1, 1]` | 时序主干 |

所有输入先执行有限数检查，缺失、NaN 和无穷值转为 0。股票、行业和分组索引不进入 LSTM，`StockLSTMModel` 只把第 0 至 10 列及第 14 至 15 列送入时序主干，避免类别编号形成虚假的连续关系。

### 12.3 标签归一化

- 收益标签：`nextReturn / 0.1` 后截断到 `[-1, 1]`，模型输出使用 `tanh`，推理时乘回 `0.1`。
- 方向标签：下一交易日收益大于 0 为 1，否则为 0，模型输出使用 `sigmoid`。
- 下行风险：`-nextReturn / 0.1` 后截断到 `[0, 1]`，模型输出使用 `sigmoid`。

## 13. 模型结构、分组 Head 与训练实现

### 13.1 共享主干与身份特征

`StockLSTMModel` 使用 2 层单向 LSTM、隐藏维度 50、Dropout 0.2 和 LayerNorm，取最后一个时间步。股票 Embedding 为 `8192 x 16`，行业 Embedding 为 `512 x 8`；二者与 50 维时序表示拼接为 74 维共享表示，再经过共享投影层输出三个基础任务值。

### 13.2 Group Head 和 Residual Head

- Group Head 共 8 组，每组保存独立的 `74 x 3` 线性权重和 3 维偏置。当前组号由行业哈希桶对 7 取模获得，因此属于稳定技术分组，而非有业务名称的行业聚类。
- Group Head 输出乘以 0.1 后叠加到共享输出，限制分组修正幅度。
- Stock Residual Head 为每个股票哈希桶保存 3 维残差，输出同样乘以 0.1。它不会复制 LSTM，只对共享结果做轻量个股校正。
- 最终输出为 `sharedRaw + groupRaw + stockResidual`，再分别使用 `tanh`、`sigmoid`、`sigmoid` 得到收益、方向概率和下行风险。

### 13.3 损失与优化

`MultiTaskStockLoss` 对收益和下行风险使用 delta 为 0.1 的 Huber Loss，对方向使用 Binary Cross Entropy，权重为 0.5、0.3、0.2。优化器使用 Adam，学习率默认 0.001，权重衰减 0.001，批次大小默认 32。

训练最多执行 100 个 Epoch。每轮完成训练集更新和验证集评估，验证损失至少改善 0.0001 才更新最佳参数；连续 10 轮未改善时提前停止。每轮保存检查点并输出训练损失、验证损失、最佳验证损失、改善状态、早停计数、耗时和预计剩余时间。

### 13.4 候选制品

训练仅保存最佳验证轮次参数，并固化特征版本、结构参数、Embedding 桶数量、Head 配置、标签缩放值、样本数量和快照 ID。参数摘要、结构兼容性、有限损失和验证损失阈值全部通过后，版本从 `CANDIDATE` 进入 `READY`；训练结束不会自动激活。

## 14. 中断与恢复设计

- 每个 Epoch 完成后，通过 `ModelBinaryCodec` 序列化当前模型参数，写入本地临时检查点文件，并将 `checkpointEpoch` 写入训练运行记录。
- 停止请求、应用重启或异常失败时保留最后一个完整检查点；旧任务保持 `CANCELLED` 或 `FAILED`，不得覆盖历史记录。
- 恢复请求只接受已有检查点的中断或失败任务，读取原任务生效参数、数据快照和检查点，从 `checkpointEpoch` 之后继续训练。
- 恢复任务创建新的运行记录，写入 `resumedFromRunId`，训练完成后生成新的候选模型版本。
- 检查点只保存模型参数，不保存 DJL 优化器状态；恢复时重新初始化优化器，因此恢复结果必须记录来源和恢复轮次。
- 检查点读取失败、路径丢失或参数无法加载时立即拒绝恢复，不能退化为静默从头训练。
- 训练成功后删除当前检查点；恢复训练成功后同时删除来源任务的旧检查点，并清空 MongoDB 运行记录中的失效路径。
- 排队阶段取消尚未产生有效检查点，立即清理路径引用；运行中失败或取消仅在检查点文件真实存在时保留恢复能力。

## 15. 已知风险与优化方向

| 风险 | 当前影响 | 优化方向 |
|---|---|---|
| 训练读取仍一次性合并全部分片 | 快照构建内存已降低，但训练启动时仍可能产生较高 Java 堆占用 | 实现分片数据集和按分片/批次惰性加载 |
| 行业哈希碰撞 | 不同行业可能共享 Embedding 或 Group Head | 建立版本化行业字典，保留未知项但减少碰撞 |
| Group Head 无业务语义 | 难以解释每组表现，也可能混合结构差异较大的行业 | 用训练窗口内统计和样本外指标形成稳定语义组，并版本化路由 |

## 16. 预测记录与评估闭环设计

### 16.1 文档结构

MongoDB 新增两类文档：

- `model_prediction_batches`：保存批次状态、模型 ID/版本、基准交易日、目标交易日、股票总数、成功数、失败数、覆盖率、执行时间和能力汇总。
- `model_predictions`：保存单股预测输入口径、预测输出、实际结果、误差、方向命中和评估状态。

预测明细使用“模型 ID + 股票代码 + 基准交易日 + 目标交易日”唯一索引保证幂等。批次索引按创建时间和模型版本支持页面倒序查询，明细索引按批次、状态和预测收益支持筛选与排序。

### 16.2 服务职责

`ModelPredictionAnalysisService` 负责完整业务闭环：

1. 从激活指针读取并锁定本次使用的模型版本。
2. 获取全市场股票代码，以固定大小分批调用现有 `LstmInferenceService.predictNextBatch`，避免一次性构造过大的 DJL 输入数组。
3. 使用每只股票最新日线确定基准日期，使用交易日历解析下一目标交易日；若日历未覆盖未来日期，按工作日兜底并在日志中记录告警。
4. 逐批使用 MongoDB 批量写入预测明细，更新批次进度和成功/失败数量。
5. 评估时读取目标日行情，幂等回填实际收益及误差，再重新计算批次能力指标。
6. 分页提供批次、预测明细和能力概要，Controller 统一返回 `ResponseDTO<T>`。

全市场预测是用户显式操作，不自动受训练开关控制；并发保护仅防止同一节点重复执行预测批次，不影响正常单股在线推理。

### 16.3 交易日和实际值

- 基准交易日来自推理所用最后一条日线。批次以成功预测结果中的最晚基准日作为统一业务基准，并对日期不一致的明细保留自身基准日，便于识别停牌股票。
- 目标交易日优先查询交易日历中基准日之后的第一个交易日；数据库日历范围不足时跳过周末寻找下一个工作日。
- 实际收益率为 `(目标日收盘价 / 基准收盘价) - 1`。
- 收益误差为 `预测收益率 - 实际收益率`；绝对误差和平方误差用于 MAE、RMSE。
- 预测与实际收益同号时方向命中；零收益按非上涨处理，避免边界口径漂移。

### 16.4 能力指标算法

| 指标 | 实现方式 |
|---|---|
| 覆盖率 | 成功预测数 / 股票总数 |
| 评估完成率 | 已评估数 / 成功预测数 |
| 方向准确率 | 方向命中数 / 已评估数 |
| MAE | 绝对收益误差的算术平均值 |
| RMSE | 收益误差平方平均值的平方根 |
| Pearson IC | 预测收益与实际收益的线性相关系数 |
| Spearman Rank IC | 分别对预测收益和实际收益做平均秩排序后计算 Pearson 相关系数 |
| Top 10% 平均收益 | 按预测收益倒序取至少一条、最多前 10% 样本，计算实际收益均值 |
| Top 10% 方向命中率 | Top 10% 样本中实际上涨比例 |
| 高置信度方向准确率 | 上涨概率不低于 0.65 或不高于 0.35 的样本方向命中率 |
| 下行风险识别率 | 下行风险不低于 0.60 的样本中实际下跌比例 |

第一版能力分级阈值集中定义在评估服务中，作为工程基线：已评估少于 100 条为 `INSUFFICIENT_DATA`；方向准确率不低于 55%、Spearman IC 不低于 0.05、MAE 不高于 3%、Top 10% 平均实际收益为正时为 `STRONG`；方向准确率不低于 50%、Spearman IC 非负、MAE 不高于 5% 时为 `ACCEPTABLE`；其余为 `WEAK`。后续应迁移为配置并通过多日滚动验证校准。

`iterationRecommended` 在能力为 `WEAK` 时为真；样本不足仅提示继续观察，不直接建议重训。能力结论只用于运维决策，不触发训练或激活操作。

## 17. 每日预测调度设计

### 17.1 任务拆分

- `DailyModelPredictionJob` 封装每日预测业务入口，使用当前激活模型同步执行完整预测批次，确保统一任务执行记录与真实批次结果一致。
- `DailyModelPredictionQuartzJob` 作为固定 Quartz 包装，使用 `JobExecutionService` 记录触发来源、运行标识、开始时间、结束状态和异常。
- `ModelPredictionEvaluationQuartzJob` 在收盘行情同步后调用待评估批次扫描，批量回填所有仍包含 `PENDING` 明细的批次。
- 两个任务均注册到 `JobSchedulerService` 固定映射，并由新 Flyway 迁移写入 `job_config`，不使用 `@Scheduled`。

### 17.2 执行时点

| 任务 | Cron | 设计意图 |
|---|---|---|
| 每日全市场预测 | `0 15 6 ? * MON-FRI` | 开盘前使用最近完整日线生成当日预测，并早于 6:30 的选股任务完成 |
| 预测实际结果评估 | `0 30 18 ? * MON-FRI` | 日线同步任务 18:00 启动后执行回填；同步未完成的记录保留待评估并在后续任务重试 |

每日预测在 Quartz 线程内同步执行，手工页面入口继续使用应用线程池异步执行。预测循环每处理一批股票检查线程中断；收到统一任务停止请求后，将预测批次标记为 `CANCELLED` 并终止后续写入。

### 17.3 幂等与批量评估

- 自动预测根据模型 ID 和行情基准交易日查询已有批次，除 `FAILED`、`CANCELLED` 外均直接复用，避免同一天重复生成。
- `ModelPredictionBatchRepository` 提供可评估状态批次查询，`ModelPredictionRepository` 提供批次是否仍存在 `PENDING` 明细的判断。
- 自动评估逐批调用统一评估逻辑；单个批次失败只记录告警，不阻断其余批次，任务结束时汇总扫描数、更新数和失败数。

### 17.4 时间与日历标记

- 批次增加 `informationCutoffAt`，记录提交预测时的自然时间；明细继续使用 `predictedAt` 记录实际生成时间。
- 批次和明细增加 `calendarFallback`，表示目标交易日是否由跳过周末的工作日规则推算。
