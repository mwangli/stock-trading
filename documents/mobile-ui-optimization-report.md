# 移动端 UI 优化报告

## 1. 结论摘要

本次优化面向只读股票交易控制台，目标设备为 iPhone 12 竖屏 `390 × 844`，同时覆盖横屏 `844 × 390` 和最低 `320px` 宽度。改造遵循“桌面工作台保持稳定、手机端重新组织信息”的原则，没有引入 `antd-mobile`、React Native 或新的 npm 依赖，也没有修改后端接口和数据契约。

核心变化如下：

- 手机端取消固定侧栏，改为四个高频入口加“更多”的五项底部导航。
- 增加 iPhone 刘海和 Home Indicator 安全区处理。
- 动态数据表格在手机端转换为摘要卡片，并可展开查看剩余字段。
- 行情目录、Agent 会话和文档目录从双栏改为底部抽屉。
- Agent、日志、Markdown、K 线和登录页获得独立的手机布局。
- 新增开发环境 React Demo 路由 `/mobile-demo`，并提供可直接双击打开的 `stock-web/mobile-demo.html`，两者都不连接真实后端。

## 3. 优化前问题

### P0：手机布局不可用

- `<=760px` 时侧栏被固定在屏幕左侧，内容仍增加 `80px` 或 `236px` 左边距。
- iPhone 12 展开侧栏后正文只剩约 `154px`，图表、表格和输入框无法正常使用。
- 页面未使用 `safe-area-inset-*`，固定区域可能与刘海或 Home Indicator 冲突。

### P1：移动信息架构不合理

- 七个页面仍依赖桌面侧栏，单手切换成本高。
- 交易、模型和任务表格最多展示 12 列，只能反复横向滑动。
- 行情股票目录、Agent 会话和文档目录在手机端占据内容之前的大块空间。
- Agent 聊天区固定 `650px`，没有根据移动浏览器可用高度计算。

### P2：视觉和交互细节不统一

- 页面间距混用 `14px`、`18px`、`22px` 等值，视觉节奏不稳定。
- 图标按钮虽有部分 `aria-label`，但缺少统一焦点、按下和禁用反馈。
- 登录页品牌区域占 `36vh`，在较矮设备上挤压登录表单。

## 4. 信息架构与断点

### 4.1 手机导航

底部导航固定为五项：

1. 概览
2. 行情
3. 交易
4. Agent
5. 更多

“更多”抽屉包含模型与预测、运行状态与日志、文档工作台、主题切换和退出登录。模型、运行状态或文档页面打开时，“更多”保持激活状态。

### 4.2 响应式范围

| 范围 | 行为 |
| --- | --- |
| `<=480px` | 手机专用顶部栏、底部导航、抽屉目录和摘要卡片 |
| `481px–760px` | 单列内容布局，仍保留桌面导航结构 |
| `761px–1100px` | 两列内容逐步收敛，图表和目录保持可用 |
| `>1100px` | 完整桌面工作台 |

手机端使用 `100dvh`，顶部和底部空间分别叠加 `safe-area-inset-top` 与 `safe-area-inset-bottom`。正文额外预留底部导航高度，避免最后一行数据或 Agent 输入框被遮挡。

## 7. Hallmark 静态审查

执行方式：

```text
node sloplint.mjs <CSS/TSX 文件> --genre modern-minimal --scope app
```

没有使用 `--render`，没有启动浏览器。

首次结果：`7 FAIL · 65 REFLEX · 3 WARN`。

修复内容：

- 将侧栏边线、品牌文字和 Demo 阴影颜色收敛为语义变量。
- 增加按钮按下、禁用和键盘焦点状态。
- 增加标题行平衡处理。
- 移除 Demo 同时使用边框和大阴影的重复层级表达。
- 将公共和移动端主要间距收敛到 4px 基础尺度。

最终结果：`2 FAIL · 0 REFLEX · 1 WARN`。

保留的两个 FAIL：

1. Hallmark 要求 CSS 第一行是其 Stamp，但项目规范要求 AI 生成标记位于文件第一行。项目规范优先，Hallmark 说明放在第二行。
2. 扫描器同时发现桌面侧栏和手机顶部栏使用 `sticky top: 0`。React 在 `<=480px` 时不会渲染桌面侧栏，两者不会同时存在，属于静态扫描误报。

剩余 WARN 是 Markdown 引用块的左侧强调线，属于内容语义设计，予以保留。

新增的纯静态 `mobile-demo.html` 单文件 Hallmark 审查结果为 `0 FAIL · 1 WARN`。唯一 WARN 将底部导航的浅色选中态与 Agent 发送按钮同时识别为填充主按钮；前者是导航位置反馈，后者是页面命令，两者颜色强度和交互职责不同，因此保留。
