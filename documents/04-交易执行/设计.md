# 自动真实交易执行设计

## 核心链路

系统只保留无人值守真实交易：

`收盘后数据同步 -> 离线 LSTM 更新 -> 新闻情感推理 -> 候选排名 -> Java 风控 -> 券商真实委托 -> 订单与成交留痕`

模型只生成候选和分数，不持有券商凭据，也不能直接调用券商接口。所有订单必须经过 `RealTradingService -> RiskController -> TradeExecutor -> ZXBrokerAdapter`。

## 执行门禁

自动委托必须同时满足：

1. 券商会话有效。
2. `TRADING_REAL_WRITE_ENABLED=true`。
3. 当日候选、可成交性、仓位、资金、T+1、止损和重复委托检查全部通过。

真实写入门禁默认关闭，它是事故隔离开关，不是人工逐单审批。

## 固定任务

- 06:00 增量采集新闻和公告。
- 06:30 使用当前生效的 LSTM 与情感模型生成候选。
- 09:35 自动买入排名靠前且未持仓的候选。
- 14:50 检查止损、止盈和 T+1 尾盘退出。
- 18:00 同步日线数据。
- 19:00 检查并更新缺失、版本不兼容或超过 30 天的全市场共享 LSTM 基础模型。

任务配置由代码固定维护，不提供通用任务管理页面、手动运行接口或在线 Cron 修改接口。

## 模型与通知边界

- 生产交易期间禁止训练模型。
- 不开放 LSTM 或情感模型在线训练、下载、切换和审批接口。
- 只保留当前生效的全市场共享 LSTM 模型及必要版本元数据；不再维护完整逐股模型。
- 通知只保留 `TradeNotificationPort` 扩展接口，当前空实现不发送 WebSocket、微信或其他外部消息。
- 订单、成交、异常和调度结果继续通过数据库及应用日志留痕。

## 验证边界

静态检查不能证明真实账户交易可用。启用真实写入前仍需在实际环境核验券商登录、资金、持仓、订单回查、T+1 和风控参数。
