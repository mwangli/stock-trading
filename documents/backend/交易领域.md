# 交易领域

## 领域定位

`com.stock.trading` 是 Backend 的真实交易安全边界，负责用户认证、运行开关、账户和持仓事实、订单、风险校验、券商适配、事实同步、交易记录及绩效聚合。

## 执行链路

```text
候选或人工请求
  → 用户范围与真实写入开关
  → 交易日和交易时间
  → 最新价格与可交易状态
  → 账户资金、持仓和 T+1
  → 仓位、费用、数量和幂等
  → 券商委托
  → 订单回查、成交同步和持久化
```

任何真实交易都必须在提交券商前重新读取当前事实。上游候选、模型预测、Agent 建议和历史缓存不能替代执行时检查。

## 风险与幂等

- `TRADING_REAL_WRITE_ENABLED` 默认关闭，券商可登录不等于允许委托。
- 当前日期和时间必须处于已确认的交易窗口。
- 股票状态、价格、账户资金、仓位和 T+1 可卖数量必须可确认。
- 相同业务批次和候选不得重复执行。
- 网络超时或结果不确定时优先回查订单，不能立即重复提交。
- 券商受理、部分成交、全部成交、拒绝和待确认使用不同状态。

委托数量按交易单位、可用资金、价格和预估费用计算。绩效只使用真实成交和费用，预测或页面估算不能写入已实现收益。

## 券商接入

券商差异封装在 `BrokerAdapter` 及具体实现中，业务 Service 使用统一的登录、账户、持仓、订单、成交、委托和撤单语义。凭据、Token、签名密钥和 OCR Key 只从运行环境读取。

查询结果不得返回敏感凭据或不必要的完整账户标识。验证码识别必须经过格式和计算校验，失败时终止登录而不是降低认证要求。

## 事实同步和记录聚合

账户与持仓按采集时间保存快照，订单和成交按券商业务标识幂等更新。历史查询达到单次上限时拆分时间窗口，避免静默截断。

交易记录从真实订单和成交聚合买卖批次、数量、成本、收入、费用和已实现收益。无法匹配的数量单独记录，不能猜测成本。

## 降级和 Agent 边界

券商未启用时保留本地数据、策略和模型能力；未登录时允许查看本地历史但禁止实时查询和写入；查询失败时保留最近快照并标记采集时间。

Agent 不持有券商凭据，不调用券商写接口，也不控制、暂停或放行真实订单。Agent 计划或建议只能作为独立记录，不能绕过本领域的执行入口。
