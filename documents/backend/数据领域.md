# 数据领域

## 领域定位

`com.stock.data` 是 Backend 的事实数据领域，负责股票资料、行情、新闻、交易日历、复权、参考序列、历史股票池和可交易状态的采集、标准化、持久化与查询。

## 核心能力

| 能力 | 当前职责 |
|---|---|
| 股票资料 | 全量同步代码、名称、市场、上市和退市信息 |
| 行情 | 日线日常增量、独立历史回补、分钟数据及查询 |
| 交易日历 | 维护开闭市状态、节假日、覆盖范围和确认状态 |
| 模型数据基础 | 维护复权因子、参考指数、历史股票池和每日可交易事实 |
| 新闻 | 按股票和来源采集、去重、分类并保存事件元数据 |
| 数据质量 | 区分缺失、过期、解析失败、来源不可用和覆盖不足 |

## 股票资料同步

同步流程先获取证券接口全量结果，再一次性读取数据库现有股票，并按股票代码划分交集、接口新增和数据库独有集合。

- 交集记录先构造更新集合，再批量更新。
- 接口新增记录补充上市日期后批量插入。
- 数据库独有记录只有在现有资料明确确认退市时才清理关联数据。
- 接口空响应、解析失败或关键范围不明时，本轮同步必须失败。

## 行情与日历

日常增量只处理当前应同步窗口，不被长期历史缺口阻断；历史回补使用独立任务按时间窗口递进。相同股票、时间和数据类型保持幂等。

交易日历优先读取已确认记录。覆盖缺失时触发维护或返回未确认状态，模型、回测和自动交易不得只根据工作日或周末猜测交易日。

## 新闻和数据质量

新闻记录保留标题、摘要、发布时间、来源和处理状态。情感与事件标签属于推断结果，不能替代原文和来源证据。

训练和回测数据按时间截断，记录业务日期、来源时间、覆盖范围及批次成功、跳过和失败原因。局部数据不能表述为全量数据。

## 存储与协作

股票资料、行情、新闻、日历、复权、历史股票池和可交易事实写入 MongoDB；Redis 只缓存热点查询，权威数据变更时同步失效缓存。

模型、策略和交易领域通过明确 Service 或 Repository 使用事实数据。Agent 只能通过内部事实 API 获取受控摘要。
