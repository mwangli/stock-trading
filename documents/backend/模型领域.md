# 模型领域

## 领域定位

`com.stock.model` 负责训练快照、LSTM 训练与推理、财经情感推理、模型版本、预测批次、候选评估、激活和回滚。模型输出是策略输入，不直接产生真实委托。

尚未完成全部编译和运行验证的 Ranking/LSTM 优化设计见[RankingLSTM-v5 Proposal](../proposals/model/RankingLSTM-v5.md)，不在本文作为生产能力陈述。

## 训练快照

训练前创建不可变快照，记录股票范围、日期范围、样本数量、特征和标签版本、切分策略、文件信息及校验值。数据准备失败与模型训练失败使用不同状态表达。

训练、验证和测试按时间切分，统计量只允许由对应训练窗口拟合，避免未来数据泄漏。快照文件和模型参数保存到 MongoDB GridFS，常规运行与版本元数据保存到 MySQL。

## 训练与候选

训练由 Backend 的统一任务体系触发，并受以下边界约束：

- 训练能力需要显式启用。
- 交易关键时间窗口不执行高资源训练。
- 同一时间只允许受控数量的训练任务。
- 训练成功只生成候选版本，不自动替换当前激活模型。
- 训练异常保留当前激活版本，并记录明确失败原因。

具体候选模型的结构、损失和指标门禁属于对应 Proposal 或版本契约。

## 推理与预测批次

预测流程确认目标交易日和行情覆盖，解析当前激活模型，筛选满足历史长度和质量要求的股票，按制品元数据构建输入并保存预测结果。批次记录模型版本、交易日期、成功数、跳过数和失败原因。

旧制品与新制品按各自元数据和输出契约加载，不能通过修改旧元数据伪装兼容。策略和 Agent 消费预测摘要时必须保留来源模型与批次信息。

## 模型制品

| 制品 | 位置 | 生命周期 |
|---|---|---|
| Embedding | `model-files/embedding` | Agent 固定只读制品 |
| Sentiment | `model-files/sentiment` | Backend 固定只读制品 |
| LSTM 参数与快照 | MongoDB GridFS | 训练、候选、激活和回滚生命周期 |

固定制品不打入可执行 JAR，部署时只读挂载。LSTM 制品必须与模型元数据、输入输出契约、训练版本和激活指针共同管理。

## 评估与激活

评估使用预测产生之后的真实行情，分别统计方向、收益、排序、覆盖和成本影响。不同数据范围、费用版本和模型契约的结果不能直接比较。

候选通过离线门禁后仍需独立观察；人工激活、回滚和当前版本切换必须保留审计记录。构建成功不能代替模型效果验证。
