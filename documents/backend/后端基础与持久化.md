# 后端基础与持久化

## 模块定位

`stock-backend` 是核心 Spring Boot 服务，启动入口为 `com.stock.backend.StockBackendApplication`，默认端口 8080。它承载数据、模型、确定性策略、交易、Quartz 编排、内部事实 API 和真实交易安全边界。

后端内部使用 Java 包隔离领域，不拆分为额外 Maven 模块：

| 包根 | 职责 |
|---|---|
| `com.stock.base` | 统一响应、异常、Port 和内部接口安全等稳定公共契约 |
| `com.stock.data` | 股票、行情、新闻、交易日历和数据质量 |
| `com.stock.model` | 训练、推理、模型版本、预测和评估 |
| `com.stock.strategy` | 排名、信号、配置、状态和回测 |
| `com.stock.trading` | 用户、账户、持仓、订单、风控和券商执行 |
| `com.stock.job` | Quartz 任务、执行记录和跨领域编排 |
| `com.stock.backend` | 启动、持久化、缓存、内部 API 和应用装配 |

## 公共契约

`com.stock.base` 只保存 Backend 多领域实际复用、语义稳定的类型，包括 `ResponseDTO<T>`、内部查询 Port、业务安全跳过异常及内部 API 令牌校验。业务 Entity、Repository、Controller 和具体 Service 不进入公共包。

Backend 与 Agent 不共享公共 Java JAR，而是使用各自定义的 HTTP DTO 交换结构化数据。

## 持久化职责

- MySQL 保存需要事务、状态和锁约束的用户、配置、任务、模型元数据及交易记录。
- MongoDB 保存行情、新闻、预测、回测、账户和持仓快照等增量或大文档数据。
- MongoDB GridFS 保存 LSTM 参数和训练快照等大文件。
- Redis 保存共享登录 Session 和可重建查询缓存，不作为权威数据库。
- Flyway 只管理 MySQL 结构；MongoDB 通过文档映射和索引初始化维护集合。

完整的数据所有权表见[系统架构](../architecture/系统架构.md)。

## 启动期动作

1. 校验 MySQL、MongoDB 和 Redis 配置。
2. 使用 Flyway 迁移 MySQL。
3. 由 `JobBootstrap` 幂等补齐固定任务配置并重建 Quartz RAMJobStore。
4. 初始化必要的 MongoDB 索引。
5. 检查 Sentiment 制品及其他可选模型能力并暴露真实状态。

核心数据库不可用时服务不能伪装为正常；可选模型或 Agent 不可用时允许受控降级，但不能改变交易权限。

## 内部事实 API

`/api/internal/agentFacts/**` 向 Agent 提供最小、只读、结构化事实。请求必须通过 `X-Internal-Token` 校验，外部入口由 Nginx 阻断。具体 Agent 边界见[Agent 架构](../agent/Agent架构.md)。
