# 核心业务链路

## 主链路

```text
市场数据采集
  → 数据质量与交易日确认
  → 模型训练或批量推理
  → 策略排名与候选信号
  → Java 风控复核
  → 券商委托
  → 订单、成交、持仓与绩效回写
```

## 数据准备

Backend 从证券接口采集股票资料、行情、复权因子、可交易状态、新闻和交易日历，完成解析、去重、覆盖范围与来源状态检查后写入权威存储。日常增量和历史回补独立运行；数据源整体为空、解析失败或关键范围不明确时必须失败。详细规则见[数据领域](../backend/数据领域.md)。

## 模型与策略

模型领域从合格数据生成训练快照、候选模型和预测批次。模型激活与训练分离，预测结果携带模型版本、交易日期和质量状态。

策略领域将模型预测、情感、技术指标、成交量和配置规则转换为排名、信号与候选集合。候选必须携带来源批次、策略版本和有效期。详细说明见[模型领域](../backend/模型领域.md)和[策略领域](../backend/策略领域.md)。

## Agent 增强

Agent 通过只读工具获取脱敏事实，生成研究、诊断、报告、交易计划草案或独立交易建议。建议单独保存和评估，不控制、暂停或放行 Backend 自动交易。详细边界见[Agent 架构](../agent/Agent架构.md)。

## 交易执行

交易领域在提交委托前重新读取最新账户、持仓、交易时间、交易日历、价格和运行开关，并执行权限、资金、仓位、T+1、停牌、涨跌停、幂等和批次隔离检查。券商订单和成交回写后，系统基于真实成交聚合交易记录与已实现收益。详细规则见[交易领域](../backend/交易领域.md)。

## 任务编排

Quartz Job 只确定触发时机、调用领域 Service 并记录执行结果，不复制数据、模型、策略或交易算法。固定任务与运行边界见[任务调度](../backend/任务调度.md)。

## 失败与降级

| 故障 | 当前处理原则 |
|---|---|
| Agent Provider 超时或熔断 | 记录建议失败，不影响 Backend 确定性交易链 |
| Embedding 不可用 | RAG 和向量 Memory 不可用，其他不依赖检索的 Agent 任务可继续 |
| 情感模型不可用 | 停止依赖情感的增强评分并暴露降级状态 |
| 历史行情存在缺口 | 日常增量继续，缺口交由独立回补任务处理 |
| 券商会话失效 | 禁止实时查询和真实写入，保留本地历史诊断 |
| 交易日历未确认 | 禁止自动交易，不使用工作日猜测替代 |
| 训练失败 | 保留当前激活模型，失败候选不得生效 |
