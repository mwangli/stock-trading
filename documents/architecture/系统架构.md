# 系统架构

## 系统定位

`stock-trading4` 是面向 A 股的数据、模型、确定性策略、Agent 辅助分析、风险控制和券商执行平台。项目只保留三个 Maven 模块：

| 模块 | 当前职责 | 默认端口 |
|---|---|---:|
| `stock-backend` | 数据、模型、策略、交易、Quartz、内部事实 API 和唯一真实交易执行边界 | 8080 |
| `stock-agent` | LangChain4j、RAG、Memory、研究诊断、交易计划草案和独立交易建议 | 8081 |
| `stock-frontend` | React 页面、交互状态及 Nginx API 分流 | 80 |

Backend 内部使用 `com.stock.base`、`data`、`model`、`strategy`、`trading`、`job` 和 `backend` 表达领域边界，这些包不是独立 Maven 模块。

## 运行关系

```text
浏览器
  |
stock-frontend:80
  |-- /api/agent/** --> stock-agent:8081
  |-- /api/** -------> stock-backend:8080
  `-- /ws/** --------> stock-backend:8080

stock-agent -- /api/internal/agentFacts/** --> stock-backend
```

`/api/internal/**` 不向浏览器开放。Backend 与 Agent 的内部调用使用 `X-Internal-Token`，两者不共享 Java 源码或 Maven 依赖。业务流程见[核心业务链路](核心业务链路.md)。

## 数据所有权

| 数据类别 | 权威存储 | 所有者 |
|---|---|---|
| 用户、配置、任务、模型元数据、交易批次与状态 | MySQL | Backend |
| 行情、新闻、预测明细、回测、账户和持仓快照 | MongoDB | Backend |
| Agent 会话、任务、Memory、RAG、计划与审计 | MongoDB | Agent |
| 登录 Session、可重建查询缓存 | Redis | Backend 与 Agent |
| LSTM 参数和训练快照 | MongoDB GridFS | Backend |
| Embedding 固定制品 | `model-files/embedding` | Agent |
| Sentiment 固定制品 | `model-files/sentiment` | Backend |

Redis 不保存不可丢失的业务事实。详细持久化职责见[后端基础与持久化](../backend/后端基础与持久化.md)。

## 核心边界

- 行情、账户、持仓、订单和交易日历属于事实；模型和 Agent 输出属于推断。
- 真实委托只能由 Backend 使用最新事实重新完成权限、风控、幂等和券商校验后提交。
- Agent 只通过受保护的内部事实 API 获取最小、只读、脱敏数据，不连接 Backend Repository 或券商写接口。
- Agent、Provider、RAG 或缓存不可用时，不得扩大交易权限或改变 Backend 的确定性交易链。
- 模型训练、候选、激活和回滚边界由[模型领域](../backend/模型领域.md)统一定义。
- 同一能力只保留一个当前入口，不维护旧模块、旧 URL 或重复兼容链。
