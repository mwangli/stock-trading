# 部署运行

## Compose 服务

生产形态包含三个应用服务和三个基础设施服务：

```text
stock-frontend:80
  |-- stock-backend:8080
  `-- stock-agent:8081

stock-backend --> stock-mysql + stock-mongo + stock-redis
stock-agent   --> stock-mongo + stock-redis
```

Backend 和 Agent 端口只绑定宿主机回环地址，外部请求统一从 Frontend Nginx 进入。Nginx 对 `/api/internal/**` 返回 404。

## 构建产物与分流

| 模块 | 产物 | 发布容器 |
|---|---|---|
| `stock-backend` | `stock-backend-*.jar` | Java 17 JRE，8080 |
| `stock-agent` | `stock-agent-*.jar` | Java 17 JRE，8081 |
| `stock-frontend` | Vite `dist/` | Nginx，80 |

| 路径 | 目标 |
|---|---|
| `/api/agent/**` | Agent |
| `/api/internal/**` | 外部拒绝 |
| 其他 `/api/**` | Backend |
| `/ws/**` | Backend |
| 其他路径 | React SPA |

## 配置与持久化

- `.env` 注入镜像、数据库、Redis、内部令牌及其他部署环境参数。
- 数据库密码、Provider Key、券商凭据和签名密钥只从运行环境读取。
- `INTERNAL_API_TOKEN` 同时注入 Backend 与 Agent，不能发送到浏览器。
- `TRADING_REAL_WRITE_ENABLED` 默认关闭。
- MySQL、MongoDB 使用宿主机持久化目录；Redis 使用 AOF，但仍只承担 Session 和可重建缓存。
- `model-files` 以只读卷挂载；Backend 加载 Sentiment，Agent 加载 Embedding。

## CI/CD

| 标签 | 工作流 | 目标服务 |
|---|---|---|
| `backend-vX.Y[.Z]` | `backend-ci-cd.yml` | `stock-backend` |
| `agent-vX.Y[.Z]` | `agent-ci-cd.yml` | `stock-agent` |
| `frontend-vX.Y[.Z]` | `frontend-ci-cd.yml` | `stock-frontend` |

工作流只重建目标服务并保留其他服务。Backend 发布校验 Sentiment 制品，Agent 发布校验 Embedding 制品；失败时收集目标服务日志并恢复原镜像。

## 验证边界

容器健康或 HTTP 可达只证明进程入口可用，不代表数据库、模型、Provider、Quartz、券商和业务任务全部正常。发布后需要分别核对镜像 SHA、容器健康、启动日志、依赖状态和目标业务终态。
