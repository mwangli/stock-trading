# 轻量模型 ONNX 迁移实施计划

## 1. 文档信息

| 项目 | 内容 |
|---|---|
| 文档日期 | 2026-10-09 |
| 适用系统 | stock-trading4 自动真实交易系统 |
| 迁移目标 | MiniRBT FP32 ONNX 情感推理（资源不足时 INT8 降级）+ LSTM FP32 ONNX 推理 + ONNX Runtime |
| 目标环境 | 2C4G 云服务器，保留本地 MongoDB，前端与 Spring Boot 分容器部署 |
| 在线原则 | 云端只执行推理，不执行模型训练、蒸馏、量化或全市场回测 |
| 安全原则 | 模型不可用、元数据不兼容或推理失败时停止候选生成，不使用规则结果冒充模型结果 |

## 2. 结论

本次迁移分为两个独立但最终汇合的模型链路：

1. 情感模型由 `yiyanghkust/finbert-tone-chinese + PyTorch FP32` 迁移为 `MiniRBT-H256 + ONNX FP32`；只有 FP32 在 2C4G 实测资源不足时才评估 INT8 降级。
2. LSTM 由 `DJL 自定义 Block + PyTorch FP32` 迁移为保持相同结构和权重语义的 `ONNX FP32`。
3. 云端统一使用 ONNX Runtime，模型训练仍在本地离线环境完成。
4. 迁移期间保留 PyTorch 和 ONNX 双引擎，通过影子推理验证模型输出、候选排名和风控结论。
5. 只有情感模型和 LSTM 均通过验收后，才能从生产包移除 PyTorch 原生运行库。

预期收益：

| 项目 | 预期变化 |
|---|---|
| 生产 JAR | 移除约 126MB 的 PyTorch CPU 原生依赖，最终包体预计减少约 130MB |
| 情感模型内存 | 先以 FP32 ONNX 实测；仅在资源不达标时评估 INT8，不能预先承诺固定降幅 |
| LSTM 内存 | 模型权重变化很小，但消除每次推理重新创建 PyTorch 模型的波动 |
| 整机内存 | 2C4G 目标常驻不超过 3.2GB，批量推理峰值不超过 3.5GB，模型切换峰值不超过 3.6GB |
| 推理性能 | 情感推理预计显著加快；LSTM 主要改善初始化、模型复用和批量推理稳定性 |
| 业务能力 | LSTM 应接近无损；情感模型存在中等能力损失风险，必须通过蒸馏和业务回放控制 |

## 3. 当前实现基线

### 3.1 情感模型

当前 `SentimentTrainerService` 同时负责模型加载、Tokenizer 初始化、PyTorch 推理、概率转换、健康状态、重新加载和非严格接口的规则降级。

严格交易入口调用 `analyzeSentimentRequired`。模型无法加载或推理失败时抛出异常，阻止交易候选生成。迁移后必须保留这一行为。

情感结果还参与以下业务逻辑：

- 按模型置信度、新闻时间、来源和事件类型进行加权。
- 计算股票情感聚合分数。
- 识别强负面事件并将聚合分数限制到 `-0.8` 以下。
- 与 LSTM 因子共同参与候选股票综合评分，默认权重约为 50%/50%。

因此，验收不能只比较分类准确率，还必须检查置信度分布、强负面触发和候选排序。

### 3.2 LSTM 模型

当前共享多任务 LSTM 包含：

- 两层单向 LSTM，隐藏层大小 50。
- 60 个时间步、13 个连续时序特征。
- 股票 Embedding：`8192 x 16`。
- 行业 Embedding：`512 x 8`。
- 8 个分组 Head。
- 个股 Residual Head。
- 收益率、上涨概率、下行风险三个输出。

当前模型参数以 DJL 二进制格式存入 MongoDB。推理时重新创建 PyTorch `NDManager` 和模型，再从 MongoDB 加载参数。模型本身不足约 20 万参数，FP32 权重约 0.8MB，因此 LSTM 不需要 INT8 量化。

### 3.3 生产依赖

当前生产包包含 DJL API、DJL PyTorch Engine、PyTorch CPU 原生运行库和 Hugging Face Tokenizers。

迁移中不能在情感模型完成 ONNX 化后立即删除 PyTorch，因为 LSTM 仍依赖 PyTorch。必须等两个模型均切换为 ONNX 后再删除。

### 6.2 教师软标签与蒸馏

使用当前 FinBERT 对训练样本生成三分类 Logits。蒸馏损失建议：

```text

          + (1 - alpha) * temperatureDistillationLoss
```

首轮参数：

```text

maxSequenceLength=128
```

这些值只作为初始参数，最终以独立时间窗口验证结果为准。

### 6.3 本地训练工具

建议新增：

```text

  generate_teacher_logits.py
  train_student.py
  evaluate_student.py
```

训练输出必须保存最佳 FP32 学生模型、FP32 ONNX、Tokenizer、标签映射、数据时间范围、分类指标、混淆矩阵和置信度校准指标。只有 FP32 资源验收失败时才额外保存 INT8 降级候选。

### 6.4 资源不足时的 ONNX INT8 降级

FP32 ONNX 是默认生产制品。只有 FP32 在 2C4G 环境中无法满足常驻内存、推理峰值或模型切换峰值门槛时，才执行 CPU 动态 INT8 量化：

1. 导出 MiniRBT FP32 ONNX。
2. 验证 FP32 ONNX 与训练框架输出。
3. 执行动态 INT8 量化。
4. 比较 INT8 与 FP32 的分类、概率和置信度分布。
5. 生成 `metrics.json` 和 SHA-256 摘要。

如果 INT8 导致负面召回率、置信度、候选排序或风控结论下降，应继续使用 FP32 ONNX，并优先扩容服务器；不得为了内存目标上线不合格制品。

### 6.6 Session 与并发

2C4G 环境建议：

- 每个模型只保留一个 Session。
- 情感推理 `intraOpThreads=1`、`interOpThreads=1`。
- 不为每条新闻创建 Session。
- 情感分析按事件组串行或小批量执行，禁止无界并发。

重新加载时先创建并验证新 Session，再原子替换引用，等待在途请求结束后关闭旧 Session。

## 7. LSTM 模型迁移实现

### 7.1 实施选择

不建议尝试从 DJL 自定义 Block 直接生成 ONNX。推荐增加明确的中间权重格式，再由本地 Python 转换器构建等价模型并导出 ONNX：

```text
DJL 模型参数
  → Java 权重导出器
  → manifest.json + float32 tensor files
  → Python 等价模型加载
  → 输出一致性检查
  → FP32 ONNX 导出
```

中间格式只用于离线转换，不在生产节点加载。

### 7.2 Java 权重导出器

新增离线工具 `DjlLstmWeightExporter`，负责：

- 从 MongoDB 或本地目录读取 DJL 参数。
- 按参数名称导出所有张量。
- 每个张量使用小端序 FP32 二进制文件。
- 在 `manifest.json` 记录名称、形状、数据类型、长度和摘要。
- 导出模型元数据以及固定的 Golden Input/Output。

建议结构：

```text
lstm-export/
  manifest.json
  metadata.json
  tensors/
    temporal_lstm_weight_ih_l0.bin

    stock_embedding.bin
    industry_embedding.bin
    group_head_weights.bin
    group_head_bias.bin
    stock_residual.bin
  golden/
    input.bin
    output.bin
```

参数名称由映射表显式管理，禁止依赖集合遍历顺序。

### 7.3 Python 等价模型

建议新增：

```text

  stock_lstm_model.py
  load_djl_weights.py
  verify_weight_mapping.py

```

Python模型必须复刻双层单向LSTM、LayerNorm、最后时间步提取、股票与行业Embedding、Shared Projection、Group Head、Residual Head以及三个输出激活。

需要特别验证不同框架的 LSTM Gate 权重排列。若 Gate 顺序不一致，转换脚本必须显式重排，不能通过放宽误差掩盖错误。

### 7.4 ONNX 输入输出契约

保留现有展平输入，减少 Java 预处理改动：

```text
input name: features
input shape: [batch, 960]
input dtype: float32
```

其中 `960 = 60 x 16`。模型内部恢复为 `[batch, 60, 16]`。

输出：

```text
output name: predictions
output shape: [batch, 3]
output dtype: float32
```

输出顺序：

```text
0 = scaledReturn
1 = directionProbability
2 = downsideRisk
```

只允许 Batch 维度动态，序列长度和特征维度固定。

新增：

## 9. 双引擎影子推理

影子模式下主引擎继续产生正式业务结果，影子引擎使用相同输入执行预测，影子结果只记录差异，不进入候选评分和交易链路。

情感差异至少记录标签、三分类概率、连续得分、置信度、强负面判断、聚合得分影响和Top N排序影响。

LSTM差异至少记录三个输出绝对误差、股票排序、阈值判断和最终候选集合变化。

日志不得保存完整敏感新闻正文，只记录样本摘要、模型版本和差异指标。

## 11. 分阶段实施

### 阶段0：建立基线

固化FinBERT评估集和LSTM Golden Input/Output，记录当前准确率、候选排序、强负面、时延和内存。

退出条件：基线可重复，输入输出均可追溯。

### 阶段1：MiniRBT FP32学生模型

准备金融数据、生成教师软标签、完成蒸馏和微调并导出FP32 ONNX。

退出条件：FP32学生模型达到业务门槛。

### 阶段2：MiniRBT FP32 资源验收与可选 INT8 降级

先验证 FP32 ONNX 的业务指标和 2C4G 资源占用；仅资源不达标时量化 INT8，并重新比较分类、概率、置信度、候选排序和风控结论。

退出条件：FP32 达到业务与资源门槛；或 FP32 资源不达标且 INT8 同时达到业务与资源门槛。

### 阶段3：Java情感ONNX接入

增加推理接口和ONNX实现，保留PyTorch主引擎并开启影子推理。
