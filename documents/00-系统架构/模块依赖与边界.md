# 模块依赖与边界

## Maven 结构

根 `pom.xml` 是仓库级聚合入口，仅注册 `stock-application`；`stock-application/pom.xml` 是应用父 POM，统一管理版本、插件和九个业务模块：

```text
stock-application/
├── stock-base
├── stock-data
├── stock-model
├── stock-strategy
├── stock-trading
├── stock-agent
├── stock-job
├── stock-web
└── stock-starter
```

## 依赖方向

```text
stock-base
   ↓
stock-data
   ↓
stock-model
   ↓
stock-strategy
   ↓
stock-trading
   ↓
stock-agent
   ↓
stock-job
   ↓
stock-starter

stock-web ───────────────→ stock-starter
```

箭头表示上游能力被下游模块依赖。下层模块不得反向依赖上层实现。

## 模块职责

| 模块 | 允许承载 | 不应承载 |
|---|---|---|
| `stock-base` | 稳定 Port、公共响应、跨模块值对象和基础异常 | 领域 Service、Entity、Controller、数据库访问 |
| `stock-data` | 市场数据采集、清洗、质量校验和持久化 | 模型训练、策略决策、券商交易 |
| `stock-model` | 数据快照、训练、推理、模型版本和预测评估 | 最终交易指令和券商访问 |
| `stock-strategy` | 确定性选股、信号、策略状态和回测 | 绕过交易风控执行委托 |
| `stock-trading` | 用户、账户、持仓、订单、风控和券商适配 | 将模型或 Agent 输出直接作为委托结果 |
| `stock-agent` | 研究、诊断、证据、RAG、Memory 和受控决策增强 | 成为基础交易链路的强制前提 |
| `stock-job` | Quartz 注册、触发、运行记录和跨域编排 | 复制领域计算或持久化逻辑 |
| `stock-web` | React 页面、路由、交互状态和静态资源 | Java 业务实现或独立生产后端 |
| `stock-starter` | 启动类、MongoDB 配置和最终聚合 | 普通业务 Service、Entity、Repository |

## 代码放置

- Controller、Service、Entity、Repository 和 DTO 放在其业务所有者模块内。
- 调度入口放在 `stock-job`，被调度的业务方法仍保留在领域模块。
- 跨模块反向查询通过 `stock-base` 中的 Port 表达，由高层模块实现。
- `stock-starter` 只处理应用装配和启动期动作。
- 固定模型文件位于仓库根目录 `model-artifacts/`，不放入 Maven 源码目录。

## 包名与目录基线

后端包根必须与 Maven 模块一一对应：

| Maven 模块 | Java 包根 |
|---|---|
| `stock-base` | `com.stock.base` |
| `stock-data` | `com.stock.data` |
| `stock-model` | `com.stock.model` |
| `stock-strategy` | `com.stock.strategy` |
| `stock-trading` | `com.stock.trading` |
| `stock-agent` | `com.stock.agent` |
| `stock-job` | `com.stock.job` |
| `stock-starter` | `com.stock.starter` |

不保留 `dataCollector`、`modelService`、`strategyAgent`、`tradingExecutor` 等旧包名兼容层。模块内统一使用 `controller`、`service`、`repository`、`entity`、`dto`、`vo`、`config` 等职责目录，Java package 与物理路径必须一致。

## 防止循环依赖

1. 下游需要上游事实时，直接依赖上游公开 Service 或稳定 DTO。
2. 上游需要下游状态时，在 `stock-base` 定义最小只读 Port，由下游实现。
3. 跨域流程由 `stock-job` 或明确的应用服务编排，不把编排逻辑下沉到数据模块。
4. 禁止通过复制 Entity、反射访问或全局工具类规避依赖规则。
