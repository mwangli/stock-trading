# 部署与运行

## 部署形态

生产环境由六个 Compose 服务组成：

```text
stock-frontend:80
  |-- stock-backend:8080
  `-- stock-agent:8081

stock-backend --> stock-mysql + stock-mongo + stock-redis
stock-agent   --> stock-mongo + stock-redis
```

Backend 和 Agent 端口只绑定宿主机回环地址，外部请求统一从 Frontend Nginx 进入。Nginx 对 `/api/internal/**` 直接返回 404。

## 构建产物

| 模块 | 产物 | 容器 |
|---|---|---|
| `stock-backend` | `stock-backend-*.jar` | Java 17 JRE，端口 8080 |
| `stock-agent` | `stock-agent-*.jar` | Java 17 JRE，端口 8081 |
| `stock-frontend` | Vite `dist/` | Nginx，端口 80 |

Frontend 不复制到 Backend JAR。Backend 与 Agent 分别打包，各自 Dockerfile 只接收本模块产物。

## API 分流

| 路径 | 目标 |
|---|---|
| `/api/agent/**` | `stock-agent:8081` |
| `/api/internal/**` | 外部拒绝 |
| 其他 `/api/**` | `stock-backend:8080` |
| `/ws/**` | `stock-backend:8080` |
| 其他路径 | React SPA 静态资源 |

Vite 开发代理使用相同分流原则：Agent 指向本机 8081，其他 API 指向本机 8080。

## 配置与安全

- `.env` 提供三模块镜像、MySQL、MongoDB、Redis 和内部服务令牌配置。
- `INTERNAL_API_TOKEN` 必须使用高强度随机值，并同时注入 Backend 与 Agent。
- 数据库密码、Provider Key、券商凭据和签名密钥只能从运行环境注入。
- `TRADING_REAL_WRITE_ENABLED` 默认关闭；Agent 可用不代表允许真实交易。
- Backend 只加载 Sentiment 固定制品，Agent 只加载 Embedding 固定制品。

## 数据持久化

- MySQL 使用宿主机持久化目录保存常规业务与事务数据。
- MongoDB 使用宿主机持久化目录保存增量文档和 GridFS。
- Redis 使用 AOF 持久化，但其业务定位仍是可重建缓存和共享 Session。
- `model-artifacts` 以只读卷挂载，运行时不得覆盖固定模型。
- Backend 与 Agent 的临时文件分别进入独立命名卷。

## CI/CD

三个模块使用独立标签和工作流：

| 标签 | 工作流 | 部署服务 |
|---|---|---|
| `backend-vX.Y[.Z]` | `backend-ci-cd.yml` | `stock-backend` |
| `agent-vX.Y[.Z]` | `agent-ci-cd.yml` | `stock-agent` |
| `frontend-vX.Y[.Z]` | `frontend-ci-cd.yml` | `stock-frontend` |

部署脚本只重建目标服务，保留其他服务；失败时收集目标服务日志并回滚到原镜像。Backend 发布校验 Sentiment 制品，Agent 发布校验 Embedding 制品。

## 健康边界

容器健康只证明目标进程或 HTTP 入口可达，不代表数据库、模型、Provider、Quartz、券商或业务任务全部可用。发布后仍需分别核对目标镜像 SHA、容器健康、启动日志和真实业务终态。
