# 部署与运行

## 部署形态

生产形态是一个 `stock-application` 容器和一个 MongoDB 数据容器。前端由 Spring Boot JAR 托管，不部署独立前端容器或 Nginx。

```text
浏览器
  → stock-application:8080
      → MongoDB
      → /app/model-artifacts（只读）
```

## 构建产物关系

1. `stock-web` 使用 Vite 生成 `dist/`。
2. Maven 将前端资源复制到 `stock-web` JAR 的 `static/`。
3. `stock-starter` 聚合后端模块和 `stock-web`。
4. Spring Boot 插件生成唯一可执行 JAR。
5. Docker 镜像将该 JAR 复制为 `/app/app.jar`。

## 运行依赖

| 依赖 | 用途 |
|---|---|
| Java 17 | Spring Boot、DJL 和业务运行时 |
| MongoDB 8 | 业务数据、任务配置、行情、模型、预测、信号和向量文档 |
| `model-artifacts/` | Embedding 与 Sentiment 固定制品 |
| 外部证券接口 | 股票、行情、新闻和交易相关事实 |
| 可选 Agent Provider | DeepSeek 或本地 Ollama |

## 资源边界

Compose 按 2C4G 环境控制资源：应用 JVM、直接内存和 MongoDB 受限，Quartz 线程数和 Agent 并发保持较低。训练任务应避开交易关键窗口，并通过运行开关和调度配置控制。

## 配置边界

- 数据库密码、Agent API Key、券商账户和签名密钥只能从环境变量注入。
- `TRADING_REAL_WRITE_ENABLED` 默认关闭，模型和 Agent 可用不代表真实交易写入开启。
- `ZXBROKER_ENABLED` 控制券商适配能力，认证状态与真实写入开关分别判断。
- `SPRING_QUARTZ_AUTO_STARTUP` 控制定时任务调度器是否启动。
- 模型路径使用仓库相对路径或容器挂载路径，不写死开发机绝对路径。

## 网络和存储

- 应用服务对外暴露 HTTP 端口。
- MongoDB 仅绑定本机访问端口，并通过内部网络供应用连接。
- 数据库存储使用持久化目录，容器重建不得清空业务数据。
- `model-artifacts` 以只读卷挂载，运行时不得修改固定模型。
- 临时训练和运行文件进入 `.tmp` 或运行时临时卷，不纳入代码资产。

## Mongo-only 切换

- 本版本不再启动或连接 MySQL，也不会自动把旧 MySQL 行数据复制到 MongoDB。
- 切换前如需保留旧数据，应先完成独立备份；可从证券接口、券商事实或固定默认配置重建的数据无需继续保留 MySQL 运行依赖。
- 使用新 Compose 部署时通过 `--remove-orphans` 移除旧 `stock-mysql`、独立前端和旧后端容器；MongoDB 持久化目录保持不变。
- 删除旧 MySQL 数据目录属于不可逆运维操作，不由应用启动或 CI/CD 自动执行。

## 健康与恢复

容器健康检查只证明应用端口可连接，不等同于数据库、模型、Provider、Quartz 和券商全部可用。系统页面和接口应分别展示各能力状态。

应用重启后，`JobBootstrap` 先补齐 MongoDB `job_config` 缺失的固定任务，再重建 RAMJobStore 任务。模型预热服务负责固定模型的启动期检查和加载。Quartz 运行态不持久化，业务执行历史保存在 MongoDB。
