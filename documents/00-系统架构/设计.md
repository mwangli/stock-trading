# 系统架构设计

## 目标结构

```text
React 前端
    |
Java Spring Boot 在线后端
    | 数据采集 | 在线特征 | ONNX 推理 | 策略 | 风控 | 调度 | 券商 |
    |
MySQL + MongoDB

Python 离线模型端
    | 数据快照校验 | LSTM/情感训练 | 评估 | ONNX 导出 | 制品构建 |
    +---------------- 候选制品 ----------------> Java 校验、激活和回滚
```

## 三端分工

- 前端只展示和操作，不承载交易规则。
- Java 后端是在线业务控制面，统一处理采集、在线特征、ONNX 推理、策略、风控、调度和真实交易。
- Python 端只处理离线训练、评估和模型制品，不直接访问券商，不修改订单、持仓和生产模型指针。
- `docs/` 与三端平级，维护跨端契约和长期设计。
- MySQL 保存配置、任务和真实交易事实。
- MongoDB 保存历史行情、新闻和必要模型元数据。

## 部署分工

### 2C4G 云服务器

- 常驻 `stock-web`、`stock-backend`、`stock-mysql` 和 `stock-mongo`。
- Java 使用 ONNX Runtime 推理。
- 不运行正式 Python 训练。
- `stock-python` 仅在显式启用 `training` Profile 时启动。

### 本地 32GB 电脑

- 使用 `python/` 的 Python 3.14 环境或训练镜像。
- 执行 LSTM、情感模型训练、评估和 ONNX 制品构建。
- 同一时间只运行一个正式训练任务。

## 迁移状态

Java 训练代码和生产 PyTorch 依赖已删除，ONNX 是唯一在线模型推理路径。当前仍需使用真实快照完成 Python 训练、ONNX 制品部署、业务回放、2C4G 资源验证和回滚演练；验证完成前不能宣称生产迁移完成。

## 故障原则

- 数据失败：停止计算。
- 模型失败：停止生成候选。
- 风控失败：禁止委托。
- 券商失败：保留本地记录并等待重新对账。
- Python 训练失败：继续使用最近一个已发布模型，不影响在线交易。
- 页面失败：显示错误或空状态，不伪造数据。
