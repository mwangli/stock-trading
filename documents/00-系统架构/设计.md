# 系统架构设计

## 目标结构

```text
React 前端
    |
Java Spring Boot 在线后端
    | 数据采集 | DJL 训练 | PyTorch 推理 | 策略 | 风控 | 调度 | 券商 |
    |
MySQL + MongoDB
```

## 前后端分工

- 前端只展示和操作，不承载交易规则。
- Java 后端统一处理采集、在线特征、DJL 模型训练、PyTorch Engine 推理、策略、风控、调度和真实交易。
- `documents/` 与前后端平级，维护跨端契约和长期设计。
- MySQL 保存配置、任务和真实交易事实。
- MongoDB 保存历史行情、新闻、LSTM 参数、配置、指标、状态和激活指针。

## 部署分工

### 2C4G 云服务器

- 常驻 `stock-web`、`stock-backend`、`stock-mysql` 和 `stock-mongo`。
- Java 使用 DJL + PyTorch Engine 训练和推理。
- 正式训练默认关闭，通过统一调度任务和 `LSTM_TRAINING_ENABLED` 显式开启。

### 模型存储

- 小型 LSTM 参数直接保存到 MongoDB，版本文档不可覆盖。
- 当前激活版本和上一回滚版本保存在独立激活文档中。
- 情感 Transformer 权重保存在 `/models/sentiment` 版本化目录，MongoDB 只保存配置、状态、摘要和路径。

## 迁移状态

Python 和 ONNX Runtime 已移除，Java 已恢复 `StockLSTMModel`、多任务 Loss、离线训练任务和 DJL PyTorch 推理。当前仍需使用真实数据完成训练、业务回放、2C4G 资源验证和 MongoDB 回滚演练；验证完成前不能宣称生产迁移完成。

## 故障原则

- 数据失败：停止计算。
- 模型失败：停止生成候选。
- 风控失败：禁止委托。
- 券商失败：保留本地记录并等待重新对账。
- LSTM 训练失败：继续使用当前激活版本，不影响在线推理。
- 页面失败：显示错误或空状态，不伪造数据。
