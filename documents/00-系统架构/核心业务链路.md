# 核心业务链路

## 主链路

```text
市场数据采集
  → 数据质量与交易日确认
  → 模型训练或批量推理
  → 候选排名与策略信号
  → Agent 可选增强判断
  → Java 风控复核
  → 券商委托
  → 订单、成交、持仓与绩效回写
```

## 数据准备

`stock-data` 从证券接口获取股票列表、日线、分钟线、复权因子、可交易状态、新闻和交易日历。数据在持久化前完成解析、去重和覆盖范围判断。

日常增量同步只关注当前交易窗口；历史缺口由独立回补任务处理。单个股票无数据或历史缺口不能导致全部日常同步失效，但数据源整体为空、解析失败或关键范围无法确认时必须明确失败。

## 模型处理

`stock-model` 从经过质量检查的数据生成训练快照。训练产生候选模型版本，激活操作与训练操作分离。批量预测记录模型版本、交易日期、批次状态和单股票结果，为策略和 Agent 提供可追踪输入。

财经情感模型从新闻文本生成情感结果；LSTM 从历史序列和参考特征生成方向与收益相关预测。二者是决策输入，不直接产生委托。

## 确定性策略

`stock-strategy` 将预测、情感、技术指标、成交量和配置规则组合为排名、信号和候选集合。策略结果包含配置版本和有效窗口，过期或数据不完整的候选不得进入真实交易。

回测使用历史可交易股票池、历史行情和当时可获得的信息，避免将未来数据泄漏到历史决策。

## Agent 增强

`stock-agent` 可以读取脱敏后的行情、模型、策略、任务、账户和风险门禁摘要，生成研究结论、诊断结果或结构化交易判断。

Agent 默认不改变 Java 基线结果。只有显式启用受控模式后，Agent 才能对已经被 Java 基线允许的买入候选做单向收缩，即跳过或延迟，不能把被基线拒绝的候选提升为可交易项。

## 交易执行

`stock-trading` 在委托前重新读取最新账户、持仓、交易时间、交易日历、价格和运行开关，并执行权限、资金、仓位、T+1、停牌、涨跌停、幂等和批次隔离检查。

券商返回的订单、成交和持仓属于外部事实，需要同步并持久化。业务绩效由已实现交易记录聚合，不把预测值或浮动展示值当作已实现收益。

## 任务编排

`stock-job` 以固定 Quartz Job 串联上述能力。任务只负责确定触发时机、调用领域服务、记录结果和处理可中断状态，不复制领域实现。

## 失败与降级

| 故障 | 处理方式 |
|---|---|
| Agent Provider 超时或熔断 | 回退 Java 基线或进入人工复核，不扩大交易权限 |
| Embedding 不可用 | RAG/Memory 检索不可用，基础 Agent 或核心交易链路继续运行 |
| 情感模型不可用 | 停止依赖情感的增强评分，保留可解释的降级标记 |
| 历史行情存在缺口 | 日常增量继续，交由独立历史回补任务处理 |
| 券商会话失效 | 禁止真实写入，保留查询和诊断能力 |
| 交易日历未确认 | 禁止自动交易，不使用猜测日期替代 |
| 训练失败 | 保留当前激活模型，候选版本不得生效 |
