# 系统概览

## 系统定位

`stock-trading4` 是面向 A 股场景的模块化单体应用，将市场数据、模型预测、确定性策略、Agent 辅助分析、风险控制和券商执行组织为一条可审计业务链路。

系统采用一个 Spring Boot 进程和一个前端静态站点，由同一个可执行 JAR 提供服务。Maven 模块用于隔离代码职责，不代表独立微服务。

## 业务目标

- 自动维护股票、行情、新闻、交易日历和可交易状态等基础事实。
- 使用 LSTM 和财经情感模型生成预测、评分和候选依据。
- 使用确定性规则完成选股、信号生成、策略状态管理和回测。
- 允许 Agent 在受控范围内提供研究、诊断和交易建议。
- 在真实交易前统一执行权限、资金、持仓、交易时间和风险校验。
- 对任务、模型、策略、Agent 判断和交易执行保留可追踪记录。

## 架构形态

## 核心设计原则

### 事实与推断分离

行情、账户、持仓和交易日历属于事实数据；模型预测、情感判断和 Agent 输出属于推断结果。推断不能覆盖或伪造事实。

### 决策与执行分离

模型和 Agent 可以影响候选、评分或建议，但真实委托只能由 Java 交易执行链路在重新校验风险后提交。

### 增强能力可降级

Agent、RAG、Memory、情感模型和定时训练均属于可降级能力。它们不可用时，基础数据、确定性策略、人工查询、风险控制和手工交易仍应保持可用。

### 单体部署、模块治理

项目面向 2C4G 级别环境，避免注册中心、网关、消息中间件和跨服务调用的额外成本。模块边界通过 Maven 依赖、包职责和稳定契约维持。

## 数据存储

| 存储 | 主要用途 |
|---|---|
| MongoDB | 用户、配置、任务、交易事实、行情、新闻、模型、策略、Agent 和向量文档 |
| `model-artifacts/` | 固定 Embedding 和 Sentiment 模型制品，只读加载 |
| MongoDB GridFS | LSTM 候选、激活、历史版本及回滚所需模型二进制 |

## 非目标

- 不建设独立微服务集群。
- 不让 Agent 直接持有券商凭据或绕过风控下单。
- 不把模型训练成功等同于生产模型自动生效。
- 不把模型预测、回测收益或 Agent 建议表述为确定投资收益。
