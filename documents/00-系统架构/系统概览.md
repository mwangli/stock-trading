# 系统概览

## 系统定位

`stock-trading4` 是面向 A 股场景的数据、模型、策略、Agent 辅助决策、风险控制和券商执行平台。

项目只保留三个 Maven 模块：`stock-backend`、`stock-agent`、`stock-frontend`。Backend 保留业务事实、确定性策略、硬风险和券商执行权；Agent 是可独立发布、可降级的增强服务；Frontend 独立构建并通过 Nginx 访问两个后端服务。

## 运行架构

```text
浏览器
  |
stock-frontend:80 (Nginx)
  |-- /api/agent/** ----------> stock-agent:8081
  |-- /api/** ----------------> stock-backend:8080
  `-- /ws/** -----------------> stock-backend:8080

stock-agent --内部事实 API--> stock-backend
stock-backend --交易门禁 API--> stock-agent

stock-backend --> MySQL + MongoDB + Redis
stock-agent   --> MongoDB + Redis
```

`/api/internal/**` 不对浏览器开放。Backend 与 Agent 的内部调用统一携带 `X-Internal-Token`，两者不共享 Java 实现或 Maven 依赖。

## 业务目标

- 自动维护股票、行情、新闻、交易日历和可交易状态等基础事实。
- 使用 LSTM 和财经情感模型生成预测、评分和候选依据。
- 使用确定性规则完成选股、信号生成、策略状态管理和回测。
- 允许 Agent 在受控范围内提供研究、诊断、交易计划和风险收缩判断。
- 在真实交易前统一执行权限、资金、持仓、交易时间和风险校验。
- 对任务、模型、策略、Agent 判断和交易执行保留可追踪记录。

## 三模块职责

| Maven 模块 | 职责 | 运行形态 |
|---|---|---|
| `stock-backend` | 数据、模型、策略、交易、Quartz、内部事实 API 和唯一交易执行边界 | Spring Boot，默认端口 8080 |
| `stock-agent` | LangChain4j、RAG、Memory、研究诊断、交易计划和受控交易判断 | Spring Boot，默认端口 8081 |
| `stock-frontend` | React 页面、交互状态和 Nginx API 分流 | 静态站点容器，端口 80 |

## 数据存储

| 存储 | 权威用途 |
|---|---|
| MySQL | 用户、配置、任务、模型元数据、交易状态及需要事务或锁约束的常规业务数据 |
| MongoDB | 行情、新闻、预测明细、回测、账户快照、Agent 会话/RAG 等增量、时序和大文档数据 |
| MongoDB GridFS | LSTM 参数和训练快照等大体积二进制制品 |
| Redis | 可重建查询缓存与 Backend/Agent 共享 Session，不保存不可丢失业务事实 |
| `model-artifacts/` | 固定 Embedding 和 Sentiment 模型制品，只读加载 |

## 核心原则

- 行情、账户、持仓和交易日历是事实；模型和 Agent 输出是推断，不能覆盖事实。
- 真实委托只能由 Backend 在重新校验当前事实、权限和风险后提交。
- Agent、RAG、Provider 或 Redis 缓存不可用时，不得扩大交易权限。
- 同一能力只保留一个当前入口，不保留旧模块、旧 URL 或兼容转发层。

## 非目标

- 不把 Backend 内部领域重新拆成多个 Maven 模块或微服务。
- 不让 Agent 直接持有券商凭据或调用券商写接口。
- 不把 Redis 当作权威数据库。
- 不把模型训练成功等同于生产模型自动生效。
