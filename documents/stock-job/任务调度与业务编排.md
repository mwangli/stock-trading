# 任务调度与业务编排

## 领域定位

`com.stock.job` 是 `stock-backend` 内部的统一后台任务领域，负责固定任务目录、Quartz 注册、Cron 触发、手工触发、暂停恢复、中断和执行记录，不是独立 Maven 模块。

## 实现与存储

`JobSchedulerService` 维护任务名称到 Quartz Job 类的明确映射。MySQL `job_config` 保存任务名称、Cron 和启用状态，`job_execution_record` 保存业务执行历史；Quartz 使用 RAMJobStore。

应用启动后，`JobBootstrap` 幂等补齐 MySQL 缺失的固定任务配置，再读取 MySQL 配置重建内存任务。已有任务的 Cron 和启停状态不被默认值覆盖。

## 固定任务

| 任务 | 业务用途 |
|---|---|
| `stockListSync` | 同步股票基础资料和生命周期信息 |
| `dailyStockDataSync` | 同步最近交易日日线数据 |
| `stockPriceHistoryBackfill` | 独立修复历史行情缺口 |
| `newsDailySync` | 采集和整理财经新闻 |
| `tradeCalendarMonthlySync` | 维护交易日历覆盖 |
| `lstmOfflineTraining` | 执行受控离线 LSTM 训练 |
| `dailyModelPrediction` | 生成每日模型预测批次 |
| `stockSelection` | 生成策略排名和候选 |
| `realTradingAutoBuy` | 对合格候选执行 Java 风控和自动买入检查 |
| `realTradingT1Exit` | 执行符合条件的 T+1 退出流程 |
| `broker-current-facts-sync` | 同步券商账户、持仓、订单和成交事实 |

Agent 不在 Backend Quartz 中维护独立任务目录。Agent 交易建议由 Agent 服务独立生成，不进入 Backend 交易任务。

## 调度边界

- Quartz Job 只调用领域 Service，不复制业务算法。
- 业务类禁止新增 `@Scheduled`。
- 任务名称必须在固定目录和 MySQL 配置中一致。
- 任务从目录移除时可清理调度定义，但保留历史执行记录。
- Misfire 使用不补跑策略，避免恢复时集中执行过期任务。
- 历史回补、训练和评估避免与交易关键窗口争抢资源。
