# 03-策略分析需求

## 模块定位

策略分析把模型输出和市场事实转换为可审计的候选与交易信号。它不保存券商凭据，不调用券商写接口，不决定最终是否允许委托。

## 输入契约

| 输入 | 来源 | 最低要求 |
|---|---|---|
| 下一交易日预测 | `modelService` | 绑定模型版本、基准交易日和目标交易日 |
| 新闻与公告情感 | `dataCollector`、`modelService` | 标明信息截止时间；缺失时不能伪造中性结果 |
| 日线、分钟线、交易日历 | `dataCollector` | 能判断交易日、停牌和可成交状态 |
| 账户和持仓快照 | `tradingExecutor` | 标明快照时间；过期快照不能用于下单候选 |
| 策略配置与运行模式 | 本模块 | 版本化、可追溯、禁止运行中无审计修改 |

## 输出契约

每个候选必须包含：股票代码、基准交易日、目标交易日、模型版本、预测分数、情感分数、综合分数、排名、建议数量、价格区间、失效原因、生成时间和数据截止时间。输出是候选事实，不是委托指令。

## 业务规则

- T 日收盘后只生成面向下一个有效交易日的候选。
- T+1 开盘后必须重新读取分钟行情、交易日历和账户快照，不能直接使用收盘候选下单。
- 当日买入的持仓不得当日卖出；退出规则由交易执行模块在可卖数量和券商状态基础上再次校验。
- 排名使用确定性排序：综合分数相同必须使用稳定的次级排序键，保证重复运行结果可比较。
- 行情、模型、情感或交易日历关键数据不完整时，候选状态为 `REJECTED` 或 `INCOMPLETE`，不能以 0 分掩盖失败。
- 回测必须使用当时可见数据、下一根可成交价格、费用、滑点、涨跌停和停牌约束，禁止读取未来数据。

## 非本期范围

- 不在策略模块实现资金冻结、委托提交、订单轮询或券商重试。
- 不建设通用规则编排器、自动超参数优化器和多策略在线市场。
- 不把回测收益直接视为真实交易收益，必须区分回测、候选和成交事实。

## 验收标准

| 验收 ID | 标准 |
|---|---|
| STRATEGY-AC-001 | 输入均带有来源、数据截止时间和交易日口径，缺失时产生明确失败状态。 |
| STRATEGY-AC-002 | 相同输入重复运行产生相同排名和稳定次序。 |
| STRATEGY-AC-003 | 候选包含模型版本、综合分数、建议数量和失效条件，且不包含券商写参数。 |
| STRATEGY-AC-004 | 回测不使用未来数据，并计入费用、滑点、停牌、涨跌停和 T+1 约束。 |
| STRATEGY-AC-005 | 策略模块不能绕过 `tradingExecutor` 直接产生券商写调用。 |
