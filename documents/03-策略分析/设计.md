# 03-策略分析设计

## 组件边界

```text
modelService 预测批次 + dataCollector 行情/新闻
             -> StrategyScheduler / StockSelector
             -> ScoreCalculator / DecisionAggregator
             -> 可成交性过滤 + 策略状态
             -> TradingSignal / StockRanking
             -> tradingExecutor 重新读取并执行门禁
```

- `StockSelector` 负责股票池和候选筛选。
- `ScoreCalculator` 负责模型、情感和行情特征的归一化与加权。
- `DecisionAggregator` 负责合并信号、稳定排序和失效原因。
- `BacktestEngine` 只读历史数据，输出回测运行和交易明细，不复用真实订单实体。
- `StrategyStateManager` 维护策略模式和切换审计；策略状态不是交易执行状态。

## 数据与状态

候选、排名、信号和回测记录写入现有持久化层；计算过程中的临时集合只保存在方法作用域或单实例内存。禁止用缓存中的候选直接代表当前可下单状态，交易执行前必须重新读取账户、行情、交易日历和风险状态。

建议状态：

```text
GENERATED -> ELIGIBLE -> EXPIRED
          \-> REJECTED
```

状态转换必须记录模型版本、行情基准日、目标交易日、操作者/任务来源和原因。已过期候选不得通过更新字段重新变成可执行候选。

## 调度与接口

策略任务由 `tradingExecutor.job` 中的固定 Quartz Job 触发，策略模块只暴露无参业务 Job 方法和查询服务，不在业务类使用 `@Scheduled`。对外接口使用明确 DTO 和 `ResponseDTO<T>`，不暴露 Entity 或 `Map`。

## 回测设计

- 回测运行保存策略版本、数据范围、模型版本、费用参数、滑点参数和运行时间。
- 每个交易日只读取当日及之前已存在的事实数据，下一交易日成交价使用下一根可成交行情。
- 回测成交、持仓和收益只写回测实体；真实账户数据由 `tradingExecutor` 独立维护。
- 缺行情、停牌、涨跌停和数据校验失败必须形成可统计的跳过原因，不静默丢弃。

## 失败与降级

- 单只股票输入不完整：该股票标记为不可用并保留原因。
- 全市场预测批次不可用：本次选股失败，不生成可执行候选。
- 情感结果缺失：按业务配置拒绝该股票或拒绝整批，不能默认补零。
- 券商状态不可用：由交易执行模块拒绝委托，策略模块不模拟成功。

## 可简化设计

- 先保留单一综合评分公式和一个策略模式，不引入规则 DSL。
- 先保留单实例内存计算，不引入 Redis；需要恢复的数据写入现有 MySQL/MongoDB。
- 回测先支持日线和固定费用参数，分钟级撮合只在真实需求明确后扩展。
