# 四模块总体架构设计

## 逻辑结构

```text
React 前端
    -> 数据采集 API
    -> 模型服务 API
    -> 策略分析 API
    -> 交易执行 API

Java Spring Boot 单体
    dataCollector -> modelService -> strategyAnalysis -> tradingExecutor -> 券商
                                              tradingExecutor.access/runtime/job

MySQL：用户、运行配置、任务、策略和交易事实
MongoDB：行情、新闻、训练快照、模型版本和预测结果
```

## 目标包结构

后端只保留四个顶层业务包：`dataCollector`、`modelService`、`strategyAnalysis`、`tradingExecutor`。现有 `systemConfig` 迁移到 `tradingExecutor.runtime`，现有 `user` 迁移到 `tradingExecutor.access`。

## 依赖方向

允许数据采集被模型和策略读取，允许模型结果被策略读取，允许策略候选被交易执行读取。禁止反向调用和环状依赖；交易执行需要市场事实时通过数据采集查询接口读取，不直接修改其持久化对象。

## 统一约束

- 所有后台任务由 `tradingExecutor.job` 的固定 Quartz Job 管理。
- 所有接口使用 DTO 和 `ResponseDTO<T>`。
- 认证只解决访问身份，运行配置只解决节点开关，风控和真实写入门禁仍由交易执行独立判断。
- 失败按模块关闭：数据失败停止计算，模型失败停止候选，策略失败停止执行，风控或券商失败禁止委托。
