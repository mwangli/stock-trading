# 支撑能力

## 模块定位

Agent 支撑能力只保存多个职责共同需要、语义稳定且不属于特定业务域的基础设施，不应演变为业务类、DTO 和工具代码的集中堆放区。

## 目录结构与职责

```text
support    # Session 用户解析、基础异常和异常响应转换
config     # Agent 通用配置与装配
stock-base/com.stock.base.web.ResponseDTO
           # 跨模块统一 HTTP 响应
```

## 允许内容

- `ResponseDTO<T>` 等跨模块协议外壳统一归属 `stock-base`。
- 当前用户上下文和共享 Session 属性。
- 不属于特定能力的 Agent 通用配置类型。
- 通用错误码、基础异常和全局异常响应转换。

## 禁止内容

- 业务请求、响应 DTO 或领域枚举。
- MongoDB Entity、Repository 和业务 Service。
- Prompt、Agent 路由、工具定义和 Provider 实现。
- Backend Wire DTO 或业务模块实现类。
- 仅被单一职责使用的所谓公共类。

## 依赖规则

`support` 和 `config` 不得反向依赖 Controller、业务 Service、Tool 或 Repository。其他职责可以单向依赖支撑能力，但业务语义必须留在对应职责类型中。

## 认证边界

Agent 与 Backend 位于同一个 Spring Boot 进程，共享 Servlet 内存 Session。登录仍由 Execution 模块提供，Agent 只解析已有身份，不复制账号、密码或登录逻辑。

Agent Controller 与其他业务 Controller 使用同一登录身份边界；模块间 Java 调用不使用 HTTP Header 传递身份。

## 扩展约束

向 `support` 或 `config` 增加类型前必须确认存在真实复用、语义一致且不会形成反向依赖。无法满足时，应将类型保留在原职责包中。

## 重点能力详细设计

### Web 访问控制

`AccessWebConfig` 在 Execution 模块统一注册访问规则：

| 路径 | 拦截器 | 身份来源 |
|---|---|---|
| 其他 `/api/**` | `AuthInterceptor` | Servlet 内存 HTTP Session |
| `/api/agent/runtime/health` | 无登录拦截 | 用于基础健康探测 |

### 用户身份解析

`AuthInterceptor` 要求 Session 同时存在：

- `AUTH_USER_ID`，类型为 `Long`。
- `AUTH_USERNAME`，类型为 `String`。

缺失时直接返回 HTTP 401 和 `ResponseDTO.error("请先登录")`。`AgentRequestUserResolver` 从相同 Session 构造 `userScope`，业务 Controller 只传递该服务端值，不能从请求 DTO 接受用户 ID。

当前部署为单实例内存 Session，进程重启后用户需要重新登录。扩展为多实例前必须引入明确的粘性会话或外部 Session 方案，不能假设内存会话跨实例共享。

### 内部令牌

模块间事实调用通过公开 Service 完成，不再存在内部 Token 或内部 HTTP 鉴权。用户范围仍由 Servlet Session 和具体用例校验。

### 统一响应与异常

`ResponseDTO<T>` 提供 `success(data)` 和 `error(message)` 两种外层契约。Controller 统一返回该类型，不使用裸 DTO 或 Map。

`FactSourceUnavailableException` 使用稳定错误码 `FACT_SOURCE_UNAVAILABLE`。`AgentExceptionHandler` 将其转换为 HTTP 503，避免前端把事实源错误当作空列表或正常降级。日志只记录错误码和异常类型，不输出内部 Token 或完整响应体。

### 配置模型

`AgentProperties` 集中承载真正跨能力的运行参数：

| 配置组 | 关键参数 |
|---|---|
| Core | `enabled`、`provider`、`timeoutMs`、`maxOutputChars`、`maxConcurrency` |
| Provider | DeepSeek/Ollama 的 enabled、baseUrl、model、maxTokens |
| Budget | 每日上限、输入/输出峰值单价、安全系数、预留 Token |
| Circuit Breaker | 开关、失败阈值、打开时间 |
| Capabilities | report、tradePlan、RAG、Memory 开关 |
| Memory/Tool | TTL、Chat Memory 条数、工具超时、审计开关 |
| Embedding | Provider、制品路径、版本、维度、Pooling、归一化、Fallback |

配置类只表达运行参数，不执行 Provider 调用、业务查询或状态机。

### shared 准入判断

新增类进入本包前必须同时满足：

1. 被至少两个独立业务包使用。
2. 不包含某一业务域的状态和规则。
3. 不需要反向依赖任何业务包。
4. 生命周期与 Agent 应用一致，而非某项能力独占。
5. 放入后不会促使其他模块绕过模块公开 Service。

不满足这些条件的 DTO、异常、配置和工具支持应留在所属业务包。
