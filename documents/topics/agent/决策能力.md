# 决策能力

## 模块定位

Agent 决策能力负责生成、保存和评估独立交易建议。它将 Backend 提供的冻结事实上下文转换为结构化建议，但不修改候选集合、订单、持仓、风控参数或券商状态。

## 业务职责

- 根据不可变 `TradeDecisionContext` 生成买入、持有、跳过或弃权建议。
- 保存建议、置信度、理由、风险提示、模型和事实版本。
- 在后续事实到达后执行反事实评估，统计建议质量和 Provider 表现。
- 对结构化模型输出执行解析、字段完整性和业务约束校验。
- 提供建议、批次、评估摘要和 Provider 指标查询。

## 职责分布

```text
controller / dto      # 建议生成、查询和评估接口契约
service / validator  # 上下文、建议、评估编排及业务约束
service / model      # 权威事实查询服务和内部事实模型
output / vo / enums  # 结构化输出、领域值对象和状态
entity / repository  # MongoDB 持久化文档和存储
```

## 核心流程

```text
生成请求
  → TradeDecisionFactService 获取冻结事实
  → TradeDecisionContextService 保存上下文
  → AgentTradeDecisionService 调用 Runtime Provider
  → TradeDecisionStructuredOutputHandler 解析
  → AgentTradeDecisionValidator 校验
  → 建议独立持久化并返回
```

评估流程使用建议生成后的真实事实，不允许用未来数据改写原始上下文。上下文至少应保留候选批次、策略版本、价格截止时间、预测、情感、新闻摘要、交易日和数据质量标记。

## 依赖边界

- 依赖 `TradeDecisionFactService`，由该服务调用 `stock-platform` 的权威事实聚合 Service。
- 通过 `AgentRuntimeCoordinator` 完成受控模型调用和结构化输出处理。
- 可复用 `support`、`config` 和 `stock-base` 的基础能力。
- 仅在查询 Service 边界依赖 Platform DTO，不直接访问 Backend Repository、Entity 或券商适配器。
- 不被 Backend 自动交易链反向依赖。

## 失败与安全边界

权威上下文不可用时返回 `FACT_SOURCE_UNAVAILABLE`，不得让模型猜测行情、持仓或候选。Provider 失败、预算不足、输出解析失败或校验失败时保存明确状态，不将自由文本当作有效建议。真实交易仍由 Backend 重新取数并执行权限、风控、幂等和券商写入。

## 扩展约束

新增建议字段时应同时更新 DTO、结构化输出、校验器、Entity 和评估逻辑。新增事实必须先扩展 `TradeDecisionFactService` 的查询语义，并在该服务中映射 Platform 领域事实，禁止在 Service 中直接拼接 Backend HTTP 请求。

## 重点能力详细设计

### 不可变决策上下文

`TradeDecisionContextService` 通过 `TradeDecisionFactService.tradeDecisionContexts` 请求 Platform 构建上下文。Agent 不自行拼接权威行情和账户数据。上下文保存后生成 `contextHash`，用于绑定候选、策略、价格截止时间、证据和数据质量状态。

核心约束：

- `contextId`、`contextHash`、`candidateBatchId` 和 `stockCode` 是建议身份，模型必须原样返回。
- `expiresAt` 是建议有效期上限，模型不能自行延长。
- `evidenceRefs` 是唯一允许引用的证据集合。
- 事后评估读取保存的上下文，不使用新数据改写原始输入。

### 建议生成与幂等

`AgentTradeDecisionService` 按候选批次加 `trade-decision-batch:{candidateBatchId}` 串行锁，并逐个处理上下文。相同 `contextHash + promptVersion` 已存在建议时直接返回，避免同一事实版本重复调用模型。

模型调用固定使用：

- `outputType=TRADE_DECISION`。
- `allowedTools=空集合`，禁止生成阶段再次查询并改变事实截面。
- 系统用户范围 `system:trade-decision`。
- Prompt 版本 `trade-decision-v1`，用于区分规则变更后的结果。

建议枚举为 `BUY`、`HOLD`、`SKIP`、`ABSTAIN`；状态为 `VALID`、`ABSTAINED`、`INVALID`、`EXPIRED`。当前生成规则要求 `ABSTAIN` 对应 `ABSTAINED`，其他建议对应 `VALID`。

### 结构化校验

`AgentTradeDecisionValidator` 在持久化前执行以下硬校验：

| 校验项 | 规则 |
|---|---|
| 上下文身份 | 四个身份字段必须与服务端上下文一致 |
| 建议与状态 | `ABSTAIN`/`ABSTAINED` 成对，其他建议必须 `VALID` |
| 优先级 | `suggestedPriority` 为 0 至 100 |
| 仓位区间 | `0 <= allocationMin <= allocationMax <= 1` |
| 有效期 | 晚于当前时间且不超过上下文 `expiresAt` |
| 原因码 | 非空，每项最长 64 字符 |
| 证据引用 | 只能引用上下文证据，汇总证据必须覆盖支持证据和反证 |
| 置信等级 | 只能使用 `LOW`、`MEDIUM`、`HIGH` |

Provider 超时、结构化解析失败或校验失败时，不生成猜测结果，而是落库显式 `ABSTAIN`：优先级和仓位归零、置信度为 `LOW`、风险标记为 `AGENT_UNAVAILABLE`，原因码区分超时和非法输出。

### 反事实评估

`TradeDecisionEvaluationService.evaluatePending` 单批处理 1 至 500 条，优先重试 `WAITING_MARKET_DATA`，再补充未评估建议。评估事实由 Backend 批量返回，Agent 使用冻结基准收盘价与目标交易日 OHLC 计算：

- 收盘收益率 `closeReturnRate`。
- 最大有利变动 `maxFavorableRate`。
- 最大不利变动 `maxAdverseRate`。
- 跳过上涨产生的机会成本 `skipOpportunityCostRate`。
- 跳过下跌获得的风险规避收益 `riskAvoidanceBenefitRate`。

市场数据状态包括 `EVALUATED`、`WAITING_MARKET_DATA`、`CONTEXT_UNAVAILABLE`。反事实结果区分基线拒绝、Agent 避免买入、Agent 与买入一致和 Agent 弃权。评估不修改真实交易记录，执行批次信息仅作为关联事实保存。

### Provider 质量统计

统计按 `provider + model` 聚合总数、有效数、弃权数、超时数、非法输出数、不可用数和证据缺口数，并计算结构化有效率与弃权率。这些指标用于评估模型稳定性，不用于自动放宽校验规则。

## 存储与接口

| MongoDB 集合 | 内容 |
|---|---|
| `trade_decision_context` | 冻结的决策上下文 |
| `agent_trade_suggestion` | Agent 建议、Prompt 版本和模型信息 |
| `trade_decision_evaluation` | 反事实行情指标和执行批次摘要 |

| API | 用途 |
|---|---|
| `POST /api/agent/tradeDecisions/generate` | 按候选批次生成建议 |
| `GET /api/agent/tradeDecisions/batches/{candidateBatchId}` | 查询批次建议 |
| `GET /api/agent/tradeDecisions/evaluations` | 查询评估结果 |
| `GET /api/agent/tradeDecisions/providerStatistics` | 查询 Provider 质量指标 |

## 设计变更检查

修改 Prompt 或校验规则时必须更新 `PROMPT_VERSION`，避免新旧语义共用幂等结果。新增推荐类型、证据字段或评估指标时，应同步修改结构化 DTO、Validator、Entity、Response、Mongo 查询和统计逻辑。
