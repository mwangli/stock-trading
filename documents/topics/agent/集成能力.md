# 集成边界

## 模块定位

Agent 与 Backend 运行在同一个 Spring Boot 进程。模块依赖固定为 `stock-platform → stock-agent → stock-application`：Platform 负责跨领域只读事实聚合，Agent 直接依赖 Platform 公开 Service，并将 Platform DTO 转换为 Agent 内部事实模型。Application 只负责最终装配，不承载事实适配逻辑。

## 调用流程

```text
Agent Tool / Decision Service
  -> AgentFactQueryService / TradeDecisionFactService
  -> stock-platform 公开聚合 Service
  -> Backend 领域 Service
  -> Platform DTO
  -> Agent 内部事实模型
```

## 设计收益

- 删除同 JVM 内部 HTTP、URL、Token、JSON Wire DTO 和重复序列化成本。
- 删除单实现中间接口和本地适配层，依赖关系由 Maven 模块顺序直接表达。
- Agent 不依赖 Data、Model、Strategy、Trading 的 Repository 或 Entity。
- Platform 及下层领域模块不反向依赖 Agent，Application 只完成最终组合装配。

## 数据边界

- Agent 自有 Session、Task、Memory、RAG、建议和审计集合可通过自身 Repository 使用 MongoDB。
- Backend 行情、模型、账户、交易和任务事实由 Platform 聚合 Service 统一提供。
- Platform 聚合 Service 只能调用已有领域 Service，不得绕过权限、风控、幂等或交易执行边界。
- Agent 转换 Service 不直接访问 Backend Repository、Entity、SQL、Mongo 查询或券商实现。
- 事实查询失败时明确返回不可用，不使用 Mock、空对象或模型猜测替代。

## 扩展步骤

1. 确认新增事实属于哪个现有领域模块，并由该模块公开明确 Service 和 DTO。
2. 在 `stock-platform` 对跨领域事实进行只读聚合，不复制业务算法。
3. 在 `stock-agent` 的具体查询 Service 中转换为 Agent 内部事实模型。
4. 静态检查依赖方向仍为 `base → data → model → strategy → trading → platform → agent → application`。
5. 禁止为单实现的同 JVM 调用重新增加中间接口、适配层或兼容模块。
