# stock-model 领域说明

## 领域定位

`com.stock.model` 是 `stock-backend` 内部的模型领域，负责训练数据快照、LSTM 训练与推理、财经情感推理、模型版本、预测批次和效果评估，不是独立 Maven 模块。模型输出是可追踪推断，不是最终交易指令。

## 核心能力

| 能力 | 说明 |
|---|---|
| 训练快照 | 固化股票范围、日期范围、特征、文件和摘要信息 |
| LSTM 训练 | 使用 DJL API 与 PyTorch Engine 训练共享时序模型 |
| LSTM 推理 | 使用激活模型对合格股票生成结构化预测 |
| 情感推理 | 加载 Backend 的固定财经模型，对文本分类 |
| 模型版本 | 管理候选、激活、上一版本和回滚关系 |
| 预测批次 | 记录模型版本、交易日、批次状态和明细结果 |
| 评估分析 | 评估历史预测、方向、收益和数据覆盖 |

## 实现方式

训练快照、训练运行、模型元数据、激活指针、预测批次和操作审计等常规状态保存在 MySQL。单股票预测明细等增量结果保存在 MongoDB；LSTM 参数和训练快照文件保存在 MongoDB GridFS。Sentiment 固定制品从 `model-artifacts/sentiment` 只读加载。

`TrainingDatasetSnapshotService` 管理快照状态，`TrainingSnapshotArtifactStore` 管理 GridFS 制品；训练、查询、激活和审计由独立 Service 负责。预测规划、执行队列、评估队列、业务评估和无状态指标计算分离，避免 Controller 或 Quartz 入口直接操作仓储。

## 运行边界

- 训练成功只产生候选版本，不自动替换激活模型。
- 推理必须记录实际模型版本，数据质量不足时明确拒绝。
- Redis 只缓存当前激活模型元数据，可随时从 MySQL 重建。
- Agent 通过 Backend 内部 API 获取模型摘要和预测候选，不依赖模型领域 Java 类。
- 模型指标用于辅助判断，不构成收益保证，也不直接提交券商委托。
