# stock-model 模块说明

## 模块定位

`stock-model` 负责训练数据快照、LSTM 训练与推理、财经情感推理、模型制品、预测批次和效果评估。模块输出可追踪的模型结果，但不决定真实交易。

## 业务用途

- 从市场数据构建可复现的训练输入。
- 训练并管理全市场共享 LSTM 模型。
- 使用固定财经情感模型分析新闻文本。
- 为每个交易日生成候选预测批次。
- 对预测结果进行覆盖率、方向准确性和成本相关评估。
- 提供模型运维页面需要的状态和审计信息。

## 核心能力

| 能力 | 说明 |
|---|---|
| 训练快照 | 固化股票范围、日期范围、特征和文件校验信息 |
| LSTM 训练 | 使用 DJL API 与 PyTorch Engine 训练共享时序模型 |
| LSTM 推理 | 使用激活模型对合格股票生成结构化预测 |
| 情感推理 | 加载本地财经模型，对单条或批量文本分类 |
| 模型版本 | 区分候选、激活、上一版本和回滚关系 |
| 预测批次 | 记录模型版本、交易日、批次状态和明细结果 |
| 评估分析 | 对历史预测、方向、收益和数据覆盖进行分析 |

## 实现方式

模型训练与推理统一使用 Java 17、DJL 和 PyTorch Engine。`TrainingDatasetSnapshotService` 负责训练快照构建和状态流转，`TrainingSnapshotArtifactStore` 负责快照制品的 GridFS 保存与读取；`ModelOperationsService` 负责编排训练操作，查询、模型激活和操作审计分别由 `ModelOperationsQueryService`、`ModelActivationService` 和 `ModelOperationAuditService` 承担，避免查询或审计逻辑隐式改变生产模型。

预测链路按执行阶段拆分：`ModelPredictionAnalysisService` 负责批次规划、缺口扫描和历史重算，`PredictionExecutionQueueService` 与 `PredictionEvaluationQueueService` 分别管理预测和评估队列，`ModelPredictionQueryService` 提供查询，`PredictionEvaluationService` 负责业务评估，`PredictionMetricsCalculator` 只执行无状态指标计算。

MongoDB 保存训练运行、数据快照、模型元数据、激活指针、预测批次和预测明细。固定模型制品从仓库根目录只读加载，LSTM 参数通过 GridFS 保存，不再使用文档内嵌参数或本地快照兼容路径。

## 依赖关系

- 依赖 `stock-base` 和 `stock-data`。
- 被 `stock-strategy`、`stock-trading`、`stock-agent`、`stock-job` 和 `stock-starter` 使用。
- 不调用券商，不直接生成订单。

## 运行边界

- 训练成功只产生候选版本，不自动替换激活模型。
- 推理必须记录实际使用的模型版本。
- 数据质量不满足门槛时应拒绝训练或预测，而不是以默认值掩盖。
- 模型不可用时，下游应获得明确降级状态。
- 模型指标用于辅助判断，不构成收益保证。
