# 风控与交易执行

## 执行原则

任何自动或人工发起的真实交易请求，都必须在提交券商前使用最新事实重新校验。上游候选、模型预测、Agent 建议和历史缓存不能替代执行时检查。

## 买入链路

```text
候选或交易计划
  → 用户与运行开关检查
  → 交易日和交易时间检查
  → 最新价格与可交易状态检查
  → 账户资金和仓位检查
  → 幂等与批次检查
  → 费用和数量计算
  → 券商委托
  → 订单回查与持久化
```

## 卖出链路

卖出信号进入执行层后，需要确认真实持仓、T+1 可卖数量、委托重复性、当前价格和券商会话。策略给出的目标数量必须被实际可卖数量约束。

## 主要风险门禁

- 当前日期必须是已确认交易日。
- 当前时间必须位于允许的交易窗口。
- 真实写入和券商能力必须同时启用。
- 券商会话有效，账户和资金事实可读取。
- 股票未停牌，价格未处于禁止委托状态。
- 买入金额、单股仓位和总风险暴露不超过配置。
- 卖出数量不超过 T+1 可卖数量。
- 相同业务批次和候选不重复执行。
- Agent 不得扩大 Java 基线允许范围。

## 幂等与批次

自动交易以业务批次记录执行范围、状态和结果。重试前先查询已有批次、订单和券商事实，避免网络超时后重复下单。

券商返回不确定时，优先回查订单状态，而不是立即再次提交。订单提交成功、券商受理、部分成交、全部成交和拒绝应使用不同状态表达。

## 费用与数量

委托数量按市场交易单位、可用资金、预估费用和价格计算。绩效统计使用实际成交和真实费用；预测收益和页面估算不写入已实现收益。

## Agent 交易计划

Agent 可以生成结构化交易计划草案并记录人工审批结果，但当前不提供从计划到真实委托的自动执行入口。真实交易必须由交易模块的既有入口显式发起，并重新经过用户范围、运行门禁、Java 风控和券商事实校验。

## 失败处理

- 风控拒绝：不调用券商，并记录明确拒绝原因。
- 券商调用失败：记录请求上下文和脱敏错误，允许受控回查。
- 状态不确定：进入待确认状态，不自动重复提交。
- 上游能力不可用：按配置降级到 Java 基线或停止自动交易。
