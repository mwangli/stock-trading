# stock-trading 领域说明

## 领域定位

`com.stock.trading` 是 `stock-backend` 内部的真实交易安全边界，负责用户认证、运行开关、账户和持仓事实、订单、风险校验、券商适配、同步和绩效聚合，不是独立 Maven 模块。

## 核心能力

| 能力 | 说明 |
|---|---|
| 认证与权限 | 系统登录、Redis Session、接口拦截和用户范围控制 |
| 运行配置 | 真实交易、调度和关键能力开关 |
| 风险控制 | 资金、仓位、T+1、时间、价格和幂等检查 |
| 券商适配 | 封装登录、查询、委托、撤单和验证码处理 |
| 事实同步 | 同步账户、持仓、订单和成交，并记录批次 |
| 交易记录 | 将订单与成交聚合为可解释的买卖记录 |
| 绩效统计 | 计算已实现收益、胜率和区间表现 |

## 实现与存储

用户、偏好、运行配置、券商订单、同步批次、自动交易批次和交易记录等常规状态保存在 MySQL。账户与持仓快照等持续追加事实保存在 MongoDB。Redis 保存共享登录 Session 和可重建运行配置缓存。

每笔委托独立记录，券商事实优先。WebSocket 日志用于运维观察，但不能替代订单、成交或审计记录。

## 安全边界

- `TRADING_REAL_WRITE_ENABLED` 默认关闭。
- 券商可登录不代表允许真实委托。
- 模型和策略结果必须经过当前账户、持仓、交易日历、价格和风险复核。
- Agent 建议不进入真实交易执行链，Agent 不持有券商凭据，也不能直接提交委托。
- 敏感凭据只从运行环境读取，不进入日志或 Agent 上下文。
- 查询能力和写入能力分开授权和降级。
