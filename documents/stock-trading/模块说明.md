# stock-trading 模块说明

## 模块定位

`stock-trading` 是真实交易安全边界，负责用户认证、运行开关、账户和持仓事实、订单管理、风险校验、券商适配、同步和绩效聚合。

## 业务用途

- 维护系统用户和界面偏好。
- 管理券商认证与会话状态。
- 查询并持久化账户、持仓、订单和成交事实。
- 在委托前执行统一风险检查。
- 提交委托并轮询订单结果。
- 聚合已实现交易记录和绩效。
- 提供系统健康、运行配置和日志能力。

## 核心能力

| 能力 | 说明 |
|---|---|
| 认证与权限 | 系统登录、接口拦截和用户范围控制 |
| 运行配置 | 真实交易、调度和关键能力的运行开关 |
| 风险控制 | 资金、仓位、T+1、时间、价格和幂等检查 |
| 券商适配 | 封装登录、查询、委托、撤单和验证码处理 |
| 事实同步 | 同步账户、持仓、订单和成交，并记录批次 |
| 交易记录 | 将订单与成交聚合为可解释的买卖记录 |
| 绩效统计 | 计算已实现收益、胜率和时间区间表现 |

## 实现方式

Controller 对外提供认证、券商查询、同步、订单、交易记录、绩效和运行配置接口。Service 编排业务流程，`execution` 包封装风控、费用、价格监控、订单轮询和券商适配。

MongoDB 保存交易事实和运行配置。券商事实优先，每笔委托独立记录；WebSocket 日志用于运维观察，但日志不是订单或审计记录的替代品。

## 依赖关系

- 依赖 `stock-base`、`stock-data`、`stock-model` 和 `stock-strategy`。
- 被 `stock-agent` 和 `stock-job` 使用。
- 对真实券商写入拥有最终执行权。

Agent 交易计划当前只保存草案并完成人工审批，不提供自动执行桥接。真实委托只能通过本模块已有的人工或统一任务入口发起，后续若增加计划执行能力，也必须由 Java 风控和券商执行链重新读取当前事实后决定。

## 安全边界

- `TRADING_REAL_WRITE_ENABLED` 默认关闭。
- 券商可登录不代表允许真实委托。
- 模型、策略和 Agent 结果必须经过交易模块复核。
- 敏感凭据只从运行环境读取，不写入日志、数据库明文或 Agent 上下文。
- 查询能力和写入能力分开授权和降级。
