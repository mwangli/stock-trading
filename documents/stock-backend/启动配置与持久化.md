# stock-backend 模块说明

## 模块定位

`stock-backend` 是核心 Spring Boot 服务，默认端口 8080。它承载数据、模型、确定性策略、交易、Quartz 编排、内部事实 API 和最终交易安全边界。

后端内部领域通过 Java 包和子目录隔离，不再拆分 Maven 子模块。启动入口为 `com.stock.backend.StockBackendApplication`。

## 内部领域

| 包根 | 职责 |
|---|---|
| `com.stock.base` | Backend 内部公共响应和最小契约 |
| `com.stock.data` | 股票、行情、新闻、交易日历和数据质量 |
| `com.stock.model` | 训练、推理、模型版本、预测和评估 |
| `com.stock.strategy` | 排名、信号、配置、状态和回测 |
| `com.stock.trading` | 用户、账户、持仓、订单、风控和券商执行 |
| `com.stock.job` | Quartz 任务、执行记录和跨领域编排 |
| `com.stock.backend` | 启动、持久化、缓存、内部 API 和应用装配 |

## 持久化边界

| 存储 | Backend 用途 |
|---|---|
| MySQL | 用户、偏好、任务配置与记录、策略配置、模型元数据、交易批次与状态 |
| MongoDB | 行情、新闻、交易日历、预测明细、回测、账户与持仓快照 |
| MongoDB GridFS | LSTM 参数和训练快照等大文件 |
| Redis | 查询缓存与 Backend/Agent 共享 Session |
| `model-artifacts/sentiment` | 固定财经情感模型制品 |

Flyway 只管理 MySQL 结构。MongoDB 通过文档映射和索引初始化维护集合与索引，Redis 缓存失败必须回退权威存储，不能改变业务结果。

## Agent 协作

- `/api/internal/agentFacts/**` 向 Agent 提供最小、只读、结构化事实。
- 内部接口必须通过 `X-Internal-Token` 校验，并由 Nginx 阻止外部访问。
- Backend 不调用 Agent 参与自动交易执行。
- Agent 建议不可用、超时或返回无效结果时，只影响建议与评估能力。
- Agent 结果不能绕过权限、交易日历、资金、持仓、价格、T+1 或券商执行校验。

## 启动期动作

- 校验 MySQL、MongoDB 和 Redis 配置。
- Flyway 迁移 MySQL。
- `JobBootstrap` 幂等补齐 MySQL 固定任务配置并重建 Quartz RAMJobStore。
- 初始化必要的 MongoDB 索引。
- 检查 Sentiment 制品和可选模型能力。

核心数据库不可用应明确阻止服务正常运行；Agent、Provider 或可选模型不可用可以受控降级，但必须暴露真实状态。
