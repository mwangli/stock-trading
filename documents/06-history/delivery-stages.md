# Python T+1 阶段交付记录

本页合并历史阶段 01 至 12 的设计结论。阶段报告中的运行证据属于当时提交的历史快照，不自动代表当前生产状态；当前仓库只读取这些阶段最终留下的数据契约。

## 阶段 01：市场数据基础

确定 BaoStock 日线与 5 分钟线采集、Parquet 不可变分区、股票代码规范和质量审计。关键约束包括交易日、每天 48 根 5 分钟线、时间边界、重复请求一致性和分钟聚合偏差。

## 阶段 02：Qlib Alpha158 与 LightGBM

建立 Qlib 数据转换、Alpha158 特征、横截面回归、每日 Top 5、IC 与排名评估。模型输出定位为候选排序，不直接等同于交易收益。

## 阶段 03：组合回测

把下午买入与次日上午卖出窗口纳入回测，考虑手续费、滑点、无法成交、单持仓和资金约束，避免用收盘价回测替代真实执行窗口。

## 阶段 04：SQLite 状态闭环

用 SQLite 保存任务运行、模型版本、预测、订单计划、订单尝试、券商事实、持仓推导、绩效和训练请求。业务键与唯一约束用于保证命令重跑幂等。

## 阶段 05：Python 券商契约

迁移登录、账户、持仓、行情、委托、撤单、当日与历史委托成交等已验证 HTTP 契约。券商负责实时事实，历史训练数据仍由市场数据源提供。

## 阶段 06：生产推理

固定模型制品、特征版本、目标交易日和股票池，重算全市场分数并原子写入预测。推理结果必须绑定模型版本，重复执行不能产生冲突批次。

## 阶段 07：影子交易计划

根据 Top 5、真实持仓、资金和行情生成上午卖出、下午买入计划，但不调用券商写接口。计划作为后续执行的可审计输入。

## 阶段 08：订单执行与恢复

设计委托、部分成交、撤单、未知状态和重启恢复。历史版本强调订单终态和资金释放，后续阶段 12 简化了正常提交后的等待逻辑，但保留唯一业务键与事实同步。

## 阶段 09：绩效与自动评估

按成交与账户事实记录毛/净收益、费用、外部现金流和最大回撤，按模型版本隔离评估窗口，并生成保持、退化或训练请求等决策。

## 阶段 10：真实验证准入

曾建立本地门禁、券商只读核对、模型绑定和小资金显式启用。历史真实验证补齐了券商股东账号与市场字段，并到达交易时间校验，但未获得成功委托号。复杂门禁后来被阶段 12 删除。

## 阶段 11：纯 Python 收口

删除旧 Java 交易后台、React 门户、Quartz、旧数据库链路和只描述已删除模块的文档，生产权威收敛为 Python、Qlib、Parquet、SQLite、券商契约和操作系统定时器。

## 阶段 12：券商结果直记

删除复杂提单门禁和正常流程中的成交等待、超时撤单；本地发起请求并记录 `SUBMITTED`、`REJECTED` 或 `UNKNOWN`，后续同步更新最终券商事实。Top 5、价格范围、股票前缀、持仓和资金仍用于决定标的与数量。

## 当前控制台继承的结果

当前 Java 控制台直接读取上述阶段形成的 Parquet 与 SQLite 表。页面保留市场、模型、订单、交易、绩效、训练请求和日志视图，但不恢复这些阶段的执行命令。
