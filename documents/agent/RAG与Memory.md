# RAG 与 Memory

## 职责划分

| 能力 | 保存内容 | 用途 |
|---|---|---|
| RAG | 项目知识、业务规则和可检索文档片段 | 为当前任务补充外部知识证据 |
| Memory | 用户确认偏好、纠正、系统事实和历史经验 | 在后续会话中保持受控连续性 |
| Chat Memory | 当前会话最近消息 | 维持短期对话上下文 |

三者不能混用。RAG 文档不会自动成为用户偏好，模型推断也不能未经确认写成长期事实。

## Embedding 契约

Embedding 使用 `model-files/embedding/bge-base-zh-v1.5` 中的本地 DJL 模型。向量维度、归一化、Pooling、最大序列长度和模型版本共同构成向量契约。模型版本或维度改变后，旧向量需要按对应版本重建，不能直接混合比较。

## RAG 流程

```text
文档导入
  → 文本分块和来源元数据
  → Embedding
  → MongoDB 向量文档
  → 查询向量和相似片段检索
  → 受控上下文组装
```

检索结果携带来源、片段标识和相关度，回答需要区分检索证据与模型推断。

## Memory 生命周期

Memory 来源区分用户确认、系统事实、模型推断和业务结果。长期 Memory 必须绑定用户范围，记录来源和创建时间，设置有效期或保留策略，并支持纠正、遗忘和过期状态。

用户纠正不直接覆盖历史记录，而是将旧记录标记为已纠正并建立新事实。密码、Token、Cookie、完整账户信息及其他敏感数据不得进入 Memory。

## 降级与数据边界

Embedding 未就绪时，RAG 和向量 Memory 返回不可用状态，不使用低质量哈希向量伪装。其他不依赖检索的 Agent 任务可以继续。

RAG 和 Memory 只提供上下文，不是行情、持仓、任务或交易状态的权威来源。涉及当前事实时必须调用对应只读工具重新查询。
