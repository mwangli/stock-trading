# Trading 交易执行模块

## 模块定位

`stock-trading` 直接消费 `stock-model` 当日预测排名，负责上午卖出、下午买入、券商委托、订单终态确认、账户持仓同步和真实收益统计。系统不再维护独立 Strategy 模块、策略配置、技术指标候选、止损止盈或候选二次评分。

## 唯一控制方式

自动交易只由两个 Quartz 任务的 `job_config.status` 控制：

- `realTradingMorningSell`
- `realTradingAfternoonBuy`

每次准备提交新委托前都重新读取对应任务状态。任务关闭时撤销当前活动委托，确认券商终态后退出。不存在独立真实写入总门禁、紧急停止、策略状态或本地风险评分。

## 上午分阶段卖出

任务运行窗口为 `09:35-11:25`，卖出券商返回的全部可卖数量，不使用止损、止盈或技术指标。

| 时间 | 委托方式 |
|---|---|
| `09:35-10:15` | 最新卖三价 |
| `10:15-10:50` | 最新卖一价 |
| `10:50-11:15` | 最新买一价 |
| `11:15-11:25` | 最优五档即时成交剩余撤销；不支持时使用最新买五保护限价 |

前三阶段单笔最多等待 60 秒。完全成交后结束该持仓；部分成交或未成交时撤销剩余，确认终态后按最新盘口和剩余可卖数量继续。多个持仓可并行，但每只股票同一时间最多一笔活动卖单。窗口结束后撤销仍活动的卖单并记录未完成数量。

## 下午模型前三名买入

任务运行窗口为 `13:05-14:54`。Trading 读取 `PredictionCandidateQueryService` 返回的最新可用预测批次，检查目标交易日和明细完整性，按融合后的 `effectiveModelScore` 降序取前三名。

| 时间 | 委托方式 |
|---|---|
| `13:05-13:45` | 最新买三价 |
| `13:45-14:20` | 最新买一价 |
| `14:20-14:45` | 最新卖一价 |
| `14:45-14:54` | 最优五档即时成交剩余撤销；不支持时使用最新卖五保护限价 |

三个候选线程共享唯一资金执行权。胜出线程重新查询资金和五档行情，扣除预计费用后按整手计算最大数量并提交一笔买单。未成交撤单并确认资金释放后重新开放竞争；部分成交立即锁定该股票，停止其他候选，后续只使用剩余资金继续买入该股票。完全成交或剩余资金不足一手时结束。

## 五档行情和委托能力

`FiveLevelQuoteDto` 明确携带买一至买五、卖一至卖五和行情时间。缺少任一档位时行情不可用于分阶段交易，禁止用单一实时价推算五档价格。

`ZXBrokerAdapter` 支持：

- 普通限价委托。
- 最优五档即时成交剩余撤销 `BEST_FIVE_IOC`。

券商未配置支持 `BEST_FIVE_IOC` 时，上层使用保护限价回退。券商字段名和价格类型代码属于外部协议，必须在真实环境独立验证。

## 订单终态和资金释放

`OrderPoller` 使用共享调度线程池，但单个订单完成只取消自身轮询任务，不关闭整个执行器。撤单后必须查询到以下终态之一：

- `FILLED`
- `CANCELLED`
- `REJECTED`

`TIMEOUT` 和未知状态不是券商事实终态。未确认终态时不得释放买入执行权、不得提交下一笔买单，也不能把接口调用成功记录为成交成功。

## 重启恢复与事实同步

应用重启后从券商当日活动委托、成交和当前持仓恢复，不依赖内存中的候选线程或轮询状态。账户、持仓、订单和成交同步继续保留，用于：

- 恢复活动订单和剩余数量。
- 计算真实可用资金和可卖数量。
- 防止重复提交。
- 按实际成交价、数量和费用统计收益。

## 与风险规则的边界

删除策略风控不等于忽略交易事实。以下校验属于订单可执行性，仍由 Java 处理：交易日和交易时段、资金、整手数量、当前持仓、T+1 可卖数量、价格有效性、活动订单唯一性、撤单终态和券商会话。

## 验证边界

当前仅确认源码和配置已按本设计修改。尚未执行 Maven 编译、Spring 启动、Quartz 运行、数据库初始化、券商五档解析、最优五档委托或真实成交验证。
