# Application 应用装配模块

## 模块定位

`stock-application` 是唯一可执行 Spring Boot 模块，负责启动入口、关系型与 MongoDB 配置、缓存、接口日志、Flyway 基线和七个 Backend 模块的最终装配。它不承载市场、模型或交易算法。

## 七模块装配

| 子模块 | 职责 |
|---|---|
| `stock-base` | 最小公共契约 |
| `stock-data` | 市场、新闻和交易日历事实 |
| `stock-model` | 训练、推理、融合和模型排名 |
| `stock-trading` | 分阶段交易、券商订单、成交和绩效 |
| `stock-platform` | Quartz、任务启停、执行记录和只读事实聚合 |
| `stock-agent` | LangChain4j、RAG、Memory 和只读业务工具 |
| `stock-application` | 启动、存储、接口日志和最终装配 |

启动类 `com.stock.StockBackendApplication` 以 `com.stock` 为扫描根。Maven 和容器启动配置必须指向同一主类。

## 数据库基线

MySQL 只保留两个基线文件：

- `V1__ddl.sql`：当前最终表结构。
- `V2__dml.sql`：当前初始化数据和默认任务。

当前基线不再包含策略配置表、策略运行状态表、自动交易暂停或紧急停止字段。默认任务只登记上午卖出和下午买入，不登记旧选股、自动买入和 T+1 退出任务。改写基线会改变已有数据库的 Flyway checksum，不能在未批准情况下直接作用于共享或生产数据库。

## Agent 事实装配

`InternalAgentFactsService` 通过各领域公开 Service 提供模型排名、任务状态、券商状态、订单、成交和绩效等只读事实。Agent 不再查询策略状态、自适应策略、策略版本或独立交易门禁，也不访问业务 Repository。

## 存储边界

| 存储 | 权威职责 |
|---|---|
| MySQL | 用户、任务配置、模型元数据和交易状态 |
| MongoDB | 行情、新闻、预测、账户、持仓、订单和 Agent 数据 |
| GridFS | 模型参数和训练快照 |
| Servlet 内存 / Caffeine | 可丢失 Session 和可重建缓存 |

## 验证边界

当前仅确认源码、POM、配置和 SQL 基线内容。未执行 Maven 编译、Spring 启动、Flyway 迁移、Repository 扫描或数据库兼容验证。
