# Model 模型模块

## 模块定位

`com.stock.model` 负责财经情感、LSTM、训练快照、模型训练与推理、预测批次、效果评估、候选版本、激活、回滚和当日排名。Trading 直接读取融合后的 `effectiveModelScore` 前三名，模型本身不直接产生真实委托。

## 核心能力

| 能力 | 主要职责 |
|---|---|
| 数据准备 | 检查版本化市场数据，执行受控回填，构建或复用不可变快照 |
| 算法实现 | Ranking LSTM、MASTER Transformer、损失函数和指标 |
| 训练快照 | 保存数据范围、特征/标签版本、切分策略、样本数和校验信息 |
| 训练与推理 | 受控训练、批量预测、队列执行和失败记录 |
| 情感分析 | 固定制品加载、情感推理、事件特征和影子评估 |
| 生命周期 | 候选、评估、激活、回滚、审计和运行状态 |

## 重点能力详细设计

### 统一训练流水线

手动接口和 `lstmOfflineTraining` Quartz 任务只负责创建同一种 `model_training_run`，随后统一进入 `ModelTrainingPipelineService`：

```text
QUEUED
→ CHECKING_DATA
→ PREPARING_DATA（Tushare 免费日线与新闻快照）
→ RECHECKING_DATA
→ PREPARING_SNAPSHOT
→ SNAPSHOT_READY
→ TRAINING
→ OFFLINE_EVALUATING
→ CANDIDATE_REGISTERED
→ SUCCEEDED
```

`ModelDataReadinessService` 在快照前检查固定来源版本的 `model_stock_daily_bars` 股票覆盖、最新日期和 `temporal-news-v1` 新闻快照。`ModelDataBackfillService` 先调用 Tushare 免费 `daily` 准备 `TUSHARE_FREE_DAILY/V6` 模型日线，再推进新闻快照游标；每轮后重新盘点，只有实际写入日线或生成快照才继续，最多执行 `dataPreparationMaxRounds` 轮。官方复权因子、历史行业、行业参考序列和精确开盘可交易状态不再是当前 53 维 V6 的训练硬门禁；无进展、达到轮数上限或复检仍不通过时，把完整报告和各轮结果写入 `gateResultJson` 并结束为 `WAITING_DATA`。

数据快照是可恢复检查点。快照达到 `READY` 后立即把 `datasetSnapshotId` 关联到训练运行；后续训练失败、停止或应用重启不会删除该快照，相同数据契约下的新任务直接复用。独立的手工快照 HTTP 入口已删除，`LstmTrainerService` 也只接受明确的 `snapshotId`，避免形成旁路。

### 训练与模型数据保留

月度 `globalDataCleanup` 只清理已经超过业务保留期且不再参与当前运行的数据：

| 数据 | 默认保留规则 |
|---|---|
| 终态训练运行 | 365 天 |
| `FAILED` 快照 | 30 天，且无训练运行引用 |
| `READY` 快照 | 90 天；同一模型和契约至少保留最近 2 份，且只删除无引用快照 |
| `RETIRED` 模型参数 | 90 天；保留模型元数据，并保护当前激活、上一回退、Ranking LSTM 和 MASTER 指针 |
| 孤儿模型参数 | MySQL 已无任何模型元数据引用时删除 |
| 旧 Mongo `lstm_models` | 保留全部 `ACTIVE` 和最近 5 个版本 |
| 终态预测批次及明细 | 365 天 |
| 情感与时序模型影子预测 | 365 天，仅清理终态记录 |
| 模型操作审计 | 730 天 |

模型参数删除后保留 MySQL 模型版本、训练配置和指标，仅清空参数文件标识、摘要和大小。当前激活版本、上一回退版本、当前 Ranking LSTM 和 MASTER 候选不得因时间到期被清理。MongoDB 删除释放的是可复用内部空间，不承诺立即降低操作系统文件大小。

训练期 Walk-Forward、独立测试和候选质量校验属于一次性离线评估，跟随本次流水线完成。MASTER 的长期影子预测、真实收益回填、滚动比较、连续调权和自动回退由 `MasterShadowPredictionService` 与 `TemporalModelEnsembleService` 持续执行，不占用训练运行状态。

### 1. 不可变训练快照

**设计目标**：训练使用可复现的数据工件，而不是每次从变化中的行情库临时拼装数据。

`TrainingDatasetSnapshotService` 根据模型名称、股票范围、日期窗口和数据契约生成 `contractHash`。相同契约存在 `READY` 快照时可以复用；契约变化必须生成新快照，不能修改旧快照元数据伪装兼容。

快照创建流程：

1. 从 `MarketDataQueryService` 读取明确时间范围的市场 DTO。
2. 固化股票集合、特征版本、标签版本、样本范围、数据切分和统计摘要。
3. 将大数据按分片写入临时工件，计算每个分片和清单摘要。
4. 通过 `TrainingSnapshotArtifactStore` 保存到 MongoDB GridFS。
5. 校验文件大小、分片摘要、清单摘要和汇总样本数后，将快照标记为 `READY`。

读取时再次校验 GridFS 文件是否存在、大小和摘要是否一致。任一工件缺失或摘要不符都必须失败，不能退回实时查询后继续训练。

### 2. LSTM 数据预处理与防泄漏

`LstmDataPreprocessor` 和 `RankingLstmDataPreprocessor` 负责把市场序列转换为 DJL 可消费的张量。流程遵循以下约束：

- 训练、验证、测试按时间顺序切分，禁止随机打散跨越未来数据。
- 标准化参数只由训练窗口拟合，再应用到验证、测试和推理窗口。
- 特征时间必须早于预测目标时间，标签和目标日真实行情不能进入特征。
- 缺失值、停牌、上市不足、样本长度不足和无效价格需要明确过滤并计数。
- 排序模型同时保留股票截面和时间序列关系，训练样本必须绑定目标交易日与股票池版本。

预处理输出应携带特征版本、标签版本、序列长度、切分范围和有效样本数，作为模型制品契约的一部分。

### 3. 基础模型职责

`RankingLSTMModel` 是唯一基础时序模型：连续特征经过单向 LSTM 和 LayerNorm 后直接读取最后一个时间步，再拼接股票、行业和市场 Embedding，输出统一四任务结果。它不再包含特征注意力或时间注意力，目标是提供参数较少、训练稳定、可快速重训的生产基线。

时间注意力、横截面股票关系和市场状态建模统一由 `MASTER_TRANSFORMER` 承担。系统只维护“稳定 Ranking LSTM 基线 + MASTER 挑战者/融合模型”两层职责。

#### 3.1 `RANKING_LSTM` 与 `MASTER_TRANSFORMER` 能力对比

> 架构标识统一使用 `MASTER_TRANSFORMER`。当前实现是 MASTER-inspired 单头横截面自注意力模型，不是完整论文复刻，也不是通用多层 Transformer Encoder。

| 对比维度 | `RANKING_LSTM` | `MASTER_TRANSFORMER` |
|---|---|---|
| 系统定位 | 唯一生产基础模型，提供稳定、低成本、可快速重训的基线结果 | 复杂能力挑战者，通过影子评估后参与融合增强，不直接替代生产基础模型 |
| 单股时间建模 | 单向 LSTM 编码完整序列，直接读取最后时间步隐藏表示 | 连续特征投影后使用时间注意力对历史交易日加权聚合，不使用 LSTM |
| 横截面股票关系 | 不直接计算股票之间的相互关系；同日分组主要用于排序损失和评估 | 在同一目标交易日股票 Batch 内执行 Q/K/V 自注意力，显式学习股票间相对关系和市场联动 |
| 类别信息 | 使用股票、行业、市场三类 Embedding，能够学习稳定类别差异 | 当前只使用连续特征，不使用三列类别索引和类别 Embedding |
| 市场状态表达 | 通过市场连续特征和市场 Embedding 间接表达 | 使用同一 Batch 股票表示均值构造市场状态，并由 `marketGate` 控制横截面关系贡献 |
| 输入组织要求 | 可以按股票独立前向；同日股票池变化不会改变某只股票的网络上下文 | 必须保持同日股票池、覆盖率和兼容的分块策略；股票缺失或 Chunk 变化会改变注意力上下文 |
| 表达能力 | 擅长提取单股连续时序和稳定类别模式，结构简单但难以直接表达股票联动 | 能同时选择重要历史交易日并建模同日股票关系，适合捕获行业轮动、风格切换和市场共振 |
| 训练与推理成本 | 参数和计算路径较少，训练、重训和推理更快，资源需求较低 | 需要构造 `[B,B]` 关系矩阵，横截面股票数增加时计算量和显存占用增长更快 |
| 稳定性与过拟合 | 对 Batch 构成不敏感，通常更稳定，数据不足时过拟合风险较低 | 对股票覆盖、分块、样本规模和市场阶段更敏感，表达能力更强但过拟合和分布漂移风险更高 |
| 数据成熟度要求 | 依赖完整时序、类别字典、标准化统计和标签质量 | 除相同基础数据外，更依赖同日股票池完整性、横截面覆盖和稳定 Batch 语义 |
| 共同输出 | `rankScore`、`expectedExcessReturn`、`upProbability`、`downsideQuantile` | 与 Ranking LSTM 使用完全相同的四任务输出契约 |
| 制品与加载 | 通过自身结构参数和类别字典重建，作为生产激活版本直接加载 | 必须按自身架构及 `crossSectionBatchSize` 重建，不能与 Ranking LSTM 制品互换 |
| 生产使用方式 | 生成基础预测和默认排序结果；新候选不达标时继续保留当前生产版本 | 先影子预测并积累真实样本外评估，满足门禁后才按受限权重写入融合排序 |
| 失败与回退 | 制品、契约或候选质量不合格时拒绝晋级，不影响现有生产模型 | 契约、覆盖、滚动指标或收益优势不满足时权重降为 `0`，自动回退到 Ranking LSTM 原结果 |

二者不是两个互斥的生产基础模型，也不采用“二选一直接上线”的方式。当前最简生产组合为：

```text
RANKING_LSTM       = 稳定生产基线和默认结果
MASTER_TRANSFORMER = 影子挑战者和受控融合增强
```

该组合把稳定性留给 Ranking LSTM，把横截面关系建模留给 MASTER。MASTER 只有在相同数据、标签、成本和样本外评估口径下持续优于基线时才获得融合权重；优势消失或任一门禁失败时，系统无需人工干预即可退回 Ranking LSTM。

### 4. MASTER Transformer 机制

`MasterTransformerModel` 用于 `MASTER_TRANSFORMER` 候选架构。其目标不是只判断单只股票的历史走势，而是在同一目标交易日内同时学习“单股时序表示”和“股票之间的横截面关系”。

当前实现是适配现有 DJL 四任务框架的 **MASTER-inspired 单头 Transformer**，并非完整复刻论文，也不是标准多层 Transformer Encoder。

#### 4.1 单股时序表示

输入首先恢复为 `[B, T, inputSize]`，末尾三列类别索引被排除，当前 MASTER 只使用连续特征：

```text
continuous [B, T, F]
  → Linear(F → H)
  → ReLU
  → LayerNorm
  → temporal attention: Linear(H → H/2) → tanh → Linear(H/2 → 1)
  → 在 T 维 softmax
  → 加权求和得到 [B, H]
```

这一阶段没有使用 LSTM。时间维通过可学习的注意力评分聚合，但当前实现没有显式位置编码、因果 Mask 或时序卷积。因此它依赖输入特征本身表达时间状态，不能将其描述为完整的时序 Transformer 编码器。

#### 4.2 横截面 Q/K/V 自注意力

得到每只股票的时序表示 `R [B, H]` 后，模型分别生成：

```text
Q = Wq * R
K = Wk * R
V = Wv * R
```

股票关系分数使用缩放点积：

```text
A = softmax((Q * K^T) / sqrt(H), stockDimension)
C = A * V
```

其中 `A` 的形状为 `[B, B]`。每一行表示一只股票对当前 Batch 内其他股票的关系权重，`C [B, H]` 是聚合后的横截面关系表示。

这要求 Batch 具有明确业务语义：

- 训练数据由 `LstmTrainerService.createDateGroupedDatasets` 先按 `targetTradeDate` 分组，禁止跨日期股票进入同一个横截面 Attention。
- 同一日期股票数超过最大 Batch 时会被拆成多个 Chunk，Attention 只能看到当前 Chunk；因此训练和推理的 Batch 大小、股票覆盖与分块策略会影响关系上下文。
- 推理必须保持候选股票集合完整，并使用与训练兼容的特征版本；不能把单股票推理结果当作完整横截面结果。

#### 4.3 市场状态门控

模型使用同一 Batch 股票时序表示的均值构造市场状态：

```text
marketState = mean(R, stockDimension)
marketGate  = sigmoid(Wg * marketState)
fused       = R + marketGate * C
```

`marketGate [1, H]` 控制横截面关系表示在各隐藏维度上的贡献。残差项保留单股自身表示，避免关系信息完全覆盖个股信号。

该门控依赖当前 Batch 的股票构成，因此股票池缺失、分块变化或覆盖不完整都会改变市场状态。影子预测必须校验股票覆盖，生产融合条件不满足时回退到 Ranking LSTM。

#### 4.4 输出契约

融合表示通过两层输出 Head 生成与 Ranking LSTM 相同的四个结果：

```text
0 rankScore               # 不限制区间，用于横截面排序
1 expectedExcessReturn    # tanh 约束后的预期超额收益
2 upProbability           # sigmoid 上涨概率
3 downsideQuantile        # sigmoid 下行风险分位
```

统一输出契约允许 Ranking LSTM 与 MASTER 复用损失、Walk-Forward 指标、影子评估和候选查询，但不代表两个模型制品可以互换。运行时必须通过 `architectureType` 重建正确模型。

#### 4.5 与标准 Transformer 的差异

| 能力 | 当前 `MasterTransformerModel` | 标准 Transformer Encoder 常见实现 |
|---|---|---|
| Attention Head | 单头 Q/K/V | 多头注意力 |
| 编码层数 | 单次横截面关系计算 | 多层堆叠 |
| 时间位置编码 | 无显式位置编码 | 位置编码或相对位置偏置 |
| 时间因果 Mask | 无 | 按任务选择 Causal Mask |
| 残差 | 融合阶段保留单股表示 | 每个 Attention/FFN 子层残差 |
| Feed Forward | 输出 Head | 每层独立 FFN |
| 类别 Embedding | 当前未使用 | 可按架构设计融合 |

因此文档和接口统一称其为 `MASTER_TRANSFORMER` 架构标识，但能力描述必须使用“MASTER-inspired 横截面自注意力模型”，不能宣称已经实现完整通用 Transformer。

#### 4.6 影子运行和生产边界

`ModelActivationService` 明确禁止将 `MASTER_TRANSFORMER` 直接激活为生产基础模型。当前安全路径为：

1. 训练并保存 MASTER 候选制品。
2. `MasterShadowPredictionService` 使用生产 Ranking LSTM 批次的相同股票集合和基础交易日执行影子预测。
3. 校验 MASTER 与基线模型的特征、标签、时间切分、成本和输出契约一致，并要求影子结果至少覆盖基线股票的 95%。
4. 真实目标日行情到齐后回填实际收益并计算滚动指标。
5. 推理先一次性构造完整股票池输入，再按制品中的 `crossSectionBatchSize` 分块前向传播；该字段只对 MASTER 强制，当前 Ranking LSTM 与 MASTER 都必须匹配 V6 53 维输入契约。
6. `TemporalModelOutputCalculator` 对排名、预期超额收益、上涨概率和下行风险统一融合，重算当日上涨概率百分位，再生成唯一 `effectiveModelScore`；生产排名和权重回放共用该计算器。
7. 至少积累 10 个已评估交易日、500 个有效股票样本和 95% 同日覆盖率；最近 20 个交易日按 MASTER 权重 `0.00、0.05、...、1.00` 回放全部组合。
8. 合格组合按 Rank IC、Top 10% 扣成本收益和最大回撤形成综合质量分；最优组合至少提升 `0.05` 才调权，每次实际权重最多变化 `0.10`。
9. Ranking LSTM 和 MASTER 权重均可降到 `0`。权重为 `0` 的模型继续每日预测，但不影响生产排名、收益字段、方向评分或风险评分。
10. 影子任务只处理 MASTER 候选创建时间之后生成的非重算生产批次，并在最近滚动窗口内补跑漏执行批次，禁止用候选创建前的历史预测或候选创建后的历史重算形成伪样本外评分。

Transformer 输出仍然只是模型事实，不直接改变仓位或调用券商写接口。

### 5. 训练、候选、自动晋级和退役

`ModelTrainingPipelineService` 负责训练编排，`LstmTrainerService` 只从已就绪快照加载样本并执行 DJL 训练；算法结构、损失函数和指标位于 `algorithm`。计划训练先生成基础时序模型候选，一次性离线评估完成后再串行生成 MASTER 候选，不需要人工激活。

生命周期分为：

| 阶段 | 含义 | 允许动作 |
|---|---|---|
| 等待数据 `WAITING_DATA` | 自动准备达到轮数上限、没有实际写入进展或复检后仍有数据缺口 | 保留盘点报告、各轮回填结果和已有快照，数据补齐后重新触发 |
| 训练中 | 正在读取已就绪快照并优化参数 | 记录进度，可安全中断 |
| 候选 `CANDIDATE` | 制品完整，等待综合评分或 MASTER 影子样本 | 自动评估、比较 |
| 激活 `ACTIVE` | 当前基础生产版本或已参与融合的 MASTER | 推理、滚动监控、自动调权 |
| 退役 `RETIRED` | 未晋级、被替换或越过硬门禁 | 保留元数据和审计证据 |

`LstmModelArtifactService` 将参数写入 GridFS，并把参数文件 ID、结构配置、输入输出契约、指标和状态写入模型元数据。`ModelPromotionPolicy` 使用 `0.45 × Rank IC 分 + 0.35 × 收益分 + 0.20 × 回撤分` 形成唯一综合评分；首个基础模型达到 `0.20` 自动晋级，后续候选至少领先生产模型 `0.05` 才自动切换。

`LstmModelRuntimeService` 和 `LstmInferenceService` 只从激活元数据与对应 GridFS 参数重建模型。参数文件缺失、模型结构不匹配或特征契约不一致时强制失败，不使用随机参数或旧文件代替。候选质量校验还会重新读取 GridFS 参数，重建实际架构并执行固定输入前向冒烟验证；输出形状、有限值或概率范围不符合契约时直接退役候选。

模型运维前端允许在受控训练弹窗选择 `RANKING_LSTM` 或 `MASTER_TRANSFORMER`，版本列表展示实际架构。前端不再提供人工激活或普通回滚按钮，只展示自动评分、影子样本、当前权重和决策原因。

### 6. 预测批次持久化队列

**设计目标**：让全市场预测可追踪、可恢复、可重试，并避免并发 Worker 重复消费同一批次。

`PredictionExecutionQueueService` 的主要流程：

1. 预测请求先创建持久化批次并进入 `QUEUED`。
2. `PredictionBatchClaimService` 通过事务认领下一批任务并转为 `RUNNING`。
3. 单 JVM 使用运行标志限制同类 Worker 并发；持久化 Claim 负责批次级互斥。
4. 按固定股票批次执行推理，持续更新总数、已处理数、成功数、失败数和进度说明。
5. 完成后记录覆盖率和批次状态，并衔接评估队列。

应用重启后，遗留 `RUNNING` 批次恢复为 `QUEUED`。线程中断时当前批次重新排队。预测失败标记 `FAILED`；人工重试只接受失败批次，先删除残留预测明细并重置进度、评估状态和错误信息，再重新入队。

历史重算通过来源批次确定股票集合，来源批次没有有效明细时直接失败，不能悄悄改用当前全市场股票池。

### 7. 预测评估和交易资格门禁

`PredictionEvaluationQueueService` 将预测完成与真实行情到齐解耦。批次只有在以下条件满足后才能进入评估：

- 预测状态属于可评估状态。
- 存在待评估预测明细。
- 目标交易日已经到达。
- 目标日行情覆盖达到要求。

否则记录 `TARGET_DATE_NOT_REACHED`、`MARKET_DATA_COVERAGE_LOW` 或 `PENDING_MARKET_DATA` 等等待原因。行情同步完成后可以扫描并唤醒等待批次。

评估分别计算方向正确率、收益误差、排序能力、覆盖率和交易相关指标。`PredictionMetricsCalculator` 与 `RankingValidationMetricsCalculator` 负责纯计算，Service 负责数据读取和持久化。不同模型契约、数据范围和费用口径的结果不能直接横向比较。

`PredictionCandidateQueryService` 对外提供候选和交易资格判断。预测完成不等于允许交易；覆盖不足、评估未完成或门禁指标不合格时，`execution` 必须拒绝自动交易。

### 8. Sentiment 固定制品与推理

情感模型由生产服务器的 `model-files/sentiment` 目录提供，并通过 Compose 只读挂载到 Backend 的 `/app/model-files/sentiment`。CI/CD 不下载、复制或打包固定模型。运行时按配置定位版本目录并交给 DJL 加载，不维护额外 manifest、摘要检查或自动修复逻辑。

`SentimentInferenceService` 负责文本预处理、模型推理和结果标准化；`SentimentAggregationService` 按股票、事件和时间窗口聚合。推理失败、输入为空、制品缺失和输出结构异常分别记录，不能统一返回中性情感掩盖故障。

### 9. Mengzi 影子部署与路由

`SentimentShadowDeploymentService` 让候选情感模型先以影子方式运行：

1. 主模型继续提供生产结果。
2. 候选模型处理相同输入，但结果只用于对比和审计。
3. 累积覆盖、稳定性和质量指标。
4. 达到门槛后由受控操作切换路由状态为 `ACTIVE`。
5. 出现质量或运行问题时切换到 `ROLLBACK` 或 `BLOCKED`。

`SentimentModelRouterService` 读取持久化路由状态决定当前模型。影子运行不会自动扩大真实交易权限，模型切换也不能绕过决策与执行门禁。

### 10. MASTER 影子预测与时序集成

`MasterShadowPredictionService` 生成不影响生产候选的 MASTER 影子结果，用于评估截面关系和新模型价值。`TemporalModelEnsembleService` 基于历史评估结果组合多个模型输出，权重必须来自已完成的历史窗口，不能使用目标日未来数据。

影子模型和集成结果需要保存模型版本、来源批次、目标交易日、信息截止时间和权重版本。只有明确完成评估和激活流程的版本才能成为正式决策输入。

## 模型制品与存储

| 制品 | 存储 | 生命周期 |
|---|---|---|
| Sentiment 固定模型 | 宿主机 `model-files/sentiment`，容器 `/app/model-files/sentiment` | 只读挂载，独立于应用镜像发布 |
| Mengzi 等候选情感模型 | 同一挂载目录下的对应版本目录 | 影子推理、评估后自动激活或回退 |
| LSTM 参数和训练快照 | MongoDB GridFS | 训练、候选、激活和回滚 |
| 模型元数据与运行记录 | MySQL/MongoDB | 版本、批次、审计和评估 |

固定制品不打入可执行 JAR 或 Backend 镜像。生产服务器预先维护完整模型目录，Compose 只读挂载后由 DJL 直接加载；应用发布流程不传输模型。旧制品与新制品按各自元数据和输入输出契约加载，不得修改旧元数据伪装兼容。

## 依赖与安全边界

- 只允许调用 `market` 的公开 Service 和 DTO，不直接访问市场 Repository 或 Entity。
- `decision` 通过模型 Service/DTO 消费预测和评估结果。
- 模型不得调用 `execution` 发起交易，也不得改变真实交易权限。
- 训练和预测任务由 `schedule` 触发，但业务算法保留在本模块 Service 中。
- 模型异常必须表现为失败、等待或不可用，不能通过默认预测结果降级为“正常”。

## 职责目录

```text
com/stock/model/
├── algorithm/    # DJL 模型、损失函数、指标和纯计算实现
├── config/       # 模型、训练、队列和影子能力配置
├── controller/   # 模型运维与预测接口
├── dto/          # 请求、响应和内部结果契约
├── entity/       # 模型、批次、快照和评估持久化对象
├── repository/   # 模型生命周期数据访问
├── service/      # 训练、推理、评估、激活和制品编排
└── vo/           # 模型内部值对象
```

## 维护规则

- 算法纯计算放入 `algorithm`，流程、事务和外部存储编排放入 `service`。
- 训练、制品写入、激活和生产生效是不同状态，不得合并表述。
- 新模型必须定义输入输出、特征、标签、切分、成本和制品版本。
- 修改模型 DTO 或批次字段时，检查决策、调度、Agent 查询 Service 和前端调用方。
