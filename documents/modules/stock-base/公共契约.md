# Base 公共契约模块

## 模块定位

`stock-base` 是 Backend 依赖链最底层的最小公共契约模块，只保存被多个上层模块稳定复用、且不属于任何具体业务域的类型和常量。它不依赖其他业务模块，不包含 Controller、Service、Repository、Entity、业务算法或应用装配。

## 当前契约

| 契约 | 职责 | 使用边界 |
|---|---|---|
| `ResponseDTO<T>` | 统一 HTTP 响应外层结构 | 只表达 `success`、`message` 和类型化 `data`，不承载业务分页或状态机 |
| `CacheNames` | 集中维护跨模块共享的缓存名称 | 只保存稳定缓存标识，不定义 TTL、容量、失效条件或业务加载逻辑 |

## 依赖方向

```text
stock-base
  ↑
stock-data → stock-model → stock-trading
  → stock-platform → stock-agent → stock-application
```

上层模块可以直接依赖 `stock-base`，但 `stock-base` 不得反向引用任何上层模块。单一业务模块内部使用的 DTO、枚举、异常和工具应留在所属模块，不因“可能复用”提前下沉。

## 准入规则

只有同时满足以下条件的内容才允许进入 `stock-base`：

1. 已经存在两个或以上真实、稳定的模块调用方。
2. 不包含市场、模型、策略、交易、Agent 或调度业务语义。
3. 不依赖 Spring Web、持久化、外部供应商或应用启动环境。
4. 变更频率低，能够作为明确的跨模块契约维护。

禁止为单实现的同 JVM 调用新增 Port、Adapter、Facade、Mapper 或兼容接口。模块间业务调用直接使用下层模块公开 Service 和 DTO，并遵守固定依赖方向。

## 维护规则

- 修改 `ResponseDTO<T>` 时必须检查全部 Controller 返回类型和全局异常处理。
- 修改缓存名称时必须检查缓存声明、读取、写入和主动失效位置。
- 新增公共类型前先证明真实复用关系，不能把业务模块中的便利类集中搬入本模块。
- 源码存在只证明 `SOURCE_IMPLEMENTED`，不代表编译、运行或接口兼容性已经验证。
