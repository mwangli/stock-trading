# Stock Backend 整体架构

## 文档定位

本文件是 `stock-backend` 的整体架构入口，与 Backend 启动类 `StockBackendApplication` 位于同一组合根 `com.stock` 下。

这里说明八个 Maven 子模块如何协作、依赖方向、公共技术装配、数据所有权和安全边界。模块内部能力与跨模块详细设计由文档门户对应页面维护。

## 代码结构

```text
stock-backend/
├── stock-base/         # 最小稳定公共契约
├── stock-data/         # 市场事实与数据质量
├── stock-model/        # 训练、推理和模型生命周期
├── stock-strategy/     # 排名、信号、策略与回测
├── stock-trading/      # 风控、账户、券商与真实交易
├── stock-platform/     # Quartz、任务控制、执行审计与事实聚合
├── stock-agent/        # LangChain4j、RAG、Memory 与受控建议
└── stock-application/  # 唯一 Spring Boot 组合根
```

Backend 只保留“业务包 → 职责层”两级结构。业务包内部根据实际代码建立 `controller`、`service`、`repository`、`entity`、`dto`、`algorithm`、`client`、`adapter`、`validator`、`config` 等职责目录，不创建空目录或重复分层。

## 模块职责

| 模块 | 权威职责 | 不负责 |
|---|---|---|
| [stock-base](./stock-base/公共契约.md) | 最小稳定公共契约 | 业务实现、持久化和应用装配 |
| [stock-data](./stock-data/市场事实.md) | 市场事实采集、标准化、持久化和质量治理 | 模型推断、策略判断、真实交易 |
| [stock-model](./stock-model/模型模块.md) | 训练快照、模型训练、推理、评估、晋级和回滚 | 选股规则和真实委托 |
| [stock-strategy](./stock-strategy/智能决策.md) | 候选排名、信号、策略状态和历史回测 | 券商账户事实和最终执行 |
| [stock-trading](./stock-trading/交易执行.md) | 用户、账户、风险、委托、成交同步和绩效 | 训练模型和生成策略候选 |
| [stock-platform](./stock-platform/任务调度.md) | Quartz 触发、任务配置、运行控制和执行审计 | 业务算法和持久化事实解释 |
| [stock-agent](./stock-agent/智能代理总览.md) | RAG、Memory、工具、研究和受控建议 | 权威事实解释和真实交易放行 |
| [stock-application](./stock-application/应用装配.md) | Spring 装配、存储配置和唯一启动入口 | 具体市场、模型、策略和交易规则 |

## 主业务依赖方向

```text
stock-base
   ↑
stock-data
   ↑
stock-model
   ↑
stock-strategy
   ↑
stock-trading
   ↑
stock-platform
   ↑
stock-agent
   ↑
stock-application
```

箭头表示上层模块消费下层模块公开能力：

- `stock-model` 可以调用 `stock-data` 的公开 Service 和 DTO，不访问市场 Repository 或 Entity。
- `stock-strategy` 可以调用 `stock-data`、`stock-model` 的公开 Service 和 DTO。
- `stock-trading` 可以读取市场事实、模型资格和决策候选，但必须自行完成最终风控和券商校验。
- `stock-platform` 可以触发各业务模块公开 Service，不复制业务算法。
- `stock-agent` 依赖 `stock-platform` 的公开 Service 和 DTO，不直接依赖业务 Repository 或 Entity。
- `stock-application` 装配全部模块，不承载领域算法或重复转发层。

## 启动与应用装配

`com.stock.StockBackendApplication` 是 Backend 唯一启动类，位于 `stock-application`。`@SpringBootApplication` 默认以 `com.stock` 为组件扫描根。

Maven `spring-boot-maven-plugin.mainClass` 必须保持为：

```text
com.stock.StockBackendApplication
```

启动过程由 Spring 和平台组件共同完成：

1. 创建应用上下文并绑定类型化配置。
2. 初始化 MySQL、MongoDB、Caffeine、HTTP 和线程池配置。
3. 执行 Flyway MySQL 迁移。
4. 初始化 MongoDB 必要索引。
5. 补齐固定任务配置并重建 Quartz RAMJobStore。
6. 检查模型制品和可选能力状态。
7. 应用就绪后记录完整启动耗时。

启动类只负责建立组合根和启动进程，不放置业务 Bean、数据访问、调度逻辑或异常处理。

## 分层职责

| 职责层 | 设计要求 |
|---|---|
| `controller` | HTTP 参数、入口日志、协议转换和 `ResponseDTO<T>` 封装 |
| `service` | 业务流程、事务、状态转换和用例编排 |
| `repository` | MySQL、MongoDB 的数据访问 |
| `entity` | 持久化对象及与持久化状态直接相关的枚举 |
| `dto` / `vo` | 接口输入输出、跨模块只读结果和内部值对象 |
| `algorithm` / `calculator` | 无持久化副作用的模型、指标、评分和费用计算 |
| `client` / `adapter` | 外部证券、券商和供应商协议调用与适配 |
| `parser` | 外部响应解析和格式标准化 |
| `validator` | 数据完整性、交易时间和业务门禁校验 |
| `config` | Spring Bean、类型化参数和基础设施配置 |

Controller 不直接访问 Repository；DTO 不承载查询、外部调用或状态机；纯计算不依赖 Spring 持久化组件。

## 数据所有权

| 数据 | 权威模块 | 主要存储 |
|---|---|---|
| 股票资料、行情、新闻、交易日历 | `stock-data` | MySQL / MongoDB |
| 训练快照、模型参数、预测和评估 | `stock-model` | MySQL / MongoDB / GridFS |
| 策略配置、候选、信号和回测 | `stock-strategy` | MySQL / MongoDB |
| 用户、账户、持仓、订单、成交和绩效 | `stock-trading` | MySQL / MongoDB |
| Agent 会话、任务、Memory、RAG 和审计 | `stock-agent` | MongoDB |
| 任务配置和执行记录 | `stock-platform` | MySQL，Quartz 使用 RAMJobStore |
| 单实例 Session 和可重建缓存 | `stock-application` 装配，各模块使用 | Servlet 内存 / Caffeine |

Session 和缓存不保存不可丢失的权威事实。跨模块不得传递持久化 Entity，统一使用明确 DTO。

## 核心业务链路

### 市场到候选

```text
市场数据采集
  → 数据质量确认
  → 训练快照与模型推理
  → 预测评估和交易资格
  → 策略过滤与综合评分
  → 候选批次
```

每个阶段都保留业务日期、信息截止时间、来源批次和版本。缺失或覆盖不足必须明确失败、等待或跳过，不能用默认值伪装完整。

### 候选到真实交易

```text
候选批次
  → 真实写入开关
  → 交易日和交易时间
  → 最新行情和可交易状态
  → 账户、资金、持仓和 T+1
  → 仓位、费用、数量和幂等
  → 券商委托
  → 订单回查、成交同步和绩效聚合
```

候选、模型和 Agent 输出都不是最终订单。`execution` 是唯一真实交易写入边界。

### 调度执行

```text
job_config
  → Quartz Trigger
  → Quartz Job
  → schedule.task
  → 业务 Service
  → job_execution_record
```

Quartz Job 只传播运行上下文并记录执行状态。历史回补、预测恢复、训练状态和券商同步游标由业务模块自身管理。

## 公共契约与内部 API

`stock-base` 只提供确实被多个模块稳定使用的最小公共契约；应用级异常和存储配置由 `stock-application` 装配。

`stock-agent` 通过 `stock-platform` 公开 Service 获取最小、只读、脱敏事实。Agent 不直接连接 Backend Repository，不持有券商凭据，也不控制真实交易放行。

## 关键安全原则

- 真实交易写入默认关闭，必须显式开启环境级门禁。
- 自动交易紧急停止只阻断后续自动委托，不删除订单和审计事实。
- 网络超时或结果不确定时优先回查订单，禁止立即重复提交。
- 模型训练成功只生成候选版本，不自动激活生产模型。
- 预测完成不等于具备交易资格，必须通过覆盖和评估门禁。
- 历史评价和回测必须遵守信息截止时间，禁止未来数据泄漏。
- 密码、Token、Cookie、私钥和券商凭据不得进入日志、DTO 或代码仓库。
