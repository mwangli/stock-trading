# 01-数据采集需求

## 模块定位

数据采集模块是四模块链路的事实数据入口，负责股票基础资料、日/周/月行情、分钟行情、交易日历、复权因子、可交易状态、新闻公告的采集、清洗、去重和持久化。它不训练模型、不生成策略候选、不访问券商账户。

## 功能范围

| 需求 ID | 需求 | 当前代码依据 |
|---|---|---|
| DATA-REQ-001 | 同步 A 股股票基础资料并支持分页、详情和统计查询 | `StockDataService`、`StockInfoRepository` |
| DATA-REQ-002 | 增量同步日线并生成周线、月线聚合数据 | `StockDataService`、价格 Repository |
| DATA-REQ-003 | 维护交易日历、复权因子、分钟线、历史股票池和每日可交易事实 | `MarketDataFoundationService` |
| DATA-REQ-004 | 采集新闻与公告，按 `(stockCode, externalId)` 去重 | `StockNewsService`、`NewsRepository` |
| DATA-REQ-005 | 按发布时间和单股容量执行新闻保留策略 | `StockNewsService.cleanupStockNews` |
| DATA-REQ-006 | 对采集结果输出保存、跳过、失败和删除数量 | 数据采集 DTO 和任务日志 |
| DATA-REQ-007 | 周期任务统一由固定 Quartz Job 触发 | `DataSyncScheduler`、`tradingExecutor` 根包 |

## 数据质量规则

- 股票代码、交易日期和外部新闻标识必须标准化后再参与唯一性判断。
- 日线数据按股票代码和交易日期幂等写入；新闻按股票代码和外部标识幂等写入。
- 交易日历、可交易状态和行情事实缺失时，下游模块必须能够识别“不完整”，不得自动补成正常交易日。
- 单只股票采集失败不得中断整个股票池，但必须保留失败股票、原因和重试结果。
- 数据采集开关关闭时，接口和任务均应明确拒绝或跳过，不能仅停止部分入口。

## 调度需求

数据模块只提供无参业务方法，不使用 `@Scheduled`，不管理 Quartz 生命周期。数据模块固定保留 4 个调度任务：`stockListSync`、`dailyStockDataSync`、`newsDailySync` 和 `tradeCalendarMonthlySync`。

- `stockListSync` 每周刷新股票主数据，是行情和模型股票范围的基础。
- `dailyStockDataSync` 统一完成当前交易日同步和递归向前缺口回补，不再拆分独立的历史全量任务。
- `newsDailySync` 以水位和外部标识增量采集新闻公告，为情感推理和选股提供输入。
- `tradeCalendarMonthlySync` 维护交易日历滚动窗口，为同步范围、预测目标日和交易门禁提供事实。

所有任务通过 `JobConfig + JobSchedulerService + Quartz` 注册，定时触发和手动触发必须复用相同的数据开关、幂等和审计逻辑。新闻元数据补全属于维护能力，不再作为固定任务；空洞修复由 `dailyStockDataSync` 的递归回补统一承担。

## 对外契约

- Controller 返回 `ResponseDTO<具体DTO>`，不直接返回 Entity、`Map` 或原始 `Object`。
- 模型服务读取已持久化的历史行情和股票范围；智能决策读取行情、交易日历和可交易状态。
- 跨模块只共享 DTO、查询服务或不可变数据快照，不允许下游直接修改采集模块 Entity。

## 非本期范围

- 不建设通用数据湖、消息总线和独立采集微服务。
- 不为每个数据源建立一套平行领域模型；外部差异在 `SecuritiesClient` 和解析层内收敛。
- 不在本模块实现模型特征、选股评分、账户持仓或真实交易。

## 验收标准

| 验收 ID | 标准 |
|---|---|
| DATA-AC-001 | 重复同步同一股票同一日期不会产生重复行情记录。 |
| DATA-AC-002 | 重复采集同一股票同一外部新闻不会重复保存。 |
| DATA-AC-003 | 批量任务能统计成功、跳过、失败和保留策略删除数量。 |
| DATA-AC-004 | 单股失败不影响其他股票，并能定位失败代码和原因。 |
| DATA-AC-005 | 调度开关关闭后，定时和手工入口都不能绕过门禁。 |
| DATA-AC-006 | 数据不完整时，下游能够得到明确质量状态而不是伪造数据。 |

## 验证边界

静态代码和文档不能证明证券平台稳定性、MongoDB 唯一索引已在线生效、全市场采集耗时和长期保留容量。上线前应分别核验接口响应、集合数量、重复聚合、索引和任务执行记录。
