# 股票交易平台精简改造计划书

> 日期：2026-09-25
> 原则：只保留能够形成真实交易闭环的功能，以月收益率稳定性作为长期目标。

## 1. 改造结论

项目采用最小可用架构：

- PC 前端：React，用于账户、行情、模型、候选、委托、成交和任务查看。
- 微信小程序：后续只提供通知、人工确认和核心状态查看，不复制 PC 全部功能。
- Java 单体后端：数据采集、模型推理、策略、风控、调度和真实交易统一实现。
- MySQL：配置、任务、交易事实、模型训练记录和结构化业务数据。
- MongoDB：历史行情、新闻、LSTM 模型参数等大体量数据。
- Selenium Chrome：仅用于中信证券登录和会话维护。
- Docker Compose：只保留开发和生产环境。

明确不建设：

- 不保留模拟券商、模拟账户或模拟实盘模式。
- 不建设 Shadow 平台。
- 不引入 Redis、独立 Python 服务、Agent 或大语言模型。
- 不建设模型制品审批、复杂生命周期、事件中心和通知投递箱。
- 不为接口失败准备假数据；失败时显示真实错误或空结果。

历史回测继续保留。回测只用于验证策略，不作为账户、委托或成交事实。

## 2. 核心业务目标

### 2.1 资金阶段

1. 千元到 5000 元：验证链路、风险和月度毛收益是否可持续。
2. 万元：验证手续费、滑点和仓位扩大后的净收益稳定性。
3. 十万元：仅在多个连续月份满足门槛后逐步扩容，长期运行。

### 2.2 评价顺序

1. 最大回撤和单日亏损是否受控。
2. 月收益率是否连续、稳定。
3. 净收益是否覆盖手续费和滑点。
4. 胜率、盈亏比和交易次数是否合理。
5. 单次最高收益不作为主要目标。

## 3. 唯一真实交易链路

```text
同步日线、分钟线、交易日历、新闻和公告
  -> 已训练 LSTM 股票池
  -> LSTM 预测下一交易日涨跌
  -> 最近 36 小时新闻与公告情感推理
  -> 按置信度聚合情感分数
  -> LSTM 与情感加权排名
  -> 风控过滤和资金分配
  -> LIVE_MANUAL 人工确认或 LIVE_AUTO 自动执行
  -> 中信证券委托与成交
  -> 券商账户、持仓、委托和成交对账
  -> PC 展示与微信通知
```

任何模型、行情、新闻或券商数据不可用时，必须停止对应交易决策，不允许用随机数、固定样例或规则结果冒充真实结果。

## 4. 模型方案

### 4.1 第一版必须使用

- LSTM：预测下一交易日收益方向或预期收益率。
- 情感分析模型：分析最近 36 小时与股票相关的新闻和公告。
- 综合评分：LSTM 为主，情感用于确认、增强或否决。

建议初始权重：

- LSTM：70%。
- 情感：30%。

权重不是长期固定值，必须由滚动回测结果调整。

### 4.2 情感模型的业务位置

情感分析不是独立展示功能，而是候选生成的必要输入：

1. 每只股票读取最近 36 小时最多 20 条真实新闻或公告。
2. 标题与正文合并后执行真实模型推理。
3. 使用模型置信度进行加权平均，得到 `[-1, 1]` 情感分数。
4. 无新闻时按中性处理。
5. 模型加载或推理失败时，本次选股失败，不降级为假分数。

### 4.3 后续候选模型

XGBoost 和 LightGBM 只作为后续对照模型。只有满足以下条件才进入真实候选评分：

- 严格滚动样本外回测优于当前组合。
- 加入后月收益稳定性提高。
- 最大回撤没有明显恶化。
- 扣除真实费用后仍有增益。

不因模型数量增加而默认提高准确率。

## 5. 买点、卖点和执行

### 5.1 候选生成

- T 日收盘后完成数据同步和模型计算。
- 只从有训练成功 LSTM 模型的股票中选股。
- 排除停牌、风险警示、流动性不足、涨跌停不可成交和数据不完整股票。
- 输出少量高置信候选，不为凑数量降低门槛。

### 5.2 次日买入

- T+1 日开盘后等待短时间，避开集合竞价异常价格。
- 分钟级数据确认价格、成交量和短线方向未明显反转。
- 委托价格、数量和最大可接受滑点在下单前重新校验。
- 小资金阶段单次交易必须考虑最低 5 元佣金。

### 5.3 卖出

- A 股当日买入不能当日卖出，最早在下一交易日退出。
- 达到止损线立即提交卖出。
- 达到止盈线后可使用移动止盈保护利润。
- 模型信号反转、情感显著恶化或临近收盘时按策略退出。
- 卖出失败、跌停或停牌必须记录原因并继续跟踪，不能标记为已退出。

## 6. 真实交易安全

### 6.1 模式

- `LIVE_MANUAL`：生成真实候选和委托参数，人工确认后下单。
- `LIVE_AUTO`：无人值守执行，但仍受全部风控约束。

不再存在其他交易模式。

### 6.2 独立总门禁

```text
TRADING_REAL_WRITE_ENABLED=false
```

默认必须为 `false`。只有完成账户核验、只读对账和小额人工确认后才可开启。交易模式与真实写门禁必须同时满足，任何一个不满足都禁止下单和撤单。

### 6.3 最小风控

只保留以下强制风控：

- 单只股票最大仓位。
- 总仓位上限。
- 单日最大亏损。
- 连续失败熔断。
- 可用资金和最小交易单位校验。
- 涨跌停、停牌和可卖数量校验。
- 委托幂等，避免重复下单。
