# DJL 原始模型制品指南

## 当前决策

项目不在 Java 在线运行时执行模型格式转换。LSTM 训练和推理使用 DJL + PyTorch Engine；Embedding 和 Sentiment 的原始 HuggingFace 权重在制品构建阶段使用官方 `djl_converter` 转换为 TorchScript，Java 运行时只加载经过验证的 `.pt` 文件。

## LSTM 制品

LSTM 是小型自定义模型，参数正文保存到 MongoDB GridFS，模型版本文档只保存元数据：

- `parameterFileId`：GridFS 参数文件 ID；历史 BSON `params` 仅作为兼容迁移输入。
- `trainingConfigJson`：本次训练使用的结构和超参数快照。
- `inputContractJson`：输入 Shape、特征版本和标签版本。
- `metricsJson`：训练损失、验证损失、最佳轮次和样本量。
- `parameterSha256`、`parameterSize`：参数完整性校验。
- `status`：版本状态。

加载时继续使用原有 `StockLSTMModel` 构造结构，再加载参数。当前方案不引入 Factory 或 `modelStructureVersion`；因此修改 `StockLSTMModel` 的参数布局时必须同时升级 `MODEL_VERSION`，并通过新训练生成新参数，禁止用新代码加载不兼容旧参数。

## 情感模型制品

情感 Transformer 权重不保存到 Git 或应用镜像，正式制品保存到 `/data/models/sentiment/<version>` 固定本地版本目录，并由 Docker named volume 持久化。逻辑上按版本目录组织，以便 DJL 多文件加载：

```text
sentiment-finbert/<version>/
├─ config.json
├─ tokenizer.json
├─ serving.properties
└─ pytorch_model.bin | model.safetensors | *.pt
```

Embedding 固定版本目录使用 DJL 可直接加载的 TorchScript 权重，文件名必须与模型名一致：

```text
bge-base-zh-v1.5/<version>/
├─ bge-base-zh-v1.5.pt
├─ config.json
├─ tokenizer.json
├─ tokenizer_config.json
├─ vocab.txt
└─ manifest.json
```

`pytorch_model.bin` 或 `model.safetensors` 只能作为 `djl_converter` 的转换输入，不能仅通过修改扩展名直接交给 DJL PyTorch Engine。

Embedding 使用 `/data/models/embedding/<version>`，应用启动后直接从固定目录读取版本制品。Docker 不挂载宿主机项目目录，而通过 `model-runtime:/data/models` named volume 恢复模型目录。

Embedding 的 `manifest.json` 使用 `embedding-artifact-v1` 契约；Sentiment 的 `manifest.json` 使用 `sentiment-artifact-v1` 契约。两者都记录模型名称、不可变版本、基础模型、PyTorch 引擎、最大序列长度、文件相对路径、字节数和 SHA-256。manifest 不把自身列入文件清单。

初始化前必须验证文件完整性、文件大小、文件摘要、标签顺序、输入契约和 PyTorch Engine 可加载性。`model-artifacts` 中只存放已经完成转换的固定版本制品，Java 运行时不调用 `djl-convert`，也不在预测请求中隐式联网下载或转换模型。应用只读取 `application.yml` 指定的不可变版本，不通过 `current` 软链接或覆盖目录隐式切换。

推荐发布流程：

1. 锁定模型托管平台 revision，下载到版本暂存目录。
2. Embedding 和 Sentiment 在制品构建阶段完成格式转换并生成 `<model-name>.pt`；发布到 `model-artifacts` 前必须确认目标文件存在且摘要已写入 manifest。
3. 生成 manifest，重新计算所有文件大小和 SHA-256。
4. 由异步预热流程执行 DJL 实际加载，只有加载成功才原子移动到正式版本目录并标记模型可用。
5. 重启时直接复用摘要有效的固定目录；版本变更通过配置修改和新一轮初始化完成。

当前中文金融情感基线为 `yiyanghkust/finbert-tone-chinese`，部署版本为 `finbert-tone-chinese-e91b1a3a`。BGE Embedding 基线为 `BAAI/bge-base-zh-v1.5`，部署版本为 `bge-base-zh-v1.5`。发布制品必须包含匹配模型名的 TorchScript `.pt`；Java 初始化流程只复制、校验和加载固定制品，不再根据原始 Transformer 文件执行动态转换。

该 BERT 模型的 TorchScript 输入签名包含 `input_ids`、`attention_mask` 和 `token_type_ids`。Java Translator 必须启用 Token Type 输入，并按照 manifest 的 `maxSequenceLength=128` 开启截断。`config.json` 中的 `id2label` 固化为小写 `neutral / positive / negative`，避免不同运行库返回标签大小写不一致。

## 版本升级规则

1. 只调整学习率、Epoch、Batch Size 等训练超参数：生成新模型版本，`StockLSTMModel` 可不变。
2. 调整输入特征、序列长度或标签：升级特征/标签版本并重新训练。
3. 调整层数、隐藏维度、Embedding 或 Head 参数布局：升级 `MODEL_VERSION` 并重新训练，旧版本仅允许由兼容代码回滚。
4. 升级 DJL 或 PyTorch Engine：重新执行参数加载、批量推理、资源和业务回放验证。
