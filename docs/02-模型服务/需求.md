## 1. 业务背景

股票价格受市场走势、行业特征、个股历史表现和短期交易行为共同影响，单一规则难以持续刻画不同股票在不同市场环境下的变化。系统需要通过 LSTM 模型学习历史时序数据中的共性与差异，为次一交易日的候选股票筛选提供收益方向、上涨可能性和下行风险参考。

模型输出只作为智能决策的输入，不直接形成交易指令。任何真实交易仍须经过候选筛选、Agent 决策、风险控制、资金检查、人工或自动交易门禁，避免模型结果绕过既有交易安全链路。

## 2. 业务目标

1. 建立覆盖全市场股票的共享 LSTM 模型，减少逐只股票维护模型带来的资源消耗和版本失控。
2. 定期使用最新历史数据更新模型，使预测能力能够跟随市场结构和交易行为变化。
3. 将模型训练、候选评估和生产启用分离，保证训练成功不等于立即影响交易。
4. 保留每次训练的参数、数据规模、结果和失败原因，支持问题追踪、版本比较和回滚。
5. 当数据、资源或运行时机不满足要求时主动拒绝训练，优先保障交易业务稳定。
6. 在长时间训练过程中持续展示当前阶段、训练轮次、完成比例、损失变化和预计剩余时间，便于运维人员判断任务是否正常推进。

## 3. 使用角色

| 角色 | 业务职责 |
|---|---|
| 模型运维人员 | 查看模型状态、发起受控训练、评估候选版本、执行激活或回滚 |
| 交易策略人员 | 使用已激活模型的预测结果生成候选股票，不参与模型训练过程 |
| 系统调度任务 | 在约定时间检查模型是否需要更新，并提交训练任务 |
| 审计人员 | 查询训练过程、版本变化、操作人和失败原因 |

## 4. 功能范围

### 4.1 本期范围

- 基于多只股票历史行情构建共享训练样本。
- 同时学习次一交易日收益、上涨方向和下行风险。
- 支持定时训练和运维人员手工发起训练。
- 支持训练开关、交易时段、并发任务、数据完整性、资源余量和参数范围门禁。
- 支持训练过程记录、候选版本保存、候选质量判断、人工激活和上一版本回滚。
- 支持训练状态、阶段、进度、耗时、预计剩余时间和损失收敛情况的持续查看。
- 支持已激活版本的单只股票与批量股票预测。

### 4.2 非本期范围

- 不由模型直接下单或修改持仓。
- 生产节点和普通运行节点不在交易时段执行训练或切换生产版本。
- 不建设自动超参数搜索、通用实验平台或多级审批平台。
- 不以一次训练损失下降作为生产可用的唯一依据。
- 不允许训练完成后自动替换当前生产模型。

## 6. 训练业务流程

1. 系统调度任务或模型运维人员提出训练请求。
2. 系统检查训练能力、运行时段、并发任务、基础数据、资源余量和参数范围。
3. 门禁不通过时记录拒绝原因，不启动训练。
4. 门禁通过后建立训练运行记录，并加载符合条件的股票历史数据。
5. 系统构建训练集和验证集，检查有效股票和样本规模。
6. 系统执行多目标训练，保留验证效果最好的轮次。
7. 训练结果通过完整性、兼容性和质量阈值检查后形成待激活候选版本。
8. 模型运维人员评估候选版本并决定激活、保留或拒绝。
9. 新版本激活后成为预测使用版本，上一版本保留为回滚目标。

## 7. 状态与审计

### 7.1 训练运行状态

| 状态 | 业务含义 |
|---|---|
| 排队中 | 已通过提交门禁，等待执行 |
| 运行中 | 正在构建数据或训练模型 |
| 成功 | 已生成并通过基础质量检查的候选版本 |
| 失败 | 训练、数据检查、完整性检查或质量检查未通过 |

### 7.2 模型版本状态

| 状态 | 业务含义 |
|---|---|
| 候选 | 已保存训练结果，尚未完成候选质量确认 |
| 待激活 | 已通过基础质量和兼容性检查，可由运维人员激活 |
| 已激活 | 当前生产预测使用的版本 |
| 已归档 | 曾被激活或保留，但当前不用于生产预测 |
| 已拒绝 | 未通过候选质量检查，不允许激活 |

### 7.3 审计要求

- 记录训练来源、触发人、提交时间、开始时间、结束时间和最终状态。
- 记录请求参数、实际生效参数、有效股票数、训练样本数、验证样本数和关键结果。
- 记录训练拒绝、训练失败、候选通过、候选拒绝、激活和回滚原因。
- 训练运行期间记录最近进度更新时间、当前阶段、轮次、完成比例、耗时、预计剩余时间及最近损失。
- 历史训练记录和模型版本不得因新版本生成而自动删除。

## 9. 验收边界

- 编译成功只能证明代码可构建，不能证明训练业务有效。
- 单次训练完成或损失下降不能单独证明模型可用于生产。
- 生产启用前仍需结合滚动验证、候选股票回放、扣除交易成本后的收益、最大回撤、换手率和资源占用进行评估。
 - 快照复用只能证明输入数据一致，不能单独证明模型效果或生产可用性。

## 10. 训练数据快照与中断恢复

### 10.1 数据快照

- 将历史行情读取、特征计算和训练样本构建形成独立的数据快照，避免每次训练重复准备相同数据。
- 快照保存数据截止日期、股票范围、特征版本、标签版本、样本数量和数据质量结果，支持历史复现和多版本备用。
- 训练任务优先使用状态正常且契约兼容的最新快照；没有可用快照时才构建新快照。
- 快照构建和模型训练的状态分开记录，运维人员可以区分数据准备和模型训练阶段。
- 快照被历史训练、回测或审计记录引用时不得自动删除。

### 10.2 中断与恢复

- 训练过程中按已完成轮次保存模型参数检查点，停止请求或应用重启不得破坏最近一次完整检查点。
- 已中断或失败且存在有效检查点的任务允许创建新的恢复任务，恢复任务必须复用原训练配置和数据快照。
- 恢复任务记录来源任务、恢复轮次和检查点校验结果，不能伪装成全新训练。
- 检查点与模型结构、特征版本或训练参数不兼容时必须拒绝恢复并说明原因。
- 恢复成功后仍只能生成新的候选模型版本，不得自动激活生产模型。

### 10.3 业务状态

| 状态 | 业务含义 |
|---|---|
| 快照构建中 | 正在读取行情、计算特征或写入快照工件 |
| 快照可用 | 工件完整、摘要一致并允许训练复用 |
| 快照失败 | 快照构建或数据质量检查失败 |
| 训练中断 | 训练被停止、应用重启或异常终止，但可能存在可恢复检查点 |

### 10.4 验收标准

- 首次构建训练数据快照后，契约一致的后续训练能够复用快照并记录快照 ID。
- 快照工件损坏、摘要不一致或特征契约变化时，训练拒绝复用并给出明确原因。
- 训练停止或应用重启后，存在完整检查点时可以创建恢复任务，并从已完成轮次之后继续训练。
- 恢复任务保留原任务 ID、快照 ID、检查点轮次和恢复后的新候选模型版本。
## 11. 全量模型数据快照规则

### 11.1 股票范围与历史数据

- 全量快照覆盖当前股票基础资料中允许参与训练的全部股票，并排除明确配置为不参与训练的代码。
- 每只股票读取相同数量的最近交易日，按日期从早到晚处理；不同股票之间不得共享或拼接时间窗口。
- 单只股票至少需要“输入序列长度加两个交易日”的有效记录。历史不足、价格无效或无法形成训练标签的股票允许跳过，但必须计入数据质量统计。
- 快照应分别记录股票池总数、有行情股票数、形成有效样本的股票数、行情记录数、训练样本数和验证样本数，便于解释股票损耗发生在哪个阶段。

### 11.2 样本规模与时间切分

- 单次训练最多保留十万个全市场样本，单只股票最多保留八十个样本，并保证每只有效股票至少分配四个样本额度。
- 单股实际样本上限由“全市场样本上限除以股票数量”确定，再受单股上下限约束。股票数量越多，单股额度越低，以维持可控训练规模。
- 当可形成窗口数超过单股额度时，从该股票完整可用时间范围内等距选取窗口，使早期、中期和近期行情均有代表，不使用不可复现的随机抽样。
- 每只股票按时间顺序将前 80% 样本作为训练集，训练集之后保留两个样本的隔离区间，剩余后段样本作为验证集。验证数据不得早于训练数据。

### 11.3 归一化业务口径

- 开盘、最高、最低和收盘价格转换为相对前收盘价的变化比例，并限制在负一到正一之间，消除绝对股价差异。
- 成交量和成交额使用“当前值相对近二十个交易日均值的对数比例”，再压缩并限制在负一到正一之间，降低极端放量对训练的冲击。
- RSI 转换到零到一范围；均线和布林带转换为相对当前收盘价的偏离比例；OBV 转换为相对近二十日成交量总和的比例并限制在负一到正一之间。
- MACD 使用相对当前收盘价的比例，避免不同价格水平造成直接量纲差异。
- 缺失、非数字或无穷值统一按中性值处理，避免单条异常行情污染整个批次；该兜底只能保障计算连续性，不能替代数据质量审计。
- 股票身份、行业身份和分组身份采用稳定类别映射；未知股票和未知行业使用专用保留类别。

### 11.4 标签与训练目标

- 主目标为下一交易日收益率，并以 10% 收益幅度映射到统一范围，超过范围的极端值进行截断。
- 方向目标表示下一交易日收益是否为正，用于提供上涨概率。
- 下行风险目标表示下一交易日负收益幅度，经统一缩放后限制在零到一之间。
- 模型同时学习收益、方向和下行风险，业务权重分别为 50%、30% 和 20%，避免单一目标决定全部训练方向。

### 11.5 行业特征与分组 Head

- 行业特征用于学习同一行业股票的共同差异；股票身份用于学习单股长期残差；二者不得替代行情时序特征。
- 当前分组规则以行业身份进行稳定分桶，固定为一个未知组和七个有效行业组，共八个 Group Head。该规则保证版本稳定和计算成本可控，但不代表七个组天然对应明确行业语义。
- Group Head 只允许对共享模型输出做小幅修正；个股 Residual Head 同样只做受限残差修正，避免局部参数覆盖共享规律。
- 后续若改为金融、周期、消费等业务语义分组，必须重新构建快照、重新训练并经过样本外验证，不允许直接沿用旧模型参数。

### 11.6 分片快照与复用

- 快照每处理一百只股票形成一个压缩分片，完成写入后释放该批次行情和样本，避免全市场原始数据同时驻留内存。
- 每个分片记录股票数、训练样本数、验证样本数、文件大小和摘要；快照清单汇总全部分片及总体样本数量。
- 只有全部分片写入完成、摘要一致且汇总数量匹配时，快照才能进入可用状态；失败构建产生的临时分片应清理。
- 分片和 manifest 完成校验后必须上传 MongoDB GridFS，MongoDB 快照元数据保存 GridFS 清单文件 ID、摘要、格式和统计信息。
- GridFS 和元数据均保存成功后必须删除本地快照目录；后续训练从 GridFS 读取并逐分片校验，不依赖节点本地路径。
- 历史本地快照继续兼容读取；首次成功复用后必须自动迁移到 GridFS 并删除原文件，迁移失败时保留原文件且不得阻断本次训练。
- 应用启动时必须清理遗留 `BUILDING` 快照对应的本地目录和 GridFS 半成品，并补清理已经持久化成功但上次未删除的本地副本。
- 模型名称、股票范围、历史天数、特征版本、输入维度和序列长度共同确定快照兼容性。任一项变化都必须重新构建快照。

## 13. 全市场预测与实际结果评估

### 13.1 业务目的

- 将已激活模型对全市场股票的一次预测固化为可审计批次，避免预测结果只在调用当时短暂存在。
- 在目标交易日行情到达后回填实际结果，形成“预测值—实际值—误差—方向命中”的闭环。
- 通过连续多个交易日积累样本，判断模型是否具备稳定的方向判断、收益排序和风险识别能力。
- 为模型继续使用、观察或重新训练提供量化依据，但不替代策略回测、交易成本和风险评估。

### 13.2 预测批次规则

- 一次全市场预测使用发起时的已激活模型，并记录模型版本；执行期间模型发生切换时，本批次仍归属于开始时绑定的版本。
- 基准交易日取参与预测股票中可用的最新共同业务日期，目标交易日取其后的下一市场交易日。
- 每只股票记录基准收盘价、预测收盘价、预测收益率、上涨概率和下行风险。
- 数据不足、模型输出异常或股票基础信息缺失时允许单股失败，但批次必须记录成功数、失败数和覆盖率。
- 批次全部成功时标记为已完成；存在部分失败时标记为部分完成；模型或批次级故障时标记为失败。

### 13.3 实际结果回填规则

- 目标交易日尚未结束或日线尚未入库时，预测记录保持待评估，不提前使用盘中价格或当前价格替代收盘结果。
- 目标交易日日线存在时，以目标日收盘价相对基准收盘价计算实际收益率，并计算收益误差、绝对误差、平方误差和方向命中结果。
- 股票停牌或目标日行情长期缺失时标记为缺行情，不纳入准确率和误差统计，但计入覆盖率说明。
- 同一批次允许重复刷新评估；已经回填且基础行情未变化的记录保持幂等，不重复增加样本数量。

### 13.4 模型能力指标

| 指标 | 业务作用 |
|---|---|
| 预测覆盖率 | 衡量全市场股票中能够形成有效预测的比例 |
| 评估完成率 | 衡量已产生实际结果的预测占比，防止用少量已回填样本代表整批结果 |
| 方向准确率 | 衡量上涨和下跌方向判断是否命中 |
| 收益率平均绝对误差 | 衡量预测收益与实际收益的平均偏离程度 |
| 收益率均方根误差 | 对较大偏差给予更高惩罚，用于识别不稳定预测 |
| 横截面线性相关性 | 衡量预测收益与实际收益在同一交易日的整体线性关系 |
| 横截面排序相关性 | 衡量模型对股票收益相对顺序的排序能力 |
| 高分股票平均实际收益 | 衡量预测收益最高的一组股票是否产生正向实际表现 |
| 高分股票方向命中率 | 衡量高置信候选股票的上涨命中情况 |
| 高置信度方向准确率 | 衡量明显看涨或明显看跌预测的可靠程度 |
| 下行风险识别率 | 衡量高下行风险股票中实际下跌的比例 |

### 13.5 能力分级与迭代建议

- 已评估样本不足时结论为“样本不足”，只允许继续观察，不给出强弱判断。
- 覆盖率、方向准确率、误差、相关性和高分股票表现均达到基线时，可评为“能力较强”。
- 核心指标达到最低可用门槛但稳定性仍不足时，评为“基本可用”，建议继续积累多个交易日样本。
- 方向准确率不高于随机基线、相关性持续为负、误差明显偏大或高分股票表现较差时，评为“能力较弱”，建议重新检查数据周期、特征、标签和训练参数。
- 迭代建议至少基于多个目标交易日的滚动结果；单个交易日只能用于流程验证和早期风险提示。

### 13.6 页面展示要求

- 页面应提供触发全市场预测、刷新实际结果和刷新列表三个明确操作。
- 页面展示当前能力等级、是否建议迭代、覆盖率、评估完成率、方向准确率、误差、相关性和高分股票表现。
- 预测明细展示股票代码、基准日、目标日、预测收益、实际收益、上涨概率、下行风险、误差、方向命中和评估状态。
- 页面支持按批次和评估状态筛选；没有实际行情时明确展示“待评估”，不能显示为零收益或预测错误。

## 15. 每日预测与自动评估

### 15.1 每日预测

- 系统在工作日开盘前自动检查当前激活模型和最新完整日线，并为当日目标交易日准备全市场预测。
- 周一预测使用上一个有效交易日的日线作为行情基准；周末自然日可以作为信息截止范围的一部分，但不能伪装成日线交易日。
- 同一模型和行情基准日已有已排队、运行中、已完成、部分完成或已评估批次时，自动任务直接复用现有结果。
- 没有激活模型、没有有效日线或已有预测正在运行时，自动任务应明确记录跳过或失败原因，不生成空批次。

### 15.2 自动评估

- 系统在每日收盘行情同步后扫描所有包含待评估记录的预测批次，并按各自目标交易日回填实际结果。
- 行情尚未到达的记录继续保持待评估，后续工作日再次自动检查；已经完成评估的记录保持不变。
- 停牌或目标日无行情的记录只有在系统已确认目标日期行情整体到达后才能标记为缺行情。

### 15.3 时间口径

| 时间 | 业务含义 |
|---|---|
| 行情基准交易日 | 模型输入中最后一条有效日线对应的真实交易日 |
| 信息截止时间 | 本批次允许使用的信息所截止的自然时间，用于说明预测形成时点 |
| 预测生成时间 | 实际完成单股或批次预测计算的时间 |
| 目标交易日 | 需要在收盘后回填实际结果的市场交易日 |

当前模型只使用日线量价和技术指标。信息截止时间晚于行情基准交易日，不代表周末新闻、公告或舆情已经进入本轮模型输入；相关非行情特征需在后续特征版本中单独建设和验证。

## 16. 情感模型制品、部署与评估

### 16.1 业务背景

情感模型需要处理财经新闻、公告和风险事件，其结果会参与候选股票排序，并可能触发强负面风险拦截。此类模型通常包含较大的权重和词表文件，如果随应用包重复分发，会显著增加发布耗时、回滚成本和节点存储压力；如果允许节点临时联网下载，又会造成版本来源不确定、节点之间结果不一致和故障时难以追溯。

系统需要把应用发布与模型制品发布分开管理。每次情感模型更新都应形成不可变版本，能够确认来源、内容、评估结果和当前使用关系，并允许在不覆盖历史版本的前提下回退。

### 16.2 业务目标

- 大体积权重不进入代码仓库、应用安装包或普通业务数据正文，避免发布链路被模型文件拖慢。
- 每个模型版本具备完整的身份、文件清单、内容摘要、标签顺序、输入限制和评估结论，确保部署内容可验证、可复现。
- 生产节点默认只使用运维人员明确部署并激活的本地版本，不依赖启动时访问外部网络。
- 模型不可用、文件损坏、版本不匹配或评估不达标时，不允许作为交易候选的情感依据。
- 页面能够区分“服务在线”“制品已部署”“完整性已验证”“模型已加载”和“评估已通过”，避免仅凭接口可访问判断模型可用。

### 16.3 制品存放规则

| 规则 ID | 业务规则 |
|---|---|
| SENTIMENT-BR-001 | 每个情感模型版本必须独立保存，历史版本不得被新版本覆盖。 |
| SENTIMENT-BR-002 | 模型权重、词表和运行配置作为一个完整制品单元管理，禁止只替换其中一个文件后继续沿用原版本标识。 |
| SENTIMENT-BR-003 | 制品必须记录每个文件的大小和内容摘要，任何文件缺失、超限或摘要不一致时均视为不可用。 |
| SENTIMENT-BR-004 | 代码仓库和应用包只保存制品规范与版本引用，不保存大体积模型正文。 |
| SENTIMENT-BR-005 | 生产节点的模型目录应为只读，运行中的应用不得修改或覆盖已部署版本。 |
| SENTIMENT-BR-006 | 外部下载只能作为受控的制品准备动作，不能作为生产请求或应用启动的隐式步骤。 |

### 16.4 部署与切换规则

- 新版本先进入待验证区域，完成文件完整性、标签顺序、输入契约、加载能力和基准样例检查后，才能成为可选版本。
- 模型版本切换必须明确记录切换前版本、切换后版本、操作时间和验证结果；切换失败时继续使用原版本。
- 应用启动时只读取明确指定的版本。没有指定版本、指定目录不存在或验证失败时，服务保持未就绪状态并展示原因。
- 回滚通过重新指定已验证的历史版本完成，不复制、不改写历史文件。
- 多节点部署时，同一环境的所有节点必须使用相同版本和摘要；节点未收敛前不得宣称发布完成。

### 16.5 评估规则

情感模型评估分为四层，任何单层结果都不能替代其他层：

1. **数据质量**：检查人工复核样本覆盖的来源、时间、股票、事件类型、标签分布和重复情况，训练集与评估集按时间隔离。
2. **分类能力**：至少统计各类别 Precision、Recall、F1、Macro-F1、混淆矩阵和置信度校准；强负面事件优先关注负面召回率和漏报数量。
3. **稳定性与性能**：统计长短文本、不同来源、不同市场阶段的分层表现，以及单条和批量推理耗时、内存占用和异常率。
