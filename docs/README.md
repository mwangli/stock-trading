## 横向能力归属

为了保持四个模块目录，横向能力按最接近的业务控制边界归档。Agent 不再作为独立第 5 个业务模块，而是归入第 3 个智能决策模块：

| 现有代码包 | 目标归属 | 归档理由 | 迁移方式 |
|---|---|---|---|
| 原 `com.stock.systemConfig` | `04-交易执行` 的运行控制能力 | 配置直接控制 Quartz、采集开关、新闻开关和模型训练开关 | 已合并到 `com.stock.tradingExecutor` 的 `domain`、`persistence`、`service` 和 `api` 目录 |
| 原 `com.stock.user` | `04-交易执行` 的访问控制能力 | 登录会话和 `AuthInterceptor` 保护运维、交易和模型操作入口 | 已合并到 `com.stock.tradingExecutor` 的 `api`、`config`、`domain`、`persistence`、`service` 和 `web` 目录，认证接口路径保持不变 |
| 原调度子域 | `04-交易执行` 的调度能力 | 调度生命周期、手动触发、停止和执行记录必须与真实交易门禁统一 | 已提升到 `com.stock.tradingExecutor` 根包，不再保留独立 `job` 子包 |

目标代码结构：

```text
com.stock
├── dataCollector
├── modelService
├── strategyAgent
└── tradingExecutor
    ├── access       # 原 user：登录、会话、权限拦截
    ├── runtime      # 原 systemConfig：运行开关和节点配置
    ├── job          # Quartz、任务定义和执行记录
    ├── execution    # 风控、订单和券商适配
    └── ...
```

Java 包迁移已于 2026-10-13 完成；数据库表名和既有 HTTP 路径保持不变。

## 端到端边界

```text
dataCollector -> modelService -> strategyAgent -> tradingExecutor -> broker
       └────────────── 原始数据和质量结果 ──────────────┘
```

- `dataCollector` 只提供事实数据，不生成交易信号。
- `modelService` 只提供预测和模型运行结果，不直接访问券商。
- `strategyAgent` 负责确定性策略计算、候选和信号生成，并由 Agent 综合证据作出交易计划决策；它不直接调用券商写接口。
- `tradingExecutor` 是唯一允许调用券商写接口的模块，所有自动任务和手工运维入口都必须经过这里的门禁。
- 前端在策略页面提供 Agent 对话入口，只调用 `strategyAgent` 接口，不复制后端交易规则。

## 当前已知缺陷

1. `00-系统架构` 与四个业务目录并列，造成系统架构是否是业务模块的歧义；系统级内容应收敛到本索引和各模块的边界章节。
2. 数据采集文档仍有旧的 `scheduled/`、独立 Maven 子模块和“待实现新闻”描述，与当前单体代码、`support/` 和已实现新闻采集不一致。
3. 模型文档信息量过大，快照、训练、预测评估和制品治理混在一个设计文件中；后续应保持一份主设计，专题报告只保留结论。
4. 智能决策文档仍需持续补充输入契约、信号状态、回测数据隔离和与交易执行的调用边界。
5. 交易执行文档已覆盖 Quartz，但还需要把认证、系统运行开关、真实写入门禁和审计责任写成同一条控制链。
6. Java 顶层业务包已收敛为四个目录；后续新增横向能力必须继续放入四个业务模块的明确子域。

## 可简化项

当前跨模块的删除、合并和暂缓项统一记录在[全模块减法优化清单](减法优化清单.md)，该清单优先于各阶段文档中的旧实现计划。

- 不建设通用任务编排平台：固定任务由代码白名单和 Quartz 管理，页面只提供查询、触发、暂停、恢复和停止。
- 不建设独立用户中心：当前为个人系统，只保留单用户登录、会话和最小权限模型；后续有多用户需求再扩展角色权限。
- 不把运行开关散落在每个业务模块：统一由 `tradingExecutor.service.SystemRuntimeConfigService` 提供门禁服务，业务模块只依赖明确的判断接口。
- 不在模块之间共享 Entity：跨模块只传 DTO、不可变快照或明确的领域结果，减少持久化模型耦合。
- 不把训练、预测、智能决策和交易执行合并成一个服务：`strategyAgent` 可以形成交易计划，但必须由 `tradingExecutor` 重新取数、执行风控和调用券商。
