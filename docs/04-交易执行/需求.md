# 自动真实交易需求

## 交易闭环

1. 收盘后同步真实行情并离线更新 LSTM 模型。
2. 使用当前生效的 LSTM 模型和近期真实新闻情感生成候选。
3. 开盘后按固定时间自动选择未持仓候选。
4. Java 风控校验资金、仓位、可成交性、重复委托和真实写入门禁。
5. 调用真实券商接口提交委托并回查订单状态。
6. 下一交易日按止损、止盈和尾盘退出规则自动卖出。
7. 保存模型决策、风控结果、委托参数、券商回执、成交和异常记录。

## 强制约束

- 不提供人工买入、人工卖出或逐单审批入口。
- 不建立模拟账户、模拟资金或模拟订单。
- 模型不得持有券商凭据或直接调用券商。
- 生产交易期间不得训练、切换或临时替换模型；交易时段外仅允许通过专用门禁触发训练和受控激活。
- 真实写入必须显式开启 `TRADING_REAL_WRITE_ENABLED`。
- 任一关键数据缺失、模型推理失败、券商会话无效或风控不通过时停止交易。
- 同一股票当日已有同方向有效委托或成交时禁止重复下单。
- 自动买入只能消费目标交易日为当天且批次追溯信息完整的候选；旧日期、不同批次混合或版本缺失时必须阻断。
- 自动买入和自动退出分别按交易日形成唯一执行批次；当天同类型任务已启动后，再次触发必须返回明确错误，不能重复进入券商委托流程。

## 固定调度

系统固定维护 11 个必要任务。任务时间和启用状态由代码初始化到 `job_config`，不提供通用任务编排能力和在线 Cron 修改能力。任务运维允许查询固定任务状态、查询执行历史、手动触发已注册固定任务，并停止排队中或执行中的任务。

### 11 个任务及必要性

| 任务 | 主要作用 | 必要性 | 上游/下游 |
|---|---|---|---|
| `stockListSync` | 每周同步证券平台股票代码、名称和基础状态 | 必要。股票范围是行情、模型和选股的共同基础 | 证券平台 -> 股票主数据 -> 行情、训练和预测 |
| `dailyStockDataSync` | 同步当前交易日日线，并递归向前回补最近三年缺口 | 必要。统一承担增量和全量缺口修复，避免重复历史任务 | 交易日历/证券平台 -> 日线 -> 训练、预测评估和策略 |
| `newsDailySync` | 按水位和外部标识增量同步新闻公告 | 必要。为情感推理和候选评分提供最新信息 | 证券平台 -> 新闻公告 -> 情感推理和选股 |
| `tradeCalendarMonthlySync` | 回补交易日历并维持未来滚动窗口 | 必要。预测目标日、同步范围和交易门禁都依赖它 | 交易日历源 -> 交易日历 -> 同步、预测和交易 |
| `lstmOfflineTraining` | 检查共享 LSTM 是否缺失或过期，并提交受控训练 | 必要。训练是模型更新唯一固定入口，但必须服从训练门禁 | 日线/股票主数据 -> 模型版本 -> 预测 |
| `dailyModelPrediction` | 开盘前补齐全市场预测批次，并回填所有满足行情条件的历史评估结果 | 必要。选股不得在运行时临时重复推理，预测与实际收益也必须形成闭环 | 激活模型和最近日线 -> 预测批次/预测评估 -> 选股和模型分析 |
| `stockSelection` | 使用预测、新闻情感和策略配置生成候选排名 | 必要。将模型事实转换为可审计候选 | 预测批次/新闻/策略配置 -> 候选批次 -> 交易执行 |
| `realTradingAutoBuy` | 开盘后读取当日可执行候选并执行买入门禁 | 必要。真实买入入口必须保留，但不能绕过风控和幂等 | 候选批次/账户事实 -> 风控 -> 券商买入 |
| `realTradingT1Exit` | 检查止损、止盈、可卖数量和 T+1 退出 | 必要。负责持仓风险收敛和尾盘退出 | 持仓/行情/交易日历 -> 风控 -> 券商卖出 |
| `broker-current-facts-sync` | 交易时段同步账户、持仓、当日委托和成交事实 | 必要。交易前和交易中必须使用最新券商事实 | 券商只读接口 -> 本地事实 -> 买入、退出和审计 |
| `daily-trade-performance-snapshot` | 收盘后刷新交易收益统计快照 | 必要。为收益展示、复盘和策略分析提供稳定快照 | 委托/成交/持仓 -> 收益快照 -> 查询和复盘 |

以下任务不再登记为固定任务：新闻元数据补全、券商历史回补、策略自动切换、策略评估、情感模型评估、Agent 日报和 Agent 交易计划自动执行。它们属于低频维护、分析或高风险自动化能力；如仍需使用，只能通过明确的人工接口或业务入口触发，不能与生产主链路共享固定调度资源。

### 任务串联要求

固定任务必须按照业务依赖串联，而不是只依赖 Cron 时间差：

1. `tradeCalendarMonthlySync` 和 `stockListSync` 维护基础范围与交易日事实。
2. `dailyStockDataSync` 和 `newsDailySync` 采集行情、新闻和公告。
3. `lstmOfflineTraining` 在收盘维护窗口检查模型版本；训练失败不得影响当前激活模型。
4. `dailyModelPrediction` 读取已激活模型和最近完整日线，先补齐预测批次，再扫描并回填满足行情条件的历史预测结果。
5. `stockSelection` 只消费已完成且日期、模型版本完整的预测批次。
6. `broker-current-facts-sync` 在交易时段持续刷新券商事实；`realTradingAutoBuy` 和 `realTradingT1Exit` 每次执行前再次读取并校验事实。
7. `daily-trade-performance-snapshot` 在收盘后汇总真实执行记录；预测评估由下一次 `dailyModelPrediction` 统一扫描并回填。

任一上游数据未完成、批次不完整或关键事实过期时，下游任务必须跳过并记录原因，不得用空数据、默认值或上一批次结果伪造成功。

任务运维必须具备以下能力：

- 查询任务定义、启用状态、下一次触发时间和当前运行状态。
- 所有已注册且启用的固定任务均可手动触发，但不允许前端传入任意 Bean 名称或方法名。
- 支持按运行 ID 取消排队任务或请求中断执行中任务，并记录停止操作结果。
- 独立保存每次执行记录，支持按任务、状态、触发来源和时间分页查询。
- 手动触发、定时触发和门禁拒绝必须记录触发来源、操作人、运行 ID、开始时间、结束时间、耗时和错误摘要。
- 真实交易任务的手动触发不能绕过交易时间、券商会话、真实写入开关、风控和幂等门禁。

## 模型管理

- LSTM 在收盘后离线训练，全市场共用当前生效基础模型和必要版本元数据。
- 训练样本必须按股票分段构造，禁止把不同股票记录拼接成同一时间窗口。
- 情感模型在生产服务中只做严格推理；模型未加载或推理失败时不得用于真实候选。
- 提供小型模型运维页面，用于版本查看、参数快照、训练运行、候选激活和上一版本回滚。
- 不建设通用训练平台、通用参数优化器、多级审批或复杂生命周期系统。

## 通知

当前不实现业务通知渠道。后端只保留 `TradeNotificationPort`，默认空实现；通知失败或未配置不得影响交易主流程。运行日志页面使用的日志 WebSocket 不属于业务通知系统。

## 访问与运行控制需求

- 认证入口统一由本模块提供，未登录请求不得访问交易、模型运维、任务运维和运行配置写接口。
- 运行配置只允许修改非敏感的节点级开关，修改必须记录操作者、时间、旧值摘要和新值摘要。
- 用户登录、运行开关、真实写入开关和风控状态是四个独立条件，任何一个条件不满足都必须拒绝真实委托。
- 认证和运行配置属于本模块的横向子域，不建立独立的第五模块目录。

## 验收

- 自动任务能生成真实候选并在全部门禁通过后调用真实券商接口。
- 门禁关闭、会话无效、风控失败或重复委托时不会调用券商写接口。
- 自动买入和自动退出均有可追溯记录。
- 页面能够查看候选批次、预测批次、涨跌模型、情感模型、策略版本、基准交易日、目标交易日和信息截止时间。
- 生产接口不存在人工下单、通用任务编排和业务通知端点；固定任务运维端点只能提供查询、历史记录、手动触发、暂停恢复和停止能力，模型运维端点必须通过时间、并发、数据、资源、参数、激活和审计门禁。
