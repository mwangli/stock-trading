# 百度云 OCR 算术验证码验证报告

## 1. 验证结论

2026-10-08 对中信证券登录接口实时获取的 50 张不同算术验证码进行了百度云 OCR 验证。样本图片数、SHA-256 唯一值数和元数据记录数均为 50，不包含重复图片。

本次验证未达到 85% 单张识别准确率目标。当前最佳单路径结果为 `accurate_basic` 原图 26/50，准确率 52%；所有已测模型和预处理路径的候选并集中，也只有 29/50 样本曾被任一路径正确识别，理论覆盖上限为 58%。因此不能通过投票、置信度阈值或增加同模型缩放路径达到 85%。

自动提交已改为默认关闭。只有显式设置 `ZXBROKER_CAPTCHA_AUTO_SUBMIT_ENABLED=true` 才允许执行实验性双路径提交；该开关不代表准确率已通过验收，生产环境不得启用。

### 3.3 当前 Java 双路径规则风险

当前实验实现使用同一个 `accurate_basic` 模型识别原图和六倍放大图，结果完全一致时才提交。离线回放结果如下：

| 指标 | 结果 |
|---|---:|
| 放行样本 | 38/50 |
| 正确放行 | 23/50 |
| 错误放行 | 15/50 |
| 放行后准确率 | 60.5% |

原图和放大图使用同一模型，错误高度相关，因此“两路一致”不是独立交叉验证。该规则不能作为生产安全门槛。

## 4. 根因分析

1. 验证码使用彩色数字、随机倾斜长线、横向遮挡和字符重叠，主要干扰线直接穿过数字关键笔画。
2. 通用文字 OCR 会把长线识别为减号、把相邻字符粘连，或遗漏被遮挡数字。
3. 放大、裁剪和中值滤波只能改变像素尺度，无法恢复已经被遮挡的字符结构。
4. 同一 OCR 模型的多种缩放结果并不独立，投票会重复放大同一类错误。
5. 50 张样本中只有 29 张曾被任一路径正确识别，说明现有候选集本身不足，后处理无法把上限提高到 85%。

## 5. 代码与配置调整

- 新增 `zxbroker.captcha-auto-submit-enabled`，环境变量为 `ZXBROKER_CAPTCHA_AUTO_SUBMIT_ENABLED`，默认值为 `false`。
- `BaiduCaptchaSolver` 在开关关闭时直接拒绝识别，不请求百度接口，也不向券商提交结果。
- 保留请求间隔、超时、AccessToken 缓存和双路径实验实现，供后续受控验证使用。
- Controller 日志明确记录自动提交开关状态。
- 部署设计不再声明 OCR 登录能力已经完成替代。

## 6. 后续方案

要达到 85% 以上准确率，建议采用以下任一方案后重新建立独立测试集：

1. 训练专用验证码模型。至少采集并人工标注数千张样本，按图片哈希去重，训练集与验收集完全隔离；模型输出字符级位置和置信度，并在 Java 侧保留低置信度拒绝策略。
2. 使用人工兜底。后端保存短时有效的验证码图片和 `CheckToken`，由受控管理端录入答案；凭据、Token 和验证码均不得返回普通前端用户。
3. 与券商确认正式 API、设备认证或免验证码授权方式，避免依赖面向人机校验的网页协议。

重新验收时至少使用 50 张全新且哈希不同的图片，统计单张严格表达式准确率；不得使用训练样本、重复图片、错误标注或“多次重试成功率”替代单张识别准确率。

## 7. 验证边界

本报告证明的是 2026-10-08 这批 50 张唯一图片在已测百度 OCR 接口和预处理方案下的静态准确率。它不证明未来验证码分布、百度模型版本或券商接口行为保持不变，也不构成生产登录可用性证明。
