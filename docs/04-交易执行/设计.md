# 真实交易执行设计

## 交易方式

- `LIVE_MANUAL`：仅允许用户在真实交易页面二次确认后提交买入；人工卖出作为止损和紧急退出入口保留。
- `LIVE_AUTO`：仅由统一调度任务或显式检查接口执行，无独立 Agent 服务。

## 三重门禁

真实写入必须同时满足：

1. 券商会话有效。
2. 交易模式与调用方式匹配。
3. `TRADING_REAL_WRITE_ENABLED=true`。

默认值始终为 `false`。只读查询、模型推理和候选展示不需要开启真实写入。

## 买入链路

`StockSelector -> RealTradingService -> RiskController -> TradeExecutor -> ZXBrokerAdapter`

候选来自已训练 LSTM 模型与最近 36 小时真实新闻情感分析。人工买入只允许选择当日候选；自动买入只选择未持仓候选，并受单批候选数量和单股金额限制。

## 卖出链路

卖出数量使用调用方指定数量，且不得超过券商返回的 `availableQuantity`。系统查询券商当日真实成交；目标股票当日存在买入成交时，拒绝卖出以落实 T+1。

无人值守退出只保留三个条件：固定止损、固定止盈、配置的尾盘退出时间。复杂 RSI、布林带和占位策略不进入真实下单链路。

## 可成交性与重复委托

- 买入要求当日 `openBuyStatus=ALLOWED`。
- 卖出要求当日 `openSellStatus=ALLOWED`。
- 可成交性事实缺失或状态未知时停止交易。
- 同一股票当日已有同方向委托或成交时拒绝重复提交。

## 调度

统一调度中心注册两个默认禁用任务：

- `realTradingAutoBuy`：交易日 09:35 检查自动买入。
- `realTradingT1Exit`：交易日 14:50 检查止损、止盈和尾盘退出。

任务即使被启用，仍必须通过 `LIVE_AUTO` 和真实写入总门禁。

## 通知

订单成交、拒绝、撤销和执行异常通过 PC WebSocket 通知。微信小程序订阅消息通道默认关闭，启用前必须配置本人 OpenId、模板 ID、AppId、AppSecret，并在微信侧完成订阅授权。

## 运行验证边界

代码编译和配置展开只能证明静态完整性。真实账户登录、委托、成交、T+1 卖出和微信到达情况必须在提供真实凭据后，以千元级资金逐笔验证。
