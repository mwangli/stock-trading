# 03-智能决策需求

## 模块定位

智能决策模块把模型输出和市场事实转换为可审计的候选、交易信号和交易计划决策。它包含确定性策略分析和 Strategy Agent 两部分：确定性代码负责可重复计算，Agent 负责证据综合、对话和最终是否形成交易计划的业务判断。模块不保存券商凭据，不直接调用券商写接口。

## 输入契约

| 输入 | 来源 | 最低要求 |
|---|---|---|
| 下一交易日预测 | `modelService` | 绑定模型版本、基准交易日和目标交易日 |
| 新闻与公告情感 | `dataCollector`、`modelService` | 标明信息截止时间；缺失时不能伪造中性结果 |
| 日线、分钟线、交易日历 | `dataCollector` | 能判断交易日、停牌和可成交状态 |
| 账户和持仓快照 | `tradingExecutor` | 标明快照时间；过期快照不能用于下单候选 |
| 策略配置与运行模式 | 本模块 | 版本化、可追溯、禁止运行中无审计修改 |

## 输出契约

每个候选必须包含：股票代码、基准交易日、目标交易日、模型版本、预测分数、情感分数、综合分数、排名、建议数量、价格区间、失效原因、生成时间和数据截止时间。输出是候选事实，不是委托指令。

## 业务规则

- T 日收盘后只生成面向下一个有效交易日的候选。
- T+1 开盘后必须重新读取分钟行情、交易日历和账户快照，不能直接使用收盘候选下单。
- 当日买入的持仓不得当日卖出；退出规则由交易执行模块在可卖数量和券商状态基础上再次校验。
- 排名使用确定性排序：综合分数相同必须使用稳定的次级排序键，保证重复运行结果可比较。
- 行情、模型、情感或交易日历关键数据不完整时，候选状态为 `REJECTED` 或 `INCOMPLETE`，不能以 0 分掩盖失败。
- 回测必须使用当时可见数据、下一根可成交价格、费用、滑点、涨跌停和停牌约束，禁止读取未来数据。

## Agent 决策与对话

- Agent 对话入口归入策略页面，用于解释候选、诊断运行状态、比较模型与情感信号、分析策略配置和生成交易计划。
- Agent 可以决定交易方向、候选股票、数量建议、价格约束、有效期和是否放弃计划，但输出必须是结构化 `TradePlan`，不能直接输出券商订单。
- `TradePlan` 生成后由 `tradingExecutor` 重新读取行情、账户、持仓、交易日历、风险状态和运行开关；复核通过后才能调用券商。
- 对话中的实时事实必须来自结构化查询服务，RAG 和 Memory 只能提供背景证据，不能覆盖实时交易事实。

## 非本期范围

- 不在策略模块实现资金冻结、委托提交、订单轮询或券商重试。
- 不建设通用规则编排器、自动超参数优化器和多策略在线市场。
- 不把回测收益直接视为真实交易收益，必须区分回测、候选和成交事实。

## 策略配置页面业务需求

策略配置页面用于集中管理当前生效的选股和交易信号参数，帮助策略人员在不修改代码和不接触部署环境的情况下调整候选生成规则。页面需要让用户明确知道当前使用的策略模式、配置版本、最近更新时间和参数是否已经生效。

页面至少提供以下业务能力：

- 查看当前策略运行状态，包括策略是否启用、当前模式、配置版本、最近一次切换时间和最近选股结果。
- 管理选股参数，包括 LSTM 与情感因子权重、最低综合得分和候选股票数量。
- 管理技术指标参数，包括移动止损、RSI、成交量和布林带指标的启用状态、权重及阈值。
- 管理收益分层和退出信号阈值，并在保存前提示参数的业务含义和取值范围。
- 支持保守、均衡、激进三种预设模式，同时允许在预设基础上进行自定义调整。
- 支持恢复默认配置，保存后形成可追溯的配置版本，不影响历史候选和回测记录。
- 展示最近一次选股排名，帮助用户观察参数调整后候选数量、综合得分和模型/情感分数组成。

## 页面边界与整合原则

- 系统设置页面继续管理主题、语言、通知、采集、训练和 Quartz 调度等平台运行开关。
- 策略配置页面管理影响选股评分和信号生成的业务参数，不与系统设置合并为一个表单。系统设置可提供进入策略配置页面的入口，但不复制策略参数。
- 真实交易写入、券商账号、风控硬门禁和委托参数不允许通过策略配置页面修改。
- 任何配置保存必须有明确成功或失败反馈；无效参数不得写入数据库。

## 运行状态连续性

策略总开关、当前模式、自动切换开关、最近切换时间和禁用指标属于生产运行事实，必须在应用重启后自动恢复。多节点同时运行时，各节点看到的状态必须一致，不能因单个进程内存不同而产生不同候选结果。

状态变化必须记录变化时间、原因、来源和对应策略配置版本。状态不可读取或无法持久化时，系统不得继续生成可执行候选。

## 每日候选批次

每日候选必须来源于已经完成并保存的当日预测批次，不能在候选生成过程中临时重复执行一套无法追溯的预测。每批候选必须绑定候选批次、预测批次、涨跌模型版本、情感模型版本、策略配置版本、基准交易日、目标交易日和信息截止时间。

真实交易只能读取目标交易日为当天、状态可执行且追溯信息完整的同一候选批次。历史候选、旧目标日候选、混合批次或缺少版本信息的候选只能用于查询，不得用于真实委托。

## 多策略评估与切换需求

### 业务背景

保守、均衡、激进三种模式服务于不同市场环境。单一模式长期运行可能在趋势、震荡或高波动阶段表现失配，因此系统需要持续比较策略表现，并在有充分证据时切换运行模式。切换必须可解释、可追溯，不能因为单日偶然收益或单次模型预测就改变生产策略。

### 评估口径

- 每个策略模式必须绑定策略配置版本、模型版本、数据快照版本和评估时间范围。
- 默认评估窗口为最近一年自然日，并按候选批次时间顺序形成评估样本；窗口内不足 20 个候选批次或不足 100 条候选时只能展示“样本不足”，不能形成有效策略结论。
- 评估同时观察净收益率、年化收益、最大回撤、胜率、盈亏比、交易次数和收益稳定性；单日收益只能作为辅助观察指标。
- 回测、模拟候选和真实成交必须分开统计。回测结果不能直接等同于真实交易效果，真实成交结果也不能覆盖历史回测事实。
- 评估必须使用当时可见的数据，按时间先后划分观察区间和验证区间，不能将未来数据带入历史决策。
- 每个候选批次必须能够关联到对应预测批次和实际收益；关联完整率低于 95% 时，评估应明确标记数据不完整。
- 最后 30% 的候选批次作为样本外验证区间，且样本外至少包含 5 个批次；样本外不足时不得以训练区间表现替代。

### 切换方式和优先级

系统支持人工切换和受控策略状态管理，不再配置固定的策略自动切换或定时策略切换任务。策略评估和模式切换属于观察与人工决策流程；风险保护触发时可以暂停候选生成，但不能代替交易执行模块的风控门禁。

历史规则自动切换逻辑不作为生产固定任务运行。若后续重新启用，必须先经过独立验证、明确的人工开关和新的调度评审；市场参考数据缺失、过期、序列不完整或无法计算涨跌幅时必须保持当前模式。

### 自动切换保护

- 自动切换默认关闭，由运维人员显式开启。
- 同一模式不重复生成切换记录。
- 自动切换设置至少 24 小时冷却期，冷却期内不因重复信号反复切换。
- 每次切换记录原模式、目标模式、触发来源、业务原因、操作者、市场数据日期和配置版本。
- 自动切换只改变候选生成所使用的策略配置，不直接激活新模型、不修改历史预测、不提交委托。

### 自动调整边界

自动调整属于第二阶段能力。系统只能在连续多个评估窗口恶化、样本数量充足、数据质量正常且候选配置通过验证时生成调整建议。调整优先级为最低综合得分和候选数量，其次是 LSTM/情感权重的小幅变化；每次变化必须有限制并形成新配置版本。未经人工确认或独立发布门禁，不得直接覆盖生产配置。

### 用户可见信息

用户需要看到当前模式、模式来源、配置版本、自动切换开关、冷却状态、最近一次切换原因、各模式评估摘要和切换历史。对于样本不足、数据过期、回测不可运行和自动调整未通过门禁等情况，页面应显示明确状态，不能显示为 0 分或空白成功。
