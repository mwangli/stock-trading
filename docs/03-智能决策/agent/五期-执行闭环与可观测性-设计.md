# AGENT 五期执行闭环与可观测性设计

## 1. 总体流程

```text
TradePlanDraft
    -> TradePlanStateMachine
    -> DB 条件抢占
    -> 当前事实复核
    -> RiskController / TradeExecutor
    -> 结果映射
    -> AgentTradePlan 终态和审计字段
```

`strategyAgent` 负责草案、证据和解释；`tradingExecutor` 负责实时事实、风险门禁、券商写入和最终状态。Agent Runtime 不直接依赖 `TradeExecutor` 或 `BrokerAdapter`。

## 2. 并发与幂等

交易计划表增加版本号和执行追踪字段。执行前使用：

```sql
UPDATE agent_trade_plan
SET status = 'EXECUTING', version = version + 1, updated_at = ?
WHERE plan_id = ?
  AND status = 'PENDING_REVALIDATION'
  AND expires_at > ?
```

返回行数为 1 才允许继续执行；返回 0 表示计划已被其他执行者处理或已过期。

## 3. 结果和错误映射

- 交易日、行情、账户、持仓、T+1、重复委托和风控失败统一进入 `RISK_REJECTED`；
- 券商连接、下单异常和订单终态失败进入 `FAILED`；
- 订单成功提交且轮询到成交进入 `EXECUTED`；
- 计划超过有效期进入 `EXPIRED`；
- 每次转换保存 `decisionMessage`、`riskCode`、`executionTraceId`、`orderId` 和 `executedAt`。

## 4. Provider 运行时

模型调用使用受控线程池、信号量和超时 Future。单 Provider 失败返回 Provider 级错误码；`auto` 模式记录 fallback 次数，只有全部失败时才返回聚合错误。

Provider 状态查询默认只报告配置和缓存的最近调用结果，不在普通状态请求中泄露密钥，也不把状态检查失败伪装为模型完成。

## 5. Agent 前端

`pages/agent` 成为唯一 Agent 工作台，拆分：

- `ModelStatusPanel`：Provider 状态和错误建议；
- `ConversationPanel`：会话、消息、加载、失败和重试；
- `EvidencePanel`：证据来源、版本、事实时间和状态；
- `TradePlanPanel`：草案字段、状态和风控结果；
- `ExecutionStatusPanel`：执行批次、订单号、失败原因和最终状态。

策略配置页只负责传递候选批次、预测批次、股票代码、策略版本和目标交易日上下文。

## 6. RAG 与 Memory 的后续设计边界

第六阶段再实现：

1. 真实 Embedding Provider 和向量存储版本管理；
2. 文档版本、租户/用户范围、可见性和过期清理；
3. Memory 的用户确认、纠错、遗忘、审计和语义检索；
4. RAG/Memory 结果统一转换为 `EvidenceItem`，接受 `AVAILABLE/UNKNOWN/EXPIRED` 状态校验；
5. 实时交易事实拥有最高优先级，RAG/Memory 只能作为背景证据。

## 7. 安全边界

- 不新增 `@Scheduled`；
- 不允许前端传入的 `userScope` 直接代表授权身份；
- 不记录完整 Prompt、API Key、Token、Cookie 或券商凭据；
- 所有交易写接口继续受 `TRADING_REAL_WRITE_ENABLED` 保护；
- RAG/Memory 不得绕过工具白名单和证据审计。
