# AGENT 三期结构化编排实施计划

## 1. 实施顺序

### 步骤一：文档和契约

- 固化三类结果 DTO、证据项、状态枚举和任务落库字段。
- 明确三期不包含 TradePlan 生成和券商执行。

### 步骤二：结果解析

- 将统一宽 DTO 拆为 Research、Diagnostic、Report 结果对象。
- 按 `outputType` 选择严格解析和校验逻辑。
- 解析失败返回标准错误码，不做隐式修复。

### 步骤三：证据编排

- 增加统一 `EvidenceItem` 和 `EvidenceAssembler`。
- Research、Diagnostic、Report 只从固定工具集合和受限 RAG/Memory 摘要获取证据。
- 将工具异常保留为失败证据，禁止默认值掩盖。

### 步骤四：任务持久化

- 增加 Flyway 迁移扩展 `agent_task`。
- 任务完成时保存结构化结果 JSON、结果类型、不确定性和证据引用。
- 列表摘要继续保留，避免前端依赖自由文本解析。

### 步骤五：静态检查

- 检查 API 返回仍为 `ResponseDTO<T>`。
- 检查工具调用没有任意 SQL、Mongo 查询、URL 或反射入口。
- 检查没有新增 `@Scheduled`、人工审批和券商写调用。
- 检查 UTF-8、控制字符、AI 标记和定向差异。
