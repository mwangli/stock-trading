# 03-智能决策 Agent 需求

## 模块定位

AGENT 是 `strategyAgent` 模块中的智能决策能力，与确定性策略分析共同组成第三层智能决策模块。它把已有的数据采集、模型服务、策略计算和交易执行查询能力封装为受控工具，通过大模型生成可解释、可追溯的分析结果和交易计划决策。

AGENT 不替代 LSTM、情感模型和确定性策略计算，但可以在智能决策层综合这些结果，决定是否生成交易计划。它不直接持有券商凭据，不直接调用券商接口，不直接写入交易执行事实。交易计划必须由 `tradingExecutor` 重新读取当前事实、执行全部门禁、完成风险复核和调用券商。

## 建设目标

- 用自然语言查询真实的预测、情感、策略、任务、交易日历、账户快照和运行状态。
- 生成带数据来源、时间口径、模型版本和不确定性说明的策略解释与每日投研报告。
- 诊断“为什么没有生成候选”“为什么任务失败”“为什么交易被门禁拦截”等运行问题。
- 为后续自动交易计划提供稳定的结构化契约，Agent 计划不能直接变成券商订单，必须经过 Java 二次校验和幂等执行。
- 在个人服务器和单用户场景下保持低内存、低并发、可关闭、可恢复和可审计。
- 建设可控的 Memory 记忆能力，让 Agent 能够复用用户偏好、历史分析、运行诊断和交易复盘信息。

## 分期范围

### 一期：策略辅助 Agent

一期必须实现以下能力：

- 策略解释：解释指定股票或候选批次的模型、情感、技术指标、排名和风险因素。
- 运行诊断：按时间、任务名、批次号或股票代码检查交易日、数据完整性、预测批次、策略任务、风控门禁和错误记录。
- 每日投研报告：按照固定模板生成市场概览、候选、模型信号、情感信号、策略模式、风险提示、数据质量和异常任务摘要。
- 证据引用：回答中的关键结论必须关联业务记录、批次、模型版本、配置版本或任务运行记录。
- 会话查询：支持有限轮次的问答和上下文追问；超过上下文或任务步数上限时必须停止并说明原因。

### 二期：策略决策与自动交易 Agent

二期生成结构化交易计划后，不设置人工审批环节，系统自动进入 Java 二次取数和风险复核。复核通过后由 `TradeExecutor` 自动执行；复核失败、数据过期、计划过期或幂等冲突时自动拒绝并记录原因。二期不改变交易执行模块的权责边界，真实写入默认关闭，开启后仍必须满足全部 Java 门禁。

二期同时建设向量库 RAG 和 Memory。RAG 用于检索文档、新闻、公告、投研报告和历史分析证据；实时行情、账户、持仓、风控和交易日历仍以结构化业务查询为准，不能用向量检索替代。

计划至少包含股票代码、方向、数量建议、价格约束、有效期、理由、证据引用、风险提示、置信度、候选批次和幂等键。计划状态至少包括 `PENDING_REVALIDATION`、`RISK_REJECTED`、`EXECUTING`、`EXECUTED`、`FAILED` 和 `EXPIRED`，不得出现需要人工审批才能继续的中间状态。

## 输入契约

| 输入 | 来源 | 要求 |
|---|---|---|
| 行情、交易日历、新闻和公告 | `dataCollector` | 必须带数据时间、来源和质量状态 |
| 预测批次和模型版本 | `modelService` | 必须绑定批次、模型版本、基准日和目标日 |
| 候选、排名、策略配置和回测 | `strategyAgent` 的确定性策略子域 | 必须带策略版本、候选批次和计算时间 |
| 任务运行、风控结果、账户和持仓快照 | `tradingExecutor` | 只能通过只读查询服务获取，必须带快照时间 |
| 用户问题或报告任务 | AGENT API | 记录用户、会话、请求时间和关联业务标识 |
| RAG 文档、新闻、公告和历史报告 | `agent.rag` | 必须保存来源、版本、时间、权限范围和内容哈希 |
| Memory 记忆 | `agent.memory` | 必须区分会话记忆、用户偏好、历史事件和交易复盘，并记录有效期 |

过期、缺失、批次混用或质量状态不通过的数据不得被模型当作当前事实。工具返回“不确定”或“不可用”时，Agent 必须保留该状态，不能用猜测、零值或“正常”替代。

## 工具要求

一期只注册只读工具，工具必须有明确的名称、参数 Schema、返回 Schema、权限、超时、最大返回量、版本和审计信息。建议工具包括：

- `queryPredictionBatch`
- `queryPredictionDetail`
- `queryStrategyRanking`
- `queryStrategyEvaluation`
- `queryNewsSentiment`
- `queryJobExecution`
- `queryRiskDecision`
- `queryTradingCalendar`
- `queryBrokerSnapshot`
- `queryBacktestResult`

Agent 只能调用工具网关，禁止直接连接 MySQL、MongoDB、Redis、券商接口或任意 Shell。工具必须执行数据范围、参数范围、单次返回量和敏感字段脱敏。

## 业务规则

- Agent 输出是分析结果或计划，不是事实源；模型输出不能覆盖数据库事实。
- 所有事实结论必须能追溯到工具返回的记录、批次、版本或时间窗口。
- 不允许把预测分数、情感分数或 Agent 置信度表述为收益保证。
- 交易日判断统一使用 `TradingCalendarService`，不得自行按周一至周五推算。
- 真实交易时，必须由 Java 重新读取当前行情、账户、持仓、交易日历和风险状态；不能复用 Agent 生成时的快照直接委托。
- 工具超时、模型超时、结构化输出校验失败或证据不足时，任务进入明确失败状态，不等待人工审批继续执行。
- 自动交易计划必须经过有效期、候选批次、交易日、价格、数量、资金、持仓、T+1、交易时间、风险限额、重复委托和 TRADING_REAL_WRITE_ENABLED 全部校验。
- RAG 只能提供背景证据和历史上下文，不能覆盖实时结构化事实；检索不到可靠来源时必须降低结论确定性或拒绝生成交易计划。
- Memory 写入必须经过类型、敏感字段、长度、来源和有效期校验；模型不能自行把任意回答写成长期记忆。
- 默认单用户、低并发、有限步骤；同一会话和同一业务任务不得无限循环或重复执行。
- Prompt、工具 Schema、模型名称、模型版本、请求摘要和响应摘要必须留存审计记录，但不得保存密码、Token、券商会话或完整敏感响应。

## 访问与安全需求

- AGENT 查询接口必须经过现有认证入口。
- 一期只允许读取用户可见的个人账户和系统数据。
- 文件、网络、Shell、写数据库、发消息、修改配置、训练模型、激活模型、提交委托均不属于一期工具权限；二期 Agent 可以生成交易计划，但提交委托只能由 `tradingExecutor` 内部服务执行。
- Prompt Injection、工具参数污染、越权访问、敏感信息泄露、无限循环和成本失控必须有拦截或降级策略。
- `TRADING_REAL_WRITE_ENABLED=false` 时，任何 Agent 相关流程都不得改变该开关或调用券商写接口。

## 资源与部署需求

- 一期 2C4G 服务器必须能够只运行 Java Agent Gateway 和现有 MySQL、MongoDB；不以 Redis、独立 Harness 容器或额外向量数据库作为一期必选依赖。
- 二期正式增加向量库，继续使用现有 MongoDB 单节点，并在其上建立向量检索索引；MongoDB 中只保存 Chunk、Embedding、payload 和向量索引所需字段，不复制完整交易事实。
- 会话、任务状态和审计优先使用 MySQL；新闻正文、行情和模型相关事实继续使用 MongoDB。
- Redis 只作为后续可选优化，用于短期缓存、限流或多实例协调，不能成为一期业务正确性的唯一依赖。
- 向量数据库和本地大模型不是一期前置条件；二期 RAG 继续使用现有 MongoDB，上线前必须完成文档切分、Embedding 版本、权限过滤、向量索引重建和删除策略。
- 外部模型调用必须支持超时、重试上限、响应大小上限、脱敏和关闭开关。

## 非本期范围

- 一期不实现自动下单、自动改策略、自动激活模型、自动训练和自动修改生产配置；二期自动交易只允许使用固定的交易计划和既有 Java 执行链路。
- 不引入微服务拆分、独立用户中心、复杂多租户、子 Agent 集群或通用工作流平台。
- 不把 DeepSeek Harness 作为生产核心依赖；一期先抽象 Agent Runtime 和 Tool Gateway，未来可接 DeepSeek API、Ollama、Harness 或其他兼容 Provider。
- 不在一期建设向量知识库；二期建设受权限和版本约束的 RAG，不把所有结构化交易数据复制到 Embedding 存储。
