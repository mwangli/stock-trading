# AGENT 三期结构化编排设计

## 1. 总体链路

```text
AgentController
  -> AgentApplicationService
  -> EvidenceAssembler
       -> 固定只读工具集合
       -> RAG 摘要
       -> Memory 摘要
  -> AgentRuntimeService
       -> LangChain4j ChatModel
       -> 严格结构化解析
  -> TypedResultValidator
  -> AgentTask 持久化
```

模型只接收已经脱敏和截断的证据文本，以及当前任务的输出 Schema。模型不得改变证据的来源、时间、状态和用户范围。

## 2. 结构化结果

### 2.1 ResearchResult

字段：`summary`、`status`、`keyFindings`、`evidenceRefs`、`uncertainty`、`nextActions`。

`status` 只能是 `PASS`、`WARN` 或 `UNKNOWN`。Research 不输出收益保证和直接下单字段。

### 2.2 DiagnosticResult

字段：`summary`、`status`、`checks`、`blockedReasons`、`evidenceRefs`、`uncertainty`。

每个 `check` 包含 `name`、`status`、`detail` 和 `evidenceRefs`。`status` 只能是 `PASS`、`WARN`、`BLOCKED` 或 `UNKNOWN`。

### 2.3 ReportResult

字段：`reportDate`、`summary`、`status`、`sections`、`dataQuality`、`evidenceRefs`、`uncertainty`。

`sections` 使用固定章节键，不允许模型任意新增影响审计和前端展示的业务字段。缺少必要章节时任务失败。

## 3. 证据集合

```text
EvidenceItem
  evidenceId
  sourceType: TOOL | RAG | MEMORY
  sourceId
  status: AVAILABLE | UNKNOWN | FAILED | EXPIRED
  asOf
  summary
  errorCode
```

`EvidenceAssembler` 负责：

1. 按任务类型选择固定工具集合。
2. 限制每个工具的输入和返回量。
3. 将工具、RAG、Memory 结果统一编号。
4. 在传给模型前执行脱敏、截断和来源标注。
5. 工具失败时保留失败证据，不用空字符串或零值覆盖。

## 4. Runtime 约束

- `AgentRuntimeRequest.outputType` 只能取 `RESEARCH`、`DIAGNOSTIC`、`REPORT`。
- Runtime 根据 `outputType` 选择对应解析器和校验器。
- 解析器只接受一个 JSON 对象，不做 Markdown 包裹、半截 JSON 或旧字段兼容修复。
- 解析成功后先做字段、枚举和数量校验，再交给应用服务持久化。
- `DEGRADED` 不强行解析模型输出；只保存结构化事实摘要和降级原因。

## 5. 工具注册

工具注册表是代码中的唯一权威入口，当前阶段至少保留：

- `queryJobExecution`：查询固定任务运行摘要。
- `queryTradingCalendar`：查询指定日期的交易日状态。
- `queryPredictionCandidate`：查询候选批次的脱敏摘要。
- `queryStrategyState`：查询当前策略状态和最新评估摘要。

工具实现只能依赖 Query Port 或现有查询服务，不能让模型直接访问 Repository、MongoTemplate、JDBC 或 HTTP Client。

## 6. 任务持久化

`AgentTaskEntity` 增加以下字段：

- `resultType`：RESEARCH、DIAGNOSTIC、REPORT。
- `structuredResult`：脱敏后的结构化 JSON。
- `uncertainty`：不确定性摘要。
- `evidenceRefs`：证据编号列表。

原有 `resultSummary` 和 `evidenceSummary` 保留作为列表页摘要，不作为唯一业务结果来源。

## 7. 明确不做

- 不在本阶段生成 `TradePlanDraft`。
- 不执行 `TradePlanExecutionService`，不调用 `ZXBrokerAdapter`。
- 不新增人工审批或人工确认状态。
- 不实现自动工具循环和模型自主选择任意 Spring Bean。
