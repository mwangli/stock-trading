# Docker 启动阻断分析与优化

## 结论

阻止 Docker Desktop 启动的程序是 **Cobra DocGuard Client**。其内核驱动
`ProcessCtrl64.sys`（服务名 `ProcessCtrl`）拦截了 Docker 后台进程
`com.docker.backend.exe` 加载 Windows 系统库 `secur32.dll`，导致后台进程直接退出，
Docker Linux Engine 因此无法创建。

`CommonService.exe` 是 Cobra DocGuard 的用户态服务；`EstVpn.exe`、`watchctrl.exe`、
`CdgTwin32.exe` 和 `CdgTwin64.exe` 是同一客户端的常驻组件。深信服 EasyConnect/aTrust
同时存在，但当前错误栈和复现结果直接指向 Cobra DocGuard 的 `ProcessCtrl` 驱动。

## 证据

- Docker 后台稳定复现：`Failed to load secur32.dll: Access is denied`。
- `secur32.dll` 和 Docker 后台程序的数字签名、ACL 均正常。
- 普通程序可以加载 `secur32.dll`，只有 Docker 后台被拒绝。
- `ProcessCtrl` 当前启动类型虽然已禁用，但驱动仍在运行且不接受动态停止。
- 2026-10-08 检查时，Windows 最后启动时间仍是 2026-09-30 18:18:16，说明驱动尚未通过完整重启卸载。

## 优化方案

1. 首选让终端安全管理员把以下 Docker 程序加入白名单，而不是长期关闭全部安全能力：
   - `Docker Desktop.exe`
   - `com.docker.backend.exe`
   - `dockerd.exe`
   - `docker.exe`
2. 当前电脑已将 `CommonService` 和 `ProcessCtrl` 的启动类型设为禁用。
3. 执行 Windows **重新启动**，不要使用休眠、睡眠或快速关机恢复；重启后确认 `ProcessCtrl` 为 `STOPPED`。
4. Docker 就绪后，仅启动项目依赖：`stock-mysql`、`stock-redis`、`stock-mongo`。
5. 数据继续挂载到 `D:/docker-data/stock-trading4/`，本机查询端口分别为 MySQL `6033`、Redis `6379`、MongoDB `27017`。

## 验证标准

- Docker Engine 可以返回服务端版本。
- 三个容器状态均为 `healthy`。
- `127.0.0.1:6033`、`127.0.0.1:6379`、`127.0.0.1:27017` 均可连接。
- 容器挂载源路径均位于 D 盘项目数据目录。
