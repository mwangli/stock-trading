# Docker 部署与备份恢复手册

> 日期：2026-09-25

## 服务

- `stock-web`：React 静态页面和 Nginx。
- `stock-backend`：Java 单体后端，包含采集、模型、策略、调度和真实交易。
- `stock-mysql`：结构化业务数据。
- `stock-mongo`：行情、新闻和模型参数。
- 券商 Token 保存在单实例 Backend 进程内，Backend 重启后通过验证码重新登录。

项目不维护预发布环境。

## 配置文件

- `docker-compose.yml`：唯一的服务定义，本地和服务器共同使用。
- `.env`：镜像、端口、数据目录、密码和环境差异，不提交仓库。
- `.env.example`：不含真实凭据的配置模板。

## 安全默认值

```text
TRADING_REAL_WRITE_ENABLED=false
ZXBROKER_ENABLED=false
```

首次部署只允许读取数据。确认中信账户、持仓、委托和成交均可正确读取后，再单独评估是否开启真实写入。

## 启动方式

本地和服务器使用同一条命令，仅 `.env` 中的镜像、绑定地址和数据目录不同：

```bash
docker compose --env-file .env up -d
```

只启动数据库：

```bash
docker compose --env-file .env up -d stock-mysql stock-mongo
```

## 必须持久化的数据

- MySQL 数据目录。
- MongoDB 数据目录。
- 本地模型目录（使用本地模型存储时）。
- 应用日志目录。

## 备份

1. 关闭真实写门禁。
2. 确认没有正在执行的委托任务。
3. 备份 MySQL。
4. 备份 MongoDB。
5. 备份模型目录和当前 `.env` 的安全副本。
6. 记录应用镜像版本。

## 恢复

1. 恢复 MySQL 与 MongoDB。
2. 恢复模型文件和配置。
3. 以 `TRADING_REAL_WRITE_ENABLED=false` 启动。
4. 验证账户、持仓、委托、成交和模型加载。
5. 人工核对通过后再恢复交易。

## 验收

```bash
docker compose --env-file .env config --quiet
```

静态展开成功不代表数据库、模型、中信登录或真实交易已运行通过。
