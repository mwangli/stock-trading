# 全模块减法优化清单

> 评估日期：2026-10-18
> 评估方式：源码、调用方、路由、迁移脚本和现有设计文档静态核对。
> 证据边界：本清单不等同于编译、测试、数据库、浏览器或线上验证结果。

## 1. 总体结论

当前系统已经形成四个业务模块：数据采集、模型服务、智能决策、交易执行。`strategyAgent` 属于智能决策模块，不再单独扩展为第五个业务模块。

本轮确认的第一优先级减法只有两项：

1. Agent 对话只保留一套策略页内嵌实现；独立 `/agent` 页面保留为直接访问入口，不再在两个页面复制会话状态。
2. RAG 检索只接受 `embeddingStatus=READY` 的向量，禁止 Hash fallback 进入正式语义检索结果。

其余模块暂不直接删除业务类，原因是当前仍能找到调用方、任务配置依赖、持久化历史数据或生产安全边界。对这些部分先保留调用链证据，再分批删除，避免用“看起来重复”替代真实无调用证明。

## 2. 减法决策规则

| 状态 | 含义 | 处理方式 |
|---|---|---|
| 可直接删除 | 已确认没有调用方、路由、迁移或运行时依赖 | 当前阶段可以删除，并做全局符号复查 |
| 需调用链确认 | 代码形态像转发或兼容层，但仍可能被任务、历史数据或外部入口使用 | 先列出调用方和数据证据，再单独实施 |
| 暂不删除 | 负责事实、风控、幂等、权限、审计或故障恢复 | 保留唯一权威入口，禁止复制实现 |
| 合并而非删除 | 多个类表达同一业务职责，但拆分有助于持久化、调度或隔离 | 先固化契约，再做小步合并 |

## 3. 数据采集模块

### 保留

- `StockDataService` 的历史行情、每日增量和回补入口仍由 `DataSyncScheduler` 调用。
- `MarketDataFoundationService` 的模型专用日线、基准日线、交易日历、复权因子、分钟线和可交易事实仍属于不同输入事实，不能仅因都读取行情就删除。
- `TradingCalendarService` 必须作为交易日判断唯一入口，不能由各业务类自行按周一至周五推算。

### 减法候选

- 逐方法检查旧的导入入口、重复日期校验和未使用的单股票查询方法；确认无调用方后删除。
- 将“业务行情主库”和“模型训练输入”在文档中明确分层，不再为两者各自增加同名同步流程。
- 采集任务只保留统一调度入口；业务服务不得重新增加 `@Scheduled`。

### 当前不删除原因

两个数据服务的输出对象、调用方和事实用途尚未完全相同。直接合并会把模型输入质量门禁和账户/交易事实混在一起，扩大故障影响面。

## 4. 模型服务模块

### 保留

- 训练、预测、批次、评估和模型制品的事实记录。
- `ModelPredictionAnalysisService` 的手动预测、定时预测、中断恢复和评估能力，直到调用链和任务终态证据证明某入口已被替代。
- 训练快照 manifest、分片文件和模型版本之间的校验，避免删除后无法恢复历史训练结果。

### 减法候选

- 将预测执行、能力评估、旧索引治理从大服务中拆成边界清晰的服务；这是结构减法，不是删除功能。
- 删除明确无调用方的 legacy 状态分支和兼容入口，但必须先检查数据库记录、制品目录和前端状态映射。
- 训练只保留 `JobConfig + JobSchedulerService` 编排，不再增加新的独立启动入口、Python 服务或 ONNX 旁路。

### 当前不删除原因

训练快照和制品兼容逻辑涉及历史数据可读性；在没有制品目录和数据库证据前，不能仅按 `@Deprecated` 或注释判断为死代码。

## 5. 智能决策与 Agent 模块

### 已实施减法

- 删除策略页重复的模型 Provider 状态卡和冗余跳转按钮。
- 策略页保留一套内嵌 Agent 对话，直接使用候选批次和策略版本上下文。
- `/agent` 页面保留完整工作台能力；两处不得再各自复制第三套会话协议或状态模型。
- RAG 搜索增加 `embeddingStatus=READY` 条件，Hash fallback 不再进入正式检索结果。

### 必须保留

- `EvidenceItem` / `EvidenceBundle` 作为工具事实、RAG 和 Memory 结果的统一证据边界。
- `TradePlan` 状态机、证据不足阻断和 Agent 不直接调用券商写接口的约束。
- 会话短期上下文与长期 Memory 的生命周期区分。

### 后续减法

- Agent 前端继续拆成状态、会话、证据、交易计划四类视图时，优先复用页面内数据契约，不新增平行 API。
- RAG 和 Memory 只作为背景证据；实时行情、账户、持仓、交易日、风控和订单事实继续由结构化工具提供。
- 仅保留一个 Runtime 入口和一个 Research/Diagnostic/Report 编排入口，删除旧的自由文本直连路径时必须先做全局引用检查。

## 6. 交易执行模块

### 必须保留

- `tradingExecutor` 是唯一券商写入口。
- 交易日、行情、账户、持仓、T+1、风控、幂等和真实写入门禁不能被 Agent 或前端替代。
- 过期交易计划必须能进入 `EXPIRED`，不能因为真实写入开关关闭而跳过清理。

### 减法候选

- `TradePlan` 执行前的事实复核、风控和券商调用只能保留一条权威链路，删除重复的前端校验和服务内二次拼装。
- 交易候选展示与可执行候选保持两个明确状态，不再复制一套“展示排序”和“执行筛选”逻辑。
- 通知仅保留扩展接口和空实现；当前不建设通知投递箱、事件中心或多渠道编排。

## 7. 任务编排

### 保留

- `JobSchedulerService` 作为唯一调度入口。
- Quartz Job 适配类在当前阶段保留，因为持久化任务类型和迁移记录可能依赖类名。

### 减法候选

- `JobConfig.beanName`、`methodName` 当前主要用于展示元数据，后续应从运行时选择逻辑中移除，避免与 `jobName -> JOB_CLASSES` 白名单产生双重权威。
- 只做一层转发的业务 Job 类可在确认管理页、运行记录、反射入口和迁移脚本无依赖后合并。
- `V34__register_agent_trade_plan_execution.sql` 与固定 Job 映射的重复描述应统一为一个权威配置来源。

## 8. 前端与页面结构

### 当前页面边界

- 策略页负责策略配置、排名、候选批次、执行状态、评估和当前策略对话。
- `/agent` 负责完整 Agent 工作台、证据和 TradePlan 展示；两者共享后端 Agent 契约，不复制交易规则。

### 后续减法

- 页面专属类型、请求和 Mock 只在确有独立职责时拆分；不为单次使用创建通用组件。
- 真实接口失败时保留明确错误/空状态；Mock 只作为展示兜底，不伪装成真实交易或模型结果。
- 表格分页、状态 Tag、响应封装和 API 错误解析继续复用现有公共入口。

## 9. 需求与设计文档

### 当前问题

- Agent 二期、三期、四期、五期文档存在阶段边界重复；RAG/Memory 在早期文档已定义基础设施，五期又重复描述为后续能力。
- `docs/README.md` 仍保留数据采集旧目录、独立 Maven 子模块和新闻未实现等过时描述。
- 总体架构文档、改造计划和专项设计对同一条交易执行边界存在重复叙述。

### 减法方案

1. `docs/README.md` 作为当前状态索引，只保留模块边界、唯一入口和当前未决项。
2. 阶段文档保留历史记录，但在标题或开头标注“历史阶段”，不得继续作为当前实现规范。
3. 当前实现规范只保留一份模块设计、一份统一任务编排设计和一份 Agent 当前边界说明。
4. 评估报告只保留结论、证据和未验证项，不重复复制完整设计。

## 10. 第六阶段实施边界

第六阶段只实现知识检索和记忆增强的安全基础，不扩大交易能力：

- 统一 `EvidenceItem` 的 `AVAILABLE`、`UNKNOWN`、`EXPIRED`、`FAILED` 语义。
- RAG/Memory 检索必须校验用户范围、可见性、版本、Embedding Provider、模型版本、维度和状态。
- 记忆删除、纠错、过期必须同步禁用或重建语义索引。
- 实时结构化事实拥有最高优先级；RAG/Memory 不能覆盖事实，也不能单独生成可执行交易计划。
- 未配置正式 Embedding 时安全降级为无检索，不把 Hash fallback 当成正式生产检索能力。
